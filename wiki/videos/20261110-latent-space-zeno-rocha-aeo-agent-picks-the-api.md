## 五、⚠️ 一条架构断言：框架的默认值正好拿掉了 agent 需要的那个面

（[00:43:35]–[00:45:35]）⚠️⚠️ **这一段的主张来自主持，而嘉宾用自己踩过的坑确认了它，本页因此分开记。**

- ⚠️⚠️ **主持的断言**：**Next.js 的 server components 与那套路由 API"让你很容易把数据直接绑到页面上"** → **"所以你永远不会暴露一个公开 API。"** → ⚠️ **"所以按默认、按它们鼓励你走的那条性能最好的路，你就不会有 API。"**
- ✅ **他给的处方很直接**：**"其实你应该永远有一个完全 headless 的后端，然后你的前端只不过是连到那个后端的许多客户端之一。"**
- ⚠️ **而嘉宾确认的是实际代价**：**"我们的 API 一开始就在 Next 上。首先账单高到我们觉得根本付不起，所以我们搬到了一台传统的 node 服务器。而我们的 dashboard 一直是一个私有 API 在消费同样的东西，于是我们不得不重复很多代码。那是一团乱。"** ⚠️ **他说现在在 monorepo 里好多了，✅ 但结论是"我们得在那之外另建一个公开 API，而两边都要维护，这很难受"。**

✅ **本页判这条值得单独记，因为它把一个框架选择变成了一个 agent 可达性的问题**：⚠️⚠️ **如果"被 agent 使用"要求一个公开、完整、与界面解耦的 API，那么过去几年被广泛推荐的那套"数据直接绑到页面"的默认值，恰好是在削减这个面。** ⚠️ **本页标注这是两位技术人的判断、不是测量，而 Next.js 一侧在期内没有被给任何反驳机会。**

## 六、⚠️ 一组为 agent 做的产品决定，以及一处被明确悬置的张力

### ⚠️⚠️ 被悬置的那一处：agent 自助注册 vs 滥用

（[01:08:57]）⚠️ **主持引的是 WorkOS 的 Michael Grinich 在推的 auth.md**——**"你不需要账号就能做基本动作"，也就是未认证使用**，⚠️ **主持自己同时指出"这显然很危险，因为它容易被滥用"。**

## 七、⚠️ AI 怎么同时弄坏与修好这个行业的两件事

### ⚠️⚠️ 弄坏的：打开率

（[00:13:06]–[00:14:07]）⚠️ **机制他说得很完整**：**打开跟踪的做法是在邮件里嵌一张 1×1 的透明 GIF，图片被加载就算一次打开。**

- ⚠️⚠️ **而坏掉的理由里有一条是 AI 自己**：**"Apple 最近在透明度和数据隐私上做的那些改动……如果他们在做摘要和那类事情，他们会在邮件落地之前先读它。"** → **"所以打开率作为一个指标整体上已经不像以前那么可靠了，因为这些过滤器在那之前就把它看过了。"**
- ⚠️ **而退路（点击跟踪）带着另一个风险**：**链接与图片的 URL 都应当与发信域一致**，⚠️ **因为把链接改写到自己的域名会造成"吵闹的邻居"问题——"如果用那个点击跟踪的客户里有一个是滥用者、发了一堆钓鱼，那个域名可能会被拉进黑名单，而从黑名单出来可能要几天或者几周"**，✅ **他的定性是"那你这生意就完了"**。⚠️ **他明确说自己早期也做过链接改写（"我们起初也这么干"）。**

### ✅ 修好的：DNS，而两头都是同一波 AI

（[00:19:15]–[00:20:18]）⚠️⚠️ **本页判这组对照是本期一个很干净的现象，而它是两位各说一半拼出来的。**

- ⚠️ **嘉宾那一半是用户侧的退化**：**"我们在服务一个新的人群，一个甚至不知道怎么排查问题的人群。我记得去年 Lovable、Bolt、v0 来的时候，我能看出这些是不同的用户——他们遇到问题的时候不知道自己遇到了问题，他们就卡住了。"** ⚠️ **而症结是 DNS**：**"今天我们收到的大多数问题就是人们配不好"**——**"他们就是不知道什么是 CNAME、什么是 A 记录、TXT 放在哪儿。"**
- ✅ **主持那一半是工具侧的解决**：**"顺便说，我现在用 Claude Code 或者 Codex 的 computer use，它完全替我管我的 DNS 记录。它会去调试、会 dig、会试那些 DNS 的东西。我根本不用操心。"**
- ✅ **本页标注这组对照**：⚠️⚠️ **同一波产品既造出了那批不会配 DNS 的用户，也造出了替他们配 DNS 的工具，而两者目前显然没有接上——嘉宾的工单量说明不会的人并没有都拿到那个工具。**

## 八、其余值得登记的几处

### ⚠️ 一条可直接搬用的支持制度

（[00:17:13]–[00:19:15]）⚠️ **他对支持的定性是"如果支持是个软件，我们大概在大版本四"**，✅ **而第 2 版上定的那条政策本页认为是本期最可照搬的运营细节**：

> ⚠️⚠️ **"你只能用一个链接来回一个工单。所以你不能直接把答案给出去。"** → **"你得先写一篇知识库文章、写文档，所以回一个工单可能要花一个半小时。但你猜怎么样？现在你把那个链接一遍一遍地发出去。"**

- ⚠️ **而规模约束他给了一个可核对的口径**：**"我们去年十二月有 100 万用户，现在有 400 万。我可以往这个问题上堆人，但那就是解决不了。"** ⚠️⚠️ **本页标注这组用户数与页首那个"今天早上 430 万"口径一致，但全部自述。**
- ✅ **他对免费额度的坚持给了一条非商业理由**：**"我当年能成为工程师，就是因为我能用那些免费产品……要不是 Heroku 的免费额度和那些别的产品，我们都不会在这儿。"**

### ⚠️ 信任模型："生而自由"，以及"误用不是滥用"

（[00:15:10]–[00:16:12]）⚠️ **他把行业惯例（先填表、人工审核、两天后通过或拒绝，"大多数时候会拒绝你"）类比成"生在一个你得先在监狱里待 18 年、证明自己是好公民才能出来做事的社会"**，✅ **而他的选择是"默认信任你"，代价自己扛（"摩擦会在我们这边"）。**

- ⚠️⚠️ **而对称的另一半是反应速度**：**"我们和别人不同的地方是，一旦我们注意到有什么不对——看退信率、投诉率、邮箱提供商给我们的所有反馈——我们会非常快地把你封掉，然后再跟你聊、试着理解。"**
- ✅ **本页判他给的那条区分值得单记**：**"而大多数时候那只是误用，不是滥用。所以我们学到我们需要把这两者分开。"**
- ⚠️ **他对这条路线的成本有一个外部警告**：**Mailgun 创始人当面告诉他"我们 90% 的 R&D 就是在打滥用者。那是个糟糕的生意，你不该进去"**（[00:27:20]），⚠️ **而他的结论是"我们必须把这件事自动化"**。

### ⚠️ 价值捕获侧的两条

- ⚠️⚠️ **按联系人计费被 AI 原生客户打破**（[01:15:00]）：**"这个行业有一个按联系人收费的模式……他们是围绕每个联系人创造的价值来定价的。但现在很疯狂，我们服务的那些 AI 公司增长太快了"**——⚠️ **他点名 Mistral 是客户，"他们加用户的量就是离谱"** → ✅ **"所以按联系人定价的商业模式有点坏掉了，我们正意识到这一点、也在试着修。"** 🔗 ✅ **本页标注这是本库"席位制/按量计费之争"那条线上一个此前没有的方向：不是买方嫌贵，而是计价单位本身的增速超出了它被设计的范围。**
- ⚠️ **发送速率成为分级依据**（[01:16:02]）：**"按域名是有最高速率的"**，⚠️ **而给 430 万用户发一次"要花一天多"**，✅ **于是主持直接问"那我多付钱进一个不同的队列？"——答"是"**。⚠️ **主持的类比是"这就像 token 的速率限制"。**
- ⚠️ **企业动作刚开始**（[01:12:59]–[01:14:00]）：**"我们只有一个 AE"**，⚠️ **而他给的理由是文化保护（全远程、"别一下子把文化搞坏"）**；✅ **而他对企业版的判断本页认为值得记**：**"对企业来说它其实是一个不同的产品……如果我只是加上 WorkOS、SSO、SCIM 和审计日志，那不会够。所以这不只是在定价页上加几项。"**

### ⚠️ 自建 SDK 与"没人打开 dashboard"

- ⚠️ **他们评估过 SDK 生成工具（Stainless、Fern 等）**，⚠️ **"我们不喜欢生成出来的东西。所以那些 SDK 每一个都是人写的——Java 的、Rust 的，全都是"**（[00:48:38]–[00:49:39]）。✅ **他的理由是分布的尾部**：**"400 万里只有 500 个人用那个？我在乎那 400 个人。"** ⚠️ **主持的反问很直接："为什么不（这么做）是因为你有 400 万用户。"**
- ⚠️⚠️ **而本页认为本期最值得与另一期并读的一处在这里**（[00:36:26]）：**"好笑的是，现在我聊到的每个客户都说：噢我从来不打开那个 dashboard……我花了那么多时间想把 dashboard 做漂亮，而现在人们不去那儿了。有点挫败，但我理解。"** 🔗 ✅ **本页标注这正好是 [同一天发布的 Dharmesh Shah 那期](20261110-a16z-dharmesh-shah-incentive-constraint-replay-the-codebase.md)"别把界面想得太重、真正有价值的是正在发生的那份工作"的一条独立佐证——而它来自一个把界面做到极致的人。**

### ⚠️ 品类创造 vs 品类主导，而主持举的例子正是同一天的另一位嘉宾

（[01:23:07]–[01:25:11]）⚠️ **主持的判断是一次直接的否定**：**"这还不是品类创造，但它是品类主导。你拥有你的品类，这很好，但还不够清楚区别在哪。"**

- ✅ **他给的定义本页认为可直接用**：**"品类创造理想的形态是：你一听到那个品类，那两个词就代表你的公司。没有长文、没有宣言、没有演讲，就两个词，也许加几个例子，剩下的你的听众自己能接下去。"**
- 🔗 ⚠️⚠️ **而他举的范例是 HubSpot 的 inbound vs outbound marketing，并点名"我们另一位嘉宾，HubSpot 的 Dharmesh"**（⚠️ **字幕作 "Dorsha"**）。✅ **本页标注这处巧合值得记：本库同一天摄取的另一期就是 [Dharmesh Shah 本人](20261110-a16z-dharmesh-shah-incentive-constraint-replay-the-codebase.md)，而他在那一期给的恰好是同一个故事的内部视角（"P&L 上每一个行项目都挂着一家千亿美元以上的软件公司，除了营销"）。** ✅ **本页判两期合起来给了"品类创造"一个完整案例：一侧是创造者自己的论证结构，另一侧是把它当作判准来衡量别人。**

### ⚠️ 个人侧，以及一处必须防误读的数字
