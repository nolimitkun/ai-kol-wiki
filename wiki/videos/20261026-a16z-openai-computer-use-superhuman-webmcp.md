## 一、⚠️⚠️ 两处 against-interest 让步，本页认为是全期最有价值的内容

### ① Atlas 里的 agent 体验"没什么人用"

（[00:41:27]）这段的语境是 James Sun 讲自己的时间线（2026-01 入职 OpenAI、最初做浏览器产品）：

> ⚠️⚠️ **"我们意识到的一件事是，在那个产品里，agentic 的体验因为几个原因其实并不是一个大的卖点。没有很多人用它，部分原因是我觉得人们大体上把它当成一个普通浏览器。"**

- **他给的转折**：**后来因为模型能力变好，他们把 browser / browser use 并进了"所有已经有 agentic 用量的现有产品"里**，然后**"我们看到的是 YC 级别的周环比增长"**。⚠️ **"YC 级别"无任何数字，本库不采信增长强度。**
- ✅ **本页认为这条该被长期保存的理由**：**它是一条"把 agent 能力放进一个独立新产品里失败、放进既有有用量的产品里才起来"的记录，而且来自做这件事的人本人。** 🔗 **与本库这一周的四份"企业采用断点"材料落在同一处**——[Tenex 的 5% 漏斗](20261021-latent-space-tenex-enterprise-agent-5-percent.md)、[Moshi 的"我把系统建好了，人人都说需要，没人点"](20261022-latent-space-moshi-recsys-for-traders.md)、[a16z Frontier 的 shadow adoption](20261022-a16z-frontier-biggest-gap-shadow-adoption.md)、[陈春宇把全部 AI 助手功能砍掉只留翻译](20261023-uncle-moon-chen-chunyu-intent-chat-translation.md)。⚠️⚠️ **本页标注这是第五份，而且第一次来自模型厂商自己的消费产品。**
- ⚠️ **"Alice / Atlas"这个产品名本库不写定**（见页首）。

### ② 四个浏览器互不通气

（[00:38:24]–[00:39:24]）被问"接下来最期待什么"，James Sun 给的不是能力而是一处自家的产品债：

> ⚠️⚠️ **"今天你可以装 Chrome 扩展，它会用你 Chrome 里的密码管理器和一切。然后我们在桌面 app 里有一个内置浏览器，它有另一套 cookie 和另一套密码。你在云上的那台电脑又有另一套。对普通消费者来说这挺迷惑的——我为什么有四个互相不通气的浏览器？我在一个里面开了标签页，它会在另一个里面出现吗？"**

- ✅ **他自己给了这件事的性质判断，本页认为这句最该引用**：**"这有点像个悖论，因为我觉得 computer use 其实是最容易理解的 AI 产品——它就是一个 AI 在用你的电脑。但因为要管理的不同状态、以及你在不同地方使用它，实现细节有时会渗出来，于是它就变得不好 grok 了。"**
- ✅ **本页的标注**：**这是一条"身份与会话状态在哪"的产品债，而不是模型问题。** 🔗 **与 [George Kurtz 那期的"agent 的身份与凭证"](20261022-no-priors-crowdstrike-kurtz-agent-state.md) 是同一问题的两端——**那边问"企业怎么知道哪个 agent 在用谁的凭证"，这边承认厂商自己都还没把一个用户的四套凭证理顺。**

- ✅ **他给的后果判断两期一致，也是本页认为真正可检验的那部分**（本期 [00:09:07]）：**"那会是一次剧变……突然之间任何你本来可以手动做的事，它都能做得更快。所以除非你真的因为某种原因想自己做，默认情况下你大概就想让 agent 替你做。"** ⚠️ **他自己留了口子："而我其实认为人们可能有很多理由想自己做。"**
- ⚠️ **速度为什么重要，他给的理由本页认为比那条主张更有信息量**（[00:08:07]）：**computer use 的强项本是后台运行（"有时候它花多久都不要紧，因为你可以去干别的"）**；⚠️ **但"有时候你想看着它、确认它做对了"**，**而真正要避免的感受是"我本来自己做就行了，还更省事"**。

### ⚠️ Astra 带来的变化：他自己的口径是"边缘上的"

（[00:01:00]–[00:03:02]）⚠️ **全部自述、全部无数字，本页记为立场；但本页认为它的克制值得照录**：

- **Ari 的三条**：① **平均更快一点，因为完成同样任务用的思考 token 更少**；② **某些创意类工作更好**（举的例子是发布视频里"你跟它说话、它在 Microsoft Paint 上画东西"，✅ **他自己说"这大概会迁移到其它创意任务"——用的是"probably"**）；③ **"边缘上更可靠"**——⚠️⚠️ **而他给了一个本页认为很诚实的提法**：**"99% 可靠和 97% 可靠之间，有一个很难察觉但其实很重要的小差别，我觉得它就是稍微高了一点，而那种感觉挺具体的。"** ✅ **即他明确说这是感觉而不是测量。**
- **James 的补充落在安全**：⚠️ **"我们最对齐的模型"**，依据指向**system card**（**"对 prompt injection 的抵抗力好得多，更不容易采取任何非预期的动作"**）。⚠️ **本库不作独立核实；而他随后把它接到商业场景上——采购、与供应商/客户对话这类敏感事务上"你会觉得安全得多"。**

## 三、⚠️⚠️ 企业侧的控制面：从"模型足够对齐"退到"确定性控制"

（[00:17:14]–[00:19:16]）✅ **本页认为这是全期机制密度最高的一段，而且它的论证结构值得单独记：他们并不是用"模型更对齐"去说服企业，而是承认那说服不了。**

> ⚠️⚠️ **"第一层是，我们怎么创造确定性的控制。我觉得那才是真正让企业有安全感的东西——即使我们的模型是史上最对齐的……但当企业管理员可以直接说'某些任务或某些数据源就是太敏感、不能用'的时候，就是会有一种安全感。"**

**两件已发布的东西（⚠️ 发布口径自述）**：

1. **确定性沙箱**：**可以说它能用哪些应用、不能用哪些；能用哪些网站、不能用哪些。**
2. **人在环的档位**：**"哪些类型的动作需要人介入"**——举例是**任何下载与上传要人批准、任何首次访问新网站要人批准**；✅ **他明确说"这些都是旋钮，企业可以自己调"。**

**第三件是一个模型而不是规则**（[00:10:08]–[00:11:08]）：

- ⚠️⚠️ **"我们有一个很棒的系统叫 Guardian……是 app 里的自动批准，它是一个很聪明的模型，在看 computer use agent 采取的每一个动作，来判断它是否安全、是否和书面意图（written intent）对齐。"**
- ✅ **本页标注这个设计的位置**：**它是"用一个审查模型逐动作比对声明意图"，即把对齐问题从训练期挪到了运行期。** 🔗 **与本库既有材料并读**：[Thariq 把 harness 拆成脑/手/界面](../people/thariq-shihipar.md)、[auto mode 作为核心 harness 的一部分](../topics/llm-os.md)；⚠️ **而 [CrowdStrike 的 Kurtz 那期](20261022-no-priors-crowdstrike-kurtz-agent-state.md) 与 [Cloudflare 的 Knecht 那期](20261023-no-priors-cloudflare-knecht-weekly-log4j-agent-kitties.md) 都主张防守方不能依赖模型层——Guardian 恰好是模型层的一次尝试，本页记下这处张力，两边无交流。**
- ⚠️ **消费侧与企业侧的分叉他说得很直接**：**"消费者可能就是'我想让它什么都干，别来问我批准'；而企业可以决定哪一类动作才放行。"**
- ⚠️ **他给的第二层是展示 eval**：**"给企业管理员看我们内部跑的所有对齐 eval，包括和内部与第三方 eval 的对照。"** ⚠️ **无任何具体 eval 名或数字。**

### ✅ 一条产品设计上的信任机制，本页认为值得记

（[00:19:16]–[00:20:16]）Ari 讲的是把"看得见"做成产品：**"我们在设计上投了很多工作，所以你想看它做任务时总能看到那个光标。它还会以一种有趣的方式做动画，这样看着不无聊。"** 以及**首次使用新应用或网站前征求许可**，**"这能帮人不觉得它要在你电脑上搞出什么脱缰的事"**。

- ✅ **他给这件事的名字是"建立信任的时刻"**：**"你得有这么一个建立信任的模式，搞清楚它是什么感觉、你想让它替你做什么，然后你慢慢就更自在了。"**
- ⚠️ **主持人当场的反应（"那个光标太可爱了"）与这条机制形成了一个本页认为该照录的对照**：**可观测性在这里同时是安全机制与情绪设计，而节目没有区分两者。**

## 四、⚠️⚠️ 开放网络上的两个问题：广告收入与 WebMCP

（[00:11:08]–[00:13:13]）✅ **本库此前完全没有 WebMCP 这条线，而这一段也是本库第一条由 agent 厂商自己承认发布方商业模式冲突的材料。**

**James Sun 把开放网络上的主体分成两个阵营**：

- **阵营一：商业模式与 agent 不相容**。⚠️⚠️ **"你想想广告主、发布方，他们的商业模式整个建立在广告上。如果 agent 替他们用网站，那收入从哪来？而在大多数地方，agent 的一次广告展示并不真的算进真实收入。"** ✅ **他自己的定位是"这是个有意思的问题，我们一直在和合作团队一起处理"**——⚠️ **没有给任何解法。**
- **阵营二：想拥抱 agent 的公司正在采用"让人与 agent 一起用"的标准**。⚠️ **他点名 WebMCP**，并说**"我们在 app 的浏览器里加了支持"**。
  - ✅ **他给的形态是分工而不是替代**：**"你可以想象 agent 把用这个站点的体验抬高，但它不是完全替代它"**；他自己的例子是**购物——"我还是喜欢看所有的酒店、航班和地方"**，**agent 做乏味的部分，而"好，现在我想完成交易、输入我的信用卡"这段交回人**，然后再交回 agent。
  - ✅ **他对 WebMCP 的定位很清楚**：**"你和网站的接口仍然是网站本身，而不是一个 API，但人是和 agent 一起在用它。"**

⚠️ **本页标注这条与本库既有材料的位置**：
- 🔗 **[Chris Dixon 的"互联网的契约正在破"](20261022-a16z-frontier-biggest-gap-shadow-adoption.md)**（给 Google 摘要换点击的交易失效、证据是 Stack Overflow 流量断崖）——✅ **这一期是同一处断裂的供给侧版本，而且说话人是造成断裂的那一方。**
- 🔗 **[Dane Knecht 的"给人的网和给机器的网该不该分开"](20261023-no-priors-cloudflare-knecht-weekly-log4j-agent-kitties.md)**：⚠️⚠️ **两方给的答案方向相反**——**Knecht（在发布方一侧）主张人与 agent 各自接住、按内容站自己的 CPM 定价、"翻译层只是额外的 token 燃烧"；而这一期（在 agent 一侧）主张同一个界面上人与 agent 协作（WebMCP）。** ✅ **本页认为这是本库目前关于 agentic web 最清晰的一处立场对立，而且两边都在自己的利益方向上。**
- 🔗 **[Erik Bernhardsson 的"训练数据成了新的分发战场"](20261022-latent-space-modal-rectangles-duration-transformation.md)**：同一位移的第三个投影。

### ⚠️ "共享智能层" vs 碎片化

（[00:31:19]–[00:32:20]）**Ari 与 James 都提到一个他们不想要的终局**：

> ⚠️ **"如果每个网站都有自己的 agent、而它不跟你的 agent 说话，那会是一个非常碎片化的世界。"**

- **他们想要的形态是"共享智能层"**：**你的 agent 在别处用遗留软件、做别的事，而当你在用某个应用时，那个应用希望拿到那部分上下文，从而给出更好的体验。**
- ⚠️ **本页标注：这条主张恰好要求一个跨站点的、以用户 agent 为中心的上下文层，而谁来持有那一层正是上面那处立场对立的核心。节目没有点出这一点。**

## 五、企业用例：boring is opportunity

（[00:20:16]–[00:23:17]）⚠️ **全部为他转述的客户与内部用例、无一个客户名与效果数字；但本页认为这份清单的具体性有参考价值，因为它全部挂在"没有 API"这个条件上。**

**James Sun 把它分成两类，并明说第一类"更无聊"（主持人当场接"无聊就是机会"）**：

| 类别 | 具体场景 | 共同条件 |
|---|---|---|
| **一、自动化乏味工作流** | **所有 system of record**：ERP、CRM | — |
| | **采购**：原流程是各团队填一张上千行的大表 → ops 团队把它录进内部采购软件 → 定成一批订单行 → 采购团队再据此逐个联系供应商 | ⚠️ **多段人工搬运** |
| | **财务月末对账**：公司里有很多台账（费用台账等），⚠️⚠️ **"很多这类财务软件没有 API 可以快速把东西拉出来"**，所以让 computer use 把各台账看一遍、对账、把可疑项标出来 | ⚠️⚠️ **无 API 是前提** |
| | **销售**：销售团队用很多不同软件（转录、取数），让 computer use 去做 prospecting 再写进 CRM 或外联软件 | — |
| | **市场调研** | — |
| **二、更有创造性的"更有野心的工作"** | **电路设计、建筑类工作、硬件工程、游戏设计**（依据是"模型现在在视觉设计上很好"） | ⚠️ **他自己说"企业现在还较少想到这些，因为它们在想那些无聊的机会"——即这一类目前没有采用证据** |

- ⚠️ **他顺带给了一条个人用例作为方法示范**（[00:22:17]）：他做了个羽毛球视频标注工具，为了看市面上的同类产品（网球/壁球/匹克球），**让 computer use 去逐个注册账号、试用、截图、给反馈**。✅ **本页认为这个用例比上面的企业清单更可核对，因为它的产出形态（截图 + 反馈）是他自己验收的。**
- **Ari 的消费侧对应清单**（[00:23:17]–[00:25:19]）：**填 DMV 表格、批量退订邮件**；以及**一类"本来没时间也没想到要做的事"**——他自述**用它维护个人财务与备餐的表格**，并提到**一位做私人教练的朋友给客户做定制内容**；⚠️ **他说自己用的是 Apple Numbers（"一个挺偏门的表格程序，但模型照样做得很好"）。**

### ⚠️⚠️ 一条被顺带说出、本页认为很要紧的倒转

（[00:04:03]）James Sun 解释企业侧为什么用例"相当明显"时说：

> ⚠️⚠️ **"企业内部有大量遗留软件没有任何 MCP 工具。那些软件已经被用了 15、20 年。而很多时候那些东西对一个普通人来说其实挺难用的——很多 UI 是上一个十年的。你甚至不知道怎么操作那些关键功能。"**
> **"所以我们看到有公司在造 skills，教模型更好地使用它们。"**

✅ **本页的标注：这里出现了一个倒转——computer use 的卖点不只是"替人做"，而是"agent 比在职员工更会用公司自己的老系统"。** ⚠️ **这条如果成立，它把 ROI 的来源从省人力挪到了"消除培训与操作知识的损耗"，而本期没有给任何一例数据。** 🔗 **与 [Lio 那期"发票软件只覆盖了这份工作的 20%"](20261002-a16z-lio-procurement-agents-incumbents.md) 落在同一类工作上（采购），✅ 但两者对瓶颈的判断不同：Lio 说瓶颈是软件覆盖不到的那 80% 的工作，这一期说瓶颈是人用不好那 20%。**

## 六、⚠️ 遗留软件 vs AI 原生：两人都给了"同时成立"

（[00:25:19]–[00:31:19]）主持人 Fabrizio 的问题很直接：**是"留住遗留软件、在上面加一层 agent"，还是"AI 原生的新玩家用 computer use 把它们换掉"？**

- **Ari 的答案是两条同时持续**：⚠️ **"造新软件的成本与复杂度低了这么多，所以你可以想象软件变化非常大；但世界上也存在这么多遗留软件，而 computer use 非常适合与它们交互。"** **"今天在生产里跑的软件，很多是 10、20、30、40 年前写的，我不觉得那些东西会一夜之间消失。"**
- ⚠️⚠️ **而他给了一条机制，本页认为是这段最有预测力的一句**：**"computer use 的存在可能给公司更多压力，让软件更好地和 agent 一起工作——因为所有软件默认都会和 agent 一起工作。"** ✅ **他点 WebMCP 作为这件事的例子。**
- ✅ **他最期待的形态是"三层叠"**（[00:31:19]）：**"有传统用户界面、但底下在用 agent，而有时那些 agent 自己在用 computer use 去自动化遗留软件，从而给你一个好得多、更贴合目的的体验。"**

### ✅ 两人都明确反对"UI 会消失"，而且理由不同

- **James Sun 的理由是手艺与被设计感**（[00:27:19]–[00:29:19]）：⚠️ **"如果互联网变成只是一堆 agent 互相说话、人不再用任何东西了，我会非常难过。"** **"手艺与匠人式软件就是用起来感觉好，因为设计它的人真的理解客户想要的体验。"**
  - **他的例子**：妻子最近玩一个连五子就赢的棋类游戏（⚠️ 字幕作 "O Mac"，按 Omok 理解）、**和朋友在线下棋被打得很惨**，于是他给她做了个**战术训练器**（走不同开局）——**"我知道她喜欢用某种方式做，她喜欢某些学习方式"**。
  - ⚠️⚠️ **而他的推论是本页认为该被 [AI 商业化与价值捕获](../topics/ai-business-and-value-capture.md) 记下的那条**：**"如果任何人都能造任何东西，而且能在很短时间里为很小众的用例造出这种精心打磨的软件……我觉得那是一个很美的世界。"** ✅ **他同时把分工说清了**：**训练结束后的错误总结可以交给 agent；但"她真的在和 AI 对练、在变强"这件事"是人必须自己做的"。**
- **Ari 的理由是直接操作**（[00:29:19]）：⚠️ **"人类的硬连线就是要直接操作，你真的想用自己的手去移动、去做事。"** **他的对照是受众规模**：**过去的软件"是为上百万、上千万、上亿、几十亿人设计的"**；⚠️⚠️ **"而我认为我们会进入一个时代，任何一个软件都可以是为一百个人、或者一个人设计的。"**
- ✅ **主持人 Seema 给了一个两桶框架，本页认为它比两位嘉宾的表述更可操作**（[00:30:19]–[00:31:19]）：
  - **消费侧**：⚠️ **"不是它的效用，而是互动、学习本身的乐趣"**——你想花时间在上面。
  - **B2B 侧**：⚠️⚠️ **"审计日志（audit log）"**——**"产品真正是：我作为人类用户设定目标，然后能够理解其中的逻辑，但不必走完整条执行链。"** 她的例子是**任何 B2B 用户仍然需要搞清楚"那笔款为什么付出去了"、能回去拿一份摘要、并能说"在这个时点付这个人、30 天给这么多折扣"**。✅ **她的收尾本页认为该引用**：**"我们为什么要将就垃圾软件？"**

## 七、⚠️⚠️ 厂商侧对"扩散缺口"的承认，以及给创业者的护城河说法

（[00:34:21]–[00:37:23]）⚠️ **这是厂商在被问"创业公司还有没有护城河"时的回答，立场上有动机往"有"的方向说；但本页认为其中两条具体内容仍然有价值。**

- ⚠️ **一条关于自家人力的承认**：**"即使我们现在挺大了，有几千人，我们内部仍然觉得被摊得很薄……相对于所有这些问题，团队并不大。"** ✅ **他给的推论是行业专长那条老论证**（懂监管、懂 go-to-market、懂怎么服务那些客户），⚠️ **而他说今天真正存在的护城河是两个词——字幕作 "speed and pay"，疑为 "speed and taste"，本库不写定。**
- ⚠️⚠️ **而本页认为真正值得保存的是这条四步缺口**：

> **"住在旧金山，我们会看到很多这样的想法：'哇，实验室什么都能干，有 Codex，为什么不是每个人都装上 Codex 让它干活？'但对普通的美国人、普通的中小企业主、甚至普通的企业来说——连搞清楚这些工具能干什么是第一；把工具以合理的方式连起来是第二；部署是第三；服务是第四。"**

- ✅ **本页标注：这是本库第一次看到模型厂商一侧把"扩散缺口"拆成四步**，🔗 **而它与 [a16z Frontier 那期"很多公司没在采用 AI，而它们的员工在采用"](20261022-a16z-frontier-biggest-gap-shadow-adoption.md) 以及 [Tenex 的 5% 漏斗](20261021-latent-space-tenex-enterprise-agent-5-percent.md) 指向同一处**——⚠️ **但注意这四步全都落在"做集成与服务的人"身上，这正好是一个对厂商有利的分工结论（模型归我、集成归你）。本页记为立场。**
- ⚠️ **他给的那个用例本页认为是全期最具体的一条端到端流程**（[00:35:21]–[00:36:22]）：一家公司用 computer use 帮**餐饮集团**——**拍后厨储藏间的照片 → 视觉模型按次日客流预测判断缺什么 → 用 computer use 去采购软件下单次日食材 → 再进 ERP 调整员工排班表**（依据是"去年同一时段这个点客流更多，比如因为节假日"）。⚠️ **无公司名、无规模、无效果；采购软件名本库无法写定（见页首）。**

## 八、其它值得记下的碎片

- **"我现在什么都先问能不能让 agent 做"**（[00:14:13]）：James Sun 自述把它变成一条强制练习——**"每当我有一个任务，我想的第一件事就是：能不能直接让 agent 做？"** ⚠️ **他的例外只有两类**：**"如果我在给某人发消息，我想让它感觉是我发的"**；以及**"除非有什么特别敏感、我想在环里的事"**。✅ **Ari 的说法更诚实一点**：**"我在努力养成那个冲动……因为有时候太容易被锁在老的做事方式里了。"**
- ⚠️ **"computer use 不是一个你会单独拿起来用的东西"**（[00:16:13]）：**James Sun 说他已经不再区分"这是不是一个 computer use 任务"**——**"它其实是模型为了做成任何事而拥有的那个通用 API。所以如果你有一个有野心的任务，越复杂，它就越可能在某个环节用到 computer use。"** ✅ **他给的唯一例外是"任务简单到我自己点两下更快"**，⚠️ **而他接着说随着速度变快"也许我连那个都不需要做了"。**
- **"通用性"是 Ari 的核心卖点**（[00:15:13]）：⚠️ **"它和我们造过的任何别的东西都不一样——别的东西需要开发者做点工作才能被采用，得有人去造一个 connector 或 MCP server。computer use 和一切都能配合，而且它用应用的方式和人用的方式一样。"** 🔗 **本库此前已记过他 2026-09-30 的那条更强版本，以及 [本库指出的那处张力](../topics/llm-os.md)——computer use 实际上越来越依赖无障碍树与结构化表示，而不是"看屏幕点鼠标"。⚠️ 本期他没有提这一层，所以这处张力仍未被厂商侧回应。**
- **主动性（proactivity）是两人都押的下一步**（[00:05:04]–[00:08:07]、[00:39:24]–[00:40:26]）：
  - ⚠️ **James Sun 给的两个一手用例**：**公司邮件系统里外部日历邀请不会进日历，于是他老漏掉外部会议**，而 dots 现在会主动标出来并问"要不要我在 Gmail 里替你接受"；以及**Slack**——**他原先用 Codex 的 automations 做"每小时/每半小时去捞一次"，结果"我最后把很多通知都屏蔽了，因为有时有用有时没用"**；✅ **换成 dots 后他给的是高层目标**（"如果我汇报链上任何人说了什么就标给我；如果有人给出关键反馈，你自己判断"）。
  - ⚠️ **他还给了一条用上云电脑的组合流程**：用户报 bug 时通常带 Sentry 日志，于是让它**驱动本地浏览器 + 云电脑，登录 Sentry、拉日志、分析、给反馈**。
  - ✅ **Ari 把主动性接到一条产品诊断上，本页认为这句最该引用**（[00:39:24]）：⚠️⚠️ **"今天这个产品的另一个难点是，你得花点心思想怎么用它、你得记得去用它、你还得说服自己去做一些和你习惯不同的事。"** 落点是**"我很期待一个 agent 能适应你、而不是你去适应它的世界"**。
- **他们怎么描述当前节点**（[00:40:26]–[00:43:30]）：⚠️ **Ari："过去 6 到 9 个月非常兴奋"**——**他们开始做这些产品时"很少有人用"**，**"今年早些时候模型突然就在这类任务上变得很好了"**（归功于研究团队），**"而就在过去几个月，产品突然开始疯长"**。✅ **他主动降了一处温**：**"但它仍然非常早，仍然只有一部分用户在用 computer use。"**
  - ⚠️ **下一个拐点他们都指向云**：**"桌面仍然非常是高级用户的东西……大多数消费者在手机上。"** 目标是**"给每一个只用手机过日子的人一台他们甚至不需要理解怎么用的强大电脑"**，**"把它带到十亿用户"**。
  - ✅ **Ari 的收尾一句**（[00:43:30]）：**"我觉得我们正处在 computer use 的 scaling moment，消费端和企业端同时。"**（⚠️ **字幕作 "skilling moment"，按视频简介的 "entering its scaling moment" 还原。**）
- ⚠️ **一处主持人提出但没被回答的问题**（[00:17:14]）：Seema 问企业用户那套"经典反驳"——**"是的，人点过去大概做得更差，但有那种问责感：这是那个人，受过训练"**。✅ **回答全部落在控制面（沙箱 + 人在环 + eval 展示），没有一处触及问责归属。** 🔗 **而问责归属这条本库恰好有材料**：[All-In 四人把 agent 代人登录的责任逐一表态（全部落在用户侧，例外是 rogue agent = 产品责任）](20261023-all-in-php-cyber-week-arora-agency-liability.md)。**本页标注这是本期最明显的一处避而不答。**
