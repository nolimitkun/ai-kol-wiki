## 一、"黑色十月"是什么

- ⚠️ **他的定义**（[00:01:01]–[00:02:02]）："黑天鹅事件"——**单月安全事件数量前所未有**，包括十月发现的漏洞数量、严重度（PHP 漏洞"可能是 AI 找到的最严重漏洞"），以及**更糟的：AI 攻击者的兴起**，以前所未见的速度与专业度攻击公司、创业公司、"冰箱"。
- **他的三段时间线**（[00:03:03]–[00:04:03]）：① **Mythos 时刻**——"天哪，模型能找漏洞了"，但"什么都没发生，太阳照常升起"；② **OpenAI–Hugging Face 事件**——看到了 AI 攻击的风险，"但那是意外的攻击"；③ **黑色十月**——"所有我们说会来的理论，全都来了，砸在我们身上"。
  - 🔗 Hugging Face 事件在本库的材料汇总见 [LLM 安全主题页](../topics/llm-security.md)；⚠️ **本期把它定性为"意外"，与 [Ajeya Cotra 那期](20260901-dwarkesh-ajeya-cotra-agent-swarm-investigation.md) 的调查叙述是否一致，本期没有展开，本库不做判断。**
- ⚠️⚠️ **机制两条**（[00:04:03]–[00:05:06]）：① 模型已能**找到并利用复杂漏洞**；② **开源模型追上来了**——"不一定是复杂的 PHP 漏洞，可以只是你 API 里的一个错误……一次以前顶尖攻击者要几周或几个月的攻击，现在大约 20 分钟"。

## 二、⚠️⚠️ 开源模型差距与攻击目标

- **差距**（[00:05:06]）：Zane 说业内进攻侧的估计"六到九个月"；Luttwak 说**找漏洞上前沿领先"不超过三个月"**，而进攻侧的真正问题是**利用**——一个不需要很高明的攻击者，用开源模型就能在 20 分钟内找到并用上你代码里的问题。
- ⚠️⚠️ **被盯上的是有 AI key 的公司**（[00:05:06]–[00:06:10]、[00:30:26]–[00:31:27]）：Wiz 博客最初列了 **9 家被攻击的 AI 开发平台，现在已到 15 家**；"创业公司现在才是 LLM 劫持（LLMjacking）的主要目标"。**他给的唯一具体动作：给 key 设额度上限**——"被偷了你不想吃一大笔账单，我们看到这种事发生得很多"。
- **CEO 视角的场景**（[00:29:22]–[00:30:26]）："你醒来，安全团队说昨晚出事了，我们一小时后才醒"——Zane 插话"一小时已经很客气了"——"而攻击从进入到拿走所有客户的 AI key 只要 20 分钟"。

## 三、PHP 漏洞：发现、泄露与补丁

- **覆盖面**（[00:07:11]）："几乎 100% 的客户都跑着某些 PHP"；"PHP 约占互联网 70%"（主持人口径）。
- ⚠️ **补丁速度**（[00:07:11]–[00:08:12]）：**头两三天约 50% 打了补丁**——"还谈不上自动化补丁，但他们非常清楚补丁的重要性"；**但这一个漏洞"要好几年才能解决"**，大量旧版 PHP 根本没有补丁。
- ⚠️⚠️ **补丁链本身跟不上**（[00:09:12]–[00:10:12]）：信息常在 CVE 公布前就泄露；CVE 出来时补丁常常还没出。**"PHP 这次我们和 PHP 一起准备了几个月让全行业就位，结果提前泄露了"**；Linux 内核即便收到漏洞报告，补丁到达所有发行版"可能要几周甚至几个月"——"**这个行业没为 AI 准备好，AI 能在几分钟内利用**"。
- ⚠️⚠️ **自动补丁：他说"我看不到路径"**（[00:10:12]–[00:11:12]）——对存量公司不现实；**新公司应该从第一天就设计成能自动打补丁**：自动开发（工单 → 补丁）+ 自动测试 + 自动 CI/CD + 自动 DevOps。🔗 与 [Jassy"把几乎全部代码重写成 agent 可改的，理由是安全"](20261023-a16z-andy-jassy-capex-cash-cycle-barbell-inference-cost.md) 同一方向，但 ⚠️ **Luttwak 明确把它限定在新公司，认为对大部分存量代码"甚至不现实"**。
- **主持人提出的数据矛盾**（[00:08:12]–[00:09:12]）：把补丁 diff 变成可用 exploit 的时间在下降，**而打补丁的时间过去 20–25 年反而上升了**。

## 四、⚠️⚠️ 发现漏洞"像比特币挖矿"

- （[00:11:12]–[00:13:13]）PHP 漏洞由 **Wiz 与另一个团队（字幕作 "Califf"）独立发现**；他的解释："**漏洞数量会减少，但就像比特币，总还有更多，新模型能挖出更多**"——所以每出一个新模型，就会有多个团队同时发现同一批漏洞。他说为 Wiz 的零日竞赛（字幕 "ZDC"）准备时，又有一个"会对互联网有重大影响"的严重漏洞被**多个团队同时报告**。
- **Wiz 内部的做法**：一个叫 **Atlas** 的漏洞检测 harness，**持续换不同厂商的模型跑**（OpenAI、Google、Anthropic），"每个模型能力都不一样"；策略是**用前沿模型那几个月的领先，集中扫关键基础设施**——"但世界上代码太多了，攻击者还是会找到我们没找到的"（[00:13:13]）。
- **模型选择**（[00:14:13]–[00:15:14]）：前沿模型、各自的 cyber 版本、每个版本行为与速度成本都不同——"复杂的矩阵"；**"独立公司唯一能做的是一直试所有模型、找最好的组合"**。⚠️ 被问到身为 Google 旗下为何不只用 DeepMind 模型，他没有正面回答两者关系。

## 五、⚠️⚠️ 成本工程：分层流水线

- **blue agent（调查攻击）**（[00:15:14]–[00:16:15]）："我不能在每个事件上跑最贵的模型"——**确定性检测 → 便宜模型 → 更高级的模型 → 全都判恶意时才让最高级模型终判，再告诉客户**。"**人们说用 AI 开发很容易，对大多数创始人不是真的——关键是服务的成本**。"
- **red agent（攻击自己）**（[00:24:20]–[00:26:20]）：同样分层——先确定性地分析全部暴露面 → **exposure agent 只看所有未认证、暴露在公网的东西，"每个端点几分钟，因为你有一百万个端点"** → 再做更深的渗透与代码分析，**关键应用可能花 10 小时去打**。"**一切都会变成流水线。**"
- ⚠️ **两侧联动**（[00:26:20]）：工程说修复太贵 → 让 blue agent 在那里加检测。
- 🔗 ✅ **本库标注**：这与 [Arca"在能力边缘约束"](20261031-latent-space-arca-agents-prompt-people-constrain-at-capability-edges.md) 和 [Kevin Mandia 的自主防御](20261006-a16z-kevin-mandia-armadin-autonomous-defense.md) 的架构相近；**本期多给的是"按端点数量分配推理预算"这一具体粒度。**

## 六、⚠️⚠️ 持续扫描 vs 一次性扫代码

- ⚠️⚠️ **"你可能浪费了 500 万美元"**（[00:17:17]–[00:18:17]）：Mythos 发布后人们说"必须把代码全扫一遍"——假设你四月扫了，**"现在又出了 Mythos 1.2，你再扫一遍"**；"**有些客户现在在扫代码上每年花几千万美元**"。问题是**怎么把预算花成持续扫描而不是单次扫描**——"我不会告诉你我们已经解决了"。
- ⚠️⚠️ **"Mythos 的 PR 去错了地方"**（[00:27:21]–[00:28:21]）：**"我其实不认为扫代码是你能做的最有效的事……先扫你的外部暴露面。"** 例子：两天前一次大事件——**移动应用里硬编码的 key 暴露了大量用户数据**；"攻击者就是从未认证的面进来的"。
- **"门槛水位一直在升"**（[00:22:17]–[00:24:20]）：把钥匙藏在脚垫下昨天算安全，"但攻击者每周都在获得超能力"——**昨天安全的应用今天可能不安全，唯一办法是持续用最新模型攻击自己**。
- **采用情况**（[00:26:20]–[00:27:21]）：⚠️ 自述 Wiz 多数客户已在用 red agent，是"增长最快的功能之一"；"整个行业做得不够"。

## 七、安全预算与"安全团队做的事大多不是安全"

- **主持人给的数据点**（[00:31:27]–[00:32:27]）：一位 CISO 告诉 a16z 合伙人，**明年安全预算预计涨 80%**（"偏高端"）。🔗 对照 [All-In 那期"安全预算 4–10% 的现状基线"](20261023-all-in-php-cyber-week-arora-agency-liability.md)。
- ⚠️⚠️ **他的回答是"预算解决不了"**（[00:32:27]–[00:34:29]）："假设一群最精英的黑客要进你家——他们不一定走门，可能走窗、走屋顶。多少房子准备好了？" **"不是预算问题，是专注、是安全架构与安全设计"**；"大部分传统安全工具已经不相关了"。具体：沙箱与隔离、网络 / 进程 / 镜像锁定；"**按国家级攻击者来准备……别以为跑在 Kubernetes 集群里就行，Linux 一直有零日，谁都能逃出容器**"。
- ⚠️⚠️ **"安全团队做的大部分事都不是安全"**（[00:35:30]–[00:37:34]）：检验方法是"你花多少时间在红队，多少时间在合规和写报告？"——"**我们应该停掉大部分在做的事，只专注找到关键风险、想办法缓解或至少加上检测，以及响应准备**"。点名过时的一类：**传统 CSPM**（云配置检查清单）——"我不在乎那个，你要在乎攻击者从哪儿来"。
- **云安全不变的部分**（[00:19:17]–[00:21:17]）：AI 攻击者仍从老问题进来，"我们只是多了漏洞和攻击类型，不代表你不用修老的"。**变化是客户期望**：以前给"漏洞 + 优先级"，现在要**回到代码、生成修复、提 PR**；以前给"检测"，现在要**完整调查、取证、根因、把攻击者赶出去**。⚠️ **"下一步是自动化响应，这很吓人，但我觉得我们没有别的选择"**（[00:21:17]）。
- **存量组织的难点**（[00:38:35]–[00:39:37]）：新公司可以全自动；存量组织"几千个开发者、不知道谁拥有什么资源"，组织知识"不写在任何地方"——"**如果我不能在几分钟内响应，我还有存在意义吗？**"

## 八、未来两三年

- **Zane Lackey 的预测**（[00:39:37]–[00:40:38]）："**我们正在回到 90 年代和 2000 年代**"——未认证的远程代码执行满天飞、频繁泄露，"甚至不意外看到互联网蠕虫回来"；转述 Martin（Casado）的 Windows XP 回忆：联网安装时，**蠕虫感染比打完补丁还快，只能离线安装**。
- **Sarah Wang 追问**：Luttwak 四月博客说"12–18 个月后会有一个 Y2K 时刻"，是否要提前？（[00:40:38]）
- ⚠️⚠️ **他的回答**（[00:41:38]–[00:42:39]）："黑色十月可能只是开始"；对比 90 年代，**"我们对技术的依赖高得多"**；以及——"**这几乎是人类目前唯一一个 AI 比人类强的领域，这才是问题**"：今天就有一次**用内核驱动零日**的攻击，"这本该非常罕见，现在每天都在发生，人类攻击者做不到"。
- ⚠️ **"我看不到两年以后"**；能活下来的公司是**现在就用新方式设计暴露在公网的系统的公司**，"**没准备好的东西应该尽快下线**"（[00:42:39]）。
- **公共基础设施**（[00:43:41]–[00:44:41]）：主持人提到欧洲冷藏设备遭攻击对食品供应链的影响；他"确实担心"——冰箱、交通，"任何联网的东西都有风险"；Wiz 的 **Scan for Good** 免费帮公共服务扫描，目的是让对方意识到"这是个更大的项目"、自己开始做红队扫描。

## 本库的判断

- ✅ **最值得记的是一条与"Mythos 叙事"相反的资源排序**：**先外部暴露面、后代码**——来自一家同时卖两种产品的公司，所以至少不是在为单一产品辩护。⚠️ 但"扫代码浪费 500 万""几千万美元"都是没有出处的示意数字。
- ✅ **"开源模型落后不超过三个月 / 原本希望一年"是本库目前对进攻侧开源差距最短的一个估计**，与主持人转述的业内"六到九个月"并列记录，⚠️ 两者都无方法说明。
