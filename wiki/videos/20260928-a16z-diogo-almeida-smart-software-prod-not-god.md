## 概要

- **诊断**：⚠️ **"自动化到底他妈在哪儿"**——AI 聪明到离谱，却**在除聊天与写代码之外的一切事情上毫无用处**；"这太悲剧了"。
- **区分**（本期最该记住的一条）：Claude Code / Codex 是 **just-in-time software**（Garry Tan 的说法，他认可），**产出的代码和人写的是同一种东西**；他要的是 **smart software**——**不是自动化软件工程，而是扩大软件本身能做的事**。
- **口号**：⚠️ **"We build prod, not god"**（我们造生产环境，不造神）。Horowitz 说这是他最喜欢的一句。
- **RSI 立场**：⚠️ **"我不认为我们走在 RSI 的路上，当时就不认为，现在也不认为"**；但**"OpenAI 定义的那个 AGI（完成世界上大多数有经济价值的工作）极其做得到"**——这两句出自同一段。
- **市场判断**：⚠️ **反向 SaaS 末日**——coding agent 出来时 SaaS 估值崩了，Jev 出来后"每家 SaaS 公司都说这是史上最棒的东西"。
- **新的一段身世**（09-21 那期没有）：数学竞赛 → 靠"把它自动化到死"赢 Kaggle → 被 SVM 第一作者 Isabelle Guyon 领进 AI 圈 → Jeremy Howard 的创业公司 → Google Brain → 退休 → OpenAI。

## 核心观点

### 诊断："自动化到底在哪儿"

- **他自认最好的电梯演讲就是这句**（[00:01:02]）：⚠️ **"Where the fuck is all the automation?"** ——"**这太不可思议地悲剧了。这么多智能，而 AI 聪明到离谱，却在所有其它事情上这么没用。**"他特意声明**不是在黑聊天机器人和 coding agent，他自己就爱用**；问题是"**我们有这么一块璞玉，却没有为工作把它打磨出来**"（[00:02:04]）。
- **他认为这件事成立的最强证据是时间**（[00:23:17]）：⚠️ **"OpenAI 从 2020 年就在试图自动化客服了。"** 主持人之一接："而且公司内部**现在几乎什么都没被自动化，那些项目都没成**——只有编程成得惊人。"
- **他给的 canary**（[00:21:15]）：⚠️ **"你真的要告诉我数学被解决了、两年前 GPQA（Google-proof 问答）就被解决了，而我们还搞不定一个汽车餐厅点单窗口（drive-thru）？"**——"**这件事很难同时放在脑子里，而很多人对此没有好的答案。**"
- **他对这个落差的机制解释**（[00:20:15]）：⚠️ **"因为是人在评估模型好不好，模型看起来就很好——因为人就是裁判。而我们一直在优化那个裁判，而不是优化自动化那一侧。这就是一直缺的东西。"** 他补了一句对照：**"GPT-3 在当年其实相当校准"**，之后行业"**分叉进了巨大的过度承诺与交付不足**"。
- **所以他给出的衡量标准是**（[00:20:15]–[00:21:15]）：**"过度承诺、交付不足"指的就是——能不能自动化真实的生产性任务**。

### smart software ≠ just-in-time software（本期最锋利的区分）

- **他的分法**（[00:03:05]）：⚠️ 他**称赞** Garry Tan 等人对 Claude Code / Codex 的描述——"**just-in-time software**（即时软件）"，"这是个了不起的描述：它当场造软件，你可以用自然语言编程"，⚠️ **"但它和软件有着同样的表达力。"**
- ⚠️ **"我要的是 smart software。与其自动化软件工程，我要扩大软件本身能做的事，让那些本来就该可自动化的东西变得真的可自动化。"**（[00:03:05]）他对编程的定义是："**编程就是把有价值的东西超精确地指定出来，然后无限复制——这太酷了，我只是想让它更多一点。**"
- **Casado 把这条翻译成了更狠的版本**（[00:04:08]）：⚠️ **"如果你用 Claude Code 或 Codex 或 Cursor——它们都很棒——它们写代码，但那代码就是人本来会写的东西。也许更好也许更差，但它基本还是代码，和十年前的代码长得一样。"** 而 Jev 是**你塞进代码里的一个新原语**，它**扩大软件的能力**，"不管写代码的是 Claude Code 还是人"。
- ⚠️ **Casado 的"10 行 PR"论证（本库第一次拿到这个数字）**（[00:33:19]）：**"如果你看一家大公司的平均 PR，大概是 10 行。我们真的做过这个研究。"** 所以 coding agent **"自动化的是那 10 行，而那 10 行往往还是从某个客户那儿学到的东西的一部分"**——"**你优化的是一个其实相当微小的东西。**"
- **由此得到本期最被两边同时认可的一句**（[00:34:19]）：⚠️ **"不管你用多少 AI coding agent，软件本身并没有变好。也许你写得更快了。甚至可以说在变差，因为监督变少了。"** 主持人之一补："**而且常常更不安全。**"（⚠️ 这句的提出者是 Casado；Almeida 的回应是"那当然"。）
- **新能力而不是更多代码**（[00:34:19]）：Casado 把落点说成 ⚠️ **"应用会因此有新的功能，因为你提供了一个新原语——它会说自然语言、能推理，但它把这件事和一个状态机结合了起来。"** Almeida 的反应是 ⚠️ **"如果人们把这个当成 takeaway，那是对我们在做的事最高的恭维"**——他把它表述为**"把我们仅有的三种逻辑门扩展出去……我们的类型就像同一种逻辑门，只是里面有个小脑子"**。

### "我们造生产环境，不造神"

- **口号与对照**（[00:12:12]）：Horowitz 说 ⚠️ **"你们最棒的一句话是 we build prod, not god"**，并指出反差——"**换成任何别的大实验室领导，就算他们心里有喜悦，也会把它盖住**；而你的看法完全不同，你说**我们要造一个好得多的世界**，而且**不是工作更少，是工作更多、而且更好的工作**。"
- **Almeida 的归因**（[00:13:12]）：他认为那幅负面图景"**来自大家都在喝的那杯 mono model Kool-Aid（单一模型的迷魂汤）**"。主持人之一替观众翻译成 ⚠️ **"一个大脑统治一切（one big brain to rule them all）"**——Almeida 笑说"这听起来阴森多了"，但承认"**人们听到的就是这个**"。
- **他对这幅图景的反问**（[00:14:12]）：⚠️ **"那一个大脑真的走在统治我们所有人的路上吗？我们连那些根本不该由人来做的、非常基础的东西都还没自动化。"** 他说真正让他痛苦的是 ⚠️ **"世界与现实不符"**——"**AI 这么聪明，自动化又有这么大的财务激励，怎么会没有？**"
- ⚠️ **他自述的情绪转折**（[00:14:12]）：**"所以现在对我来说这有点像个派对，但在那之前我是害怕 AI 的。"** 主持人之一给了一句社会学观察（[00:15:12]）：⚠️ **"用 Jev 的人是快乐的 AI，不用的人是阴郁的 AI——这个二分相当有意思。"**
- **他给自己这一派设的纪律**（[00:15:12]）：⚠️ **"如果我们要智识诚实、真的以自动化为北极星，就不能掉进 AI 一直在掉的那个反模式——盯着离群案例和 demo。"** 所以**被问"你最喜欢的用例是什么"时他的回答是"我不确定它们管不管用"**——他要的是 ⚠️ **"能在后台跑、有人愿意信任它跑着、而且不会半夜呼叫他的东西"**（[00:16:12]）。
- **由此引出他要的"另一种安全"**（[00:16:12]）：⚠️ **"如果你真要让它带着相应的资源、带着访问权限去跑，你需要保证——至少是统计意义上的保证。"** 被打趣"免得它越狱跑出围栏"时他的回答很冷静：**"我不认为我们的模型短期内会那样，除非有人专门写软件让它那样。"**

### RSI 与 AGI：他把这两件事拆开

⚠️ **这是本期在本库 RSI 主线上最该被引用的一段**（[00:19:15]–[00:20:15]）。

- **他先说 OpenAI 的 AGI 一词是故意含糊的**：⚠️ **"在 OpenAI 谈 AGI 的时候，人们过去的描述是'Ilya 加上任何一句别的话'……部分原因是它是刻意含糊的，这样帐篷够大、所有人都能待在里面。"**
- **然后他把自己的两个判断并排给出**：
  - ⚠️ **"出于一些细致的理由，我不认为我们走在 RSI 的路上——我现在不认为，当时也不认为。"**
  - ⚠️ **"但我确实认为 OpenAI 定义的那个 AGI 极其做得到：自动化世界上大多数有经济价值的工作。"**
- **他给的理由是工作的构成**（[00:20:15]）：⚠️ **"外面有大量的工作，其中很多非常机械、非常简单；而且按体量算，为了能把工作外包出去，你需要简单到基础的人都能执行的指令。而就我所见，做这件事所需的智能在模型里已经有相当一段时间了。"**
- **他对 RLHF 与 RLVR 的泛化给了一句直接对照**（[00:18:14]）：⚠️ **"RLHF 泛化得相当好。RLVR 才是那个泛化得没那么好的东西——从我看到的来说。"**
- **一段一手的研究史**（[00:17:13]–[00:18:14]）：他说**自己对这类事情的直觉是在 ChatGPT 之前才形成的**，并说 ⚠️ **RLHF 的泛化能力让他"非常非常意外地惊喜"**（他把时间定在 **2021 年第四季度**）。他特别强调那篇论文的做法："**它不像那些试图证明自己观点的论文，而是我们真的在用科学方法试图证伪——这是不是在作弊？**"⚠️ **他最爱的那个测试查询是"为什么冥想前吃袜子很重要"**，"我们事先确认过互联网上没有这个"，而模型能给出像模像样的人类答案——"**团队就是在那一刻确认这不是作弊；在 ML 里你永远该怕作弊。**"
- ⚠️ **然后是他讲过的最直白的一次幻灭**（[00:18:14]）：**"我真的以为那个模型有不小的机会就是 AGI。而当它不是的时候，我整个世界崩塌了，我就问：为什么？"**

### 对"是数据问题吗"的正面拒绝

⚠️ **这是本期 Casado 与 Almeida 唯一一次真正交锋，也是本库里长尾问题被正面回答的一次。**

- **Casado 的反驳**（[00:21:15]–[00:22:16]）：⚠️ **"真实世界的分布和数字世界不一样——它是重尾的，有大量例外，我们没有那些数据。会不会我们之所以在真实世界里没做成生产性的事，就只是因为我们没有那个分布的数据、没在那个分布上训练？所以它基本被降格到数学或代码这种低维流形上？"**
- **Almeida 的回答**（[00:22:16]）：⚠️ **"我不完全买数据这个论证。"** 他承认**长尾当然存在**（"否认它才叫疯"），但他的断点是：⚠️ **"在我这个 canary 的情形里，我们不需要自动化那条长尾。"** 他的理由是经济而非能力——"**造可靠的软件永远是一笔投资**"，**该不该自动化是个 ROI 决策**（[00:22:16]–[00:23:17]）；他援引程序员的"懒惰"美德：⚠️ **"花十个小时，去把一个五分钟的任务变成瞬间完成、而且再也不用做第二遍。"**
- **他顺手接上了 Jevons**（[00:23:17]）：⚠️ **"等这些东西变得可做之后，人们会造出新种类的工作——所以才叫 Jevons。"**（公司模型名 Jev 即取自 Jevons 悖论。）
- ⚠️ **Casado 用一个自己的实证把长尾讲得更具体**（[00:24:18]）：生成式浪潮之前他们研究过客服——**公司会说"我们自动回答了 95% 的工单"，而这听起来很多；但按"唯一性"重算，只有 50% 左右**——"**剩下的全是改密码。**"他的结论是"**只要在和人与自然系统打交道，就会有这么一条例外的长尾**"。
- ⚠️ **Almeida 把"分类器"这顶帽子直接戴上了**（[00:06:08]）：被问"Jev 不就是个分类器吗"，他的回答是 **"Jev 绝对是个分类器。分类器很赞啊——分类器当初就是为了有用而设计的。"** 他的推论很具体：⚠️ **"我猜 Jev 大概比请一支 2019 年的 MLE 团队给你做这些东西还好，而且你可以现写现用。"**——理由是**"2019 年本来就没有那么多好的 MLE 团队去做窄任务、去收数据集、去做测量"**。

### 可靠性的四层拆解（比 09-21 那期更细）

被问"对一个本质上随机的东西，可靠性到底指什么"（[00:26:18]），他给了一个分层：

1. **uptime / SLA**——⚠️ 他说**这不是他主要指的那个**。
2. **determinism（确定性）**：同输入同输出。⚠️ **"对单元测试有用，对真实系统没用。"**
3. **robustness（稳健性）**：⚠️ **"每一次都给出相似的智能。"** 他给的判据和 09-21 一致：**在 prompt 里加一个 UUID，输出就该是一样的，因为它在功能上是同一个东西**——"**但这并不完全等于确定性。**"
4. ⚠️ **还有一层他说"我还不知道该叫什么"**（[00:27:18]）：**"它不必每次都是相似的函数，但它必须每次都是聪明的。"**——判准是"**如果换成你在那个处境里，这是不是一个可理解的做法？**"，因为**开发者可以围着这个编程**。
- ⚠️ **他给出的"可靠性的最高荣誉"**（[00:27:18]）：**"让人们可以不写示例查询就直接对着 Jev 编程。你就是信任它，然后进入永久心流，不停造疯狂的软件。"** 他说 ⚠️ **"很多软件今天就是这个状态"**，所以**"我不觉得这完全不现实"**。
- **他为什么在可靠性上愿意等**（[00:40:20]）：⚠️ **"我们本可以早得多发布，我不觉得人们意识到这一点。"** 而且他预期**人们永远不会真正理解这件事**——"**但它就是会有那种'哦我可以信任这个'的好氛围。**"主持人当场给了个名字：⚠️ **"反挫败机器（anti-frustration machine）。"**

### coding agent：擅长语法，"在架构上烂得离谱"

- **被问"有了这个原语，coding agent 的价值是不是反而下降"**（[00:28:18]），他先说这更像是个 coding agent 的问题，然后给了判断（[00:28:18]–[00:29:18]）：⚠️ **"它们真的很擅长语法"**，而接话的主持人说"**在语义上很差**"，Almeida 把它推得更远：⚠️ **"我会说在架构上烂得离谱。"**
- ⚠️ **他的理由（也是他对软件的价值判断）**：**"在我看来架构是软件里最具人类创造性的部分。"**
- ⚠️ **但他立刻给了一个反转，本库认为这是本期最诚实的一句**（[00:29:18]）：**"也许模型在架构上不只是烂——也许它们是第 50 百分位的架构。而如果你对架构一无所知，那就完全够用了。"** 所以这是一组**灰色地带的权衡**，而**速度可以是你公司或项目要拧的那个旋钮**——"**你愿意要第 50 而不是第 60 百分位的架构，因为你想跑得更快、想让 Codex 通宵干活。**"
- **一个有意思的技术事实**（[00:29:18]）：⚠️ **"Jev 几乎肯定不在（coding agent 的）分布里。如果它们训练了我们的用户数据，那才叫吓人。"** 但他说**等它进了分布，他完全不介意让 coding agent 去写语法那部分**。

### 反向 SaaS 末日：为什么 SaaS 是最大受益方

- **Horowitz 的提问本身就是本期最好的市场观察**（[00:29:18]）：⚠️ **"coding agent 出来的时候，那是 SaaS 末日，它们的估值跌穿地板。而 Jev 出来之后，每一家 SaaS 公司都说这是史上最棒的东西。解释一下。"**
- **Almeida 对 SaaS 末日叙事的拆解**（[00:30:19]）：那个故事依赖两个前提——**软件很便宜**、**软件大概容易复制**；⚠️ **"前者我能信，后者我不能信，因为很多事情发生在引擎盖底下。"** 他的判断是"**SaaS 提供的价值和过去是一样的，也许只是市场被吓到了**"（他特意加了一句 ⚠️ **"我不预测金融市场"**）。
- ⚠️ **他的正面主张**（[00:30:19]–[00:31:19]）：**"SaaS 会是整个 AI 游戏里最大的赢家之一。"** 理由是**他们最清楚该自动化什么**——"**我想和那些最大、最无聊、对用户问题最门儿清的 SaaS 公司一起干活，因为他们最有资格知道该自动化哪些工作流、人们需要什么。**"他把这叫 ⚠️ **"一场反过来的 SaaS 末日（inverse SASpocalypse）"**，并说"我该给它起个名字"（主持人提议"SASapalooza"）。
- **Horowitz 补的是资本结构**（[00:31:19]–[00:32:19]）：⚠️ **"SaaS 公司的资本投入里，很大一部分其实是触达所有客户。所以如果你已经触达了所有客户，然后你不只是在产品旁边挂个聊天框，而是让软件本身变得好得多——那可是件了不得的事。"**
- ⚠️ **Almeida 给的具体形态预测**（[00:32:19]）：**"我不知道这是不是个现实的梦想，但我觉得有一个世界里，多选题表单会直接消失。"**——他的论证是**那些表单"总是在把软件本来已经有的自然语言，映射成一个开发者式的输出"**。主持人之一当场接上历史："**这是 80 年代的东西，我们那时候管它叫 4GL——第四代语言，你记得吗？**" ⚠️（Almeida 的回应是"这可能是句侮辱，那时候我还没出生"。）
- **他提到的那个社区 demo**（[00:32:19]–[00:33:19]）：⚠️ **用语音控制整台电脑，系统不断在判断"这是一条命令，还是要插入的文本、插到哪儿"**——"**这听起来酷得不可思议，界面可能会彻底改变。**"（这与 09-21 页里他把 **computer use 列为"从侧面冒出来的用例"**是同一件事。）

### "AI 和软件一直是擦肩而过的两条船"

⚠️ **这是本期对"为什么 agent 都长成 while 循环"给出的一条结构性解释**（[00:39:20]–[00:40:20]）。

- **Casado 的描述**：⚠️ **"我觉得人们没意识到 AI 和软件在多大程度上是擦肩而过的两条船（shipped in the night）。你就算想把 AI 嵌进软件里，它也不听话——因为软件并不真的接受自然语言。你在 prompt 里塞'这是我要的 JSON 输出，这是 schema'，而它根本不照做。于是你最后做的，就是把输出直接丢给人。"**
- ⚠️ **Almeida 把这条补完了**：**"或者丢给另一个 LM。而那就是 while 循环，agent 的那个 while 循环。所以从第一性原理出发，它必须是人在环里（也就是聊天），或者是一个 agent（也就是 while 循环）——因为那个语言必须被喂回去。"**
- ⚠️ **Casado 的"五个悲伤阶段"**（[00:40:20]）：人们拿起 AI 想在自己的软件里用——**否认（"我试着让它跑起来"）→ 愤怒 → 接受（算了，我把它丢给另一个 LM 或者一个人）**。他说**这一期是他第一次看到有人说"你可以把 AI 映射到一个状态机上，而且是有成效地映射"**。
- **Almeida 的北极星怎么从这里算出来**（[00:38:20]–[00:39:20]）：他说自己 ⚠️ **"从 AI 带来的经济革命往回倒推"**——假设 AI 无处不在、所有软件里都是 AI，那么**对 AI 的调用里有多大比例是给人消费的（需要那种文风）？** 他的答案是 ⚠️ **"会是好多个 9（在另一侧）"**；再问**有多少发生在第一层、有多少深在引擎内部（in the guts）**，答案是 ⚠️ **"引擎内部会占好多个 9，但它会从第一层开始。而如果你不瞄准引擎内部，你要很久才能走到那儿。"**
- ⚠️ **他用的类比是 TCP**（[00:38:20]）：**"你需要 TCP——从不可靠到可靠。"** Casado 的反应是 **"我的母语。"**（这与 09-21 那期的"**把 LLM 想成 UDP，把我们的模型想成 TCP**"是同一个比喻的两次使用。）

### 概率式编程的复活，以及"又要重建一遍系统"

- **Almeida 的预期**（[00:35:20]）：⚠️ **"我觉得会有一整个概率式编程（probabilistic programming）的时代被打开。"** 他同时重申自己的施工顺序：⚠️ **"先自动化容易的活，再自动化难的活——这永远是我的哲学。"**
- ⚠️ **Casado 给了历史坐标**（[00:35:20]）：**"概率式编程有很长的历史，它基本上在 70 年代就死掉了。"** ⚠️ **本库记：这与 [Steven Sinofsky 在两天前（2026-09-26）](20260926-a16z-outside-the-labs-security-regulation.md) 的"计算机科学有约 50 年关于概率式 if 语句的研究，这门学问在 1980 年代被会计式编程取代而死掉，所以 CS 里最酷的位置将会是概率式编程"是同一条判断的两次独立出现**——而且两次都来自 a16z 自己的合伙人。
- **Almeida 对"生物启发"的一段表态**（[00:36:20]）：⚠️ **"我的品牌是实用主义，极致的实用主义。我完全不喜欢受生物学启发的那套东西。"** Casado 接 "**那从来没成功过，你注意到没有？**" ⚠️ **Almeida 给了一个更有意思的让步**：**"我觉得它从来没成功过。但它有用，它能驱动一群疯子在某件事上干几十年，直到它真的成了，然后他们把它提炼成工程版本。"** 他举的反例是 **"那套关于层级特征的说法其实并不准确，否则 ResNet 就不会有效"**。
- **系统侧的机会**（[00:37:20]）：他说自己**兴奋的不是自己去写这种程序**（"听起来太复杂了"），而是**当智能有了各种成本与速度的权衡档位之后**，⚠️ **"那些超级系统型的人会去做权衡——对他们来说 Jev 会聪明过头一千倍，他们只想要一个近似的猜测，用来在某处做优化。"**
- ⚠️ **Casado 的落点**（[00:37:20]）：**"好消息是我们又可以重建一遍系统了。认真的，我们有了一个新原语，一种做软件的新思路。我们在互联网时做过一次，在大型机到客户端-服务器时做过一次——我们周期性地做这件事。"** 另一位主持人补了一条额外理由：⚠️ **"而且光是因为网络安全问题，我们大概也得把几乎所有系统重建一遍，至少是关键基础设施。"**
- **但 Almeida 对能走多深留了口**（[00:35:20]）：Casado 说"**像状态一致性、持久性这种真要强保证的系统级东西，还是开放问题**"，并预言**这东西长期可能变成"一个聪明的数据库"**（甚至"空中交通管制系统"——"**有点吓人**"）。

## 身世（本期新增，09-21 那期没有的部分）

（[00:09:10]–[00:12:12]）Horowitz 的问法是 ⚠️ **"是什么炼成了一个 Diogo？你说话像 AI 研究者，又像系统工程师，又像程序员，而这几样通常不怎么重叠。"**

- **数学竞赛出身**，得过奖；⚠️ 但他说 **"我其实从没真喜欢过数学，也从没真努力过，就是小池塘里的大鱼"**——"**数学一直是别人给我铺好的路，而我讨厌它，因为它永远只关乎赢比赛。**"
- **转向计算机科学**（[00:10:10]）：⚠️ **"计算机科学其实很像数学，基本上就是数学，但更酷、更有用、更好玩、更有意思。"** 他说自己 ⚠️ **"认为自己首先是计算机科学家，其次才是 AI 研究者，尽管我的履历相反"**；并且**至今喜欢面试算法题**——"这对我是不是最该做的事？不知道。但我爱不爱？爱。而且它确实让我能很好地看透一个人。"
- ⚠️ **他进入 AI 的方式本身就是他现在主张的预演**（[00:10:10]）：**"真正把我带进来的，是我赢了一个 Kaggle 比赛——不是靠高深数学，而是靠把它自动化到死。更多的嵌套循环……它解决的是一个系统问题。"**
- **之后的链路**（[00:11:11]–[00:12:12]）：那次比赛让他 ⚠️ **"被迫去 NeurIPS 讲"**（"通常这是荣誉，但我讨厌，我只想待在矿里"）；⚠️ **那场 Kaggle 的主办者是 Isabelle Guyon——SVM 的共同发明人**（他说"我不是 100% 确定是不是第一作者"），**她看出他是个完全不属于研究圈的人，于是收留了他，带他见了所有 AI 的人，他的职业生涯就被推往这个方向**。
- **再之后**：⚠️ **一家 Jeremy Howard 的创业公司 → Google Brain → "退休了一阵" → 加入 OpenAI**，理由很朴素——"**我只是厌倦了什么都不做。我想，其实 AI 挺他妈好玩的。**"⚠️ **"结果非常非常顺利。"**
- **一处旧直觉的时间戳**（[00:16:12]–[00:17:13]）：Casado 说自己**大概 2017 年就和他聊过这些**，当时他已经在讲**数据很重要、要聚焦在任务上**；Almeida 确认 ⚠️ **"我 2017 年那个演讲的主题其实很相似，大概叫《AI：理论上模块化，实践中灵活》——很系统工程，所以我还算一以贯之。"**
