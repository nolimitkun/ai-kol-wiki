## 概要

这是本库**第一份"传统实体企业把自己整个重建成 agent 公司"的一手内部叙述**——而且不是试点、不是 pilot，是**已经跑到 96% 交互与 95% 交易由 agent 完成**的规模。Kavak 是拉美的二手车市场（买车、翻新、卖车、放贷），为此还自建了金融科技、物流和一套 Carfax——嘉宾说这些基础设施在拉美"根本不存在"，只能垂直自建（[00:02:06]–[00:03:06]）。

本库此前关于"AI 落地"的材料几乎全部来自**卖方**——[Decagon](../people/decagon-founders.md)、[Netic](../people/melisa-tokmak.md)、[Lassie](../people/lassie-founders.md)、[Retell AI](../people/todd-li.md) 都是把 agent 卖给企业的公司。**这一期是买方兼自建方**，而且是**非科技行业、拉美市场、有大量物理作业（800 名技师）**的公司。这个位置本身就是本库缺的。

本期最该被单独引用的五条：

1. ⚠️ **"每个客户一个 agent"，不是"每个任务一个 agent"**——每个客户被分配一个**带独立虚拟机**的长期 agent，记住这个客户多年的交互、自己定长期目标（最大化 LTV），每天实例化 **10 万–20 万个**，"有时工作 3 分钟，有时 8 小时，有时 3 天，然后给下一个任务定个闹钟再去睡觉"（[00:08:12]、[00:29:28]）。
2. ⚠️ **Opus 4.5 出来之后，他们把跑了两年、已经带来盈利的多 agent 系统全部推倒重来**——理由是"**智能已经不需要那个图和多 agent 的格架与 harness 了，因为它会约束这个级别的智能**"（[00:28:27]–[00:29:28]）。这是本库**第一条"模型进步导致已盈利架构被主动作废"的一手记录**。
3. ⚠️ **他们让 agent 当了一个城市的 CEO**——在墨西哥 Cuernavaca 圈出一块业务交给 agent，第一个月目标是利润翻倍，**没达到，做到了 1.5 倍**（[00:16:18]–[00:17:19]）。本库对"AI 能不能做管理岗"此前只有推测，这是第一个带数字的实施样本。
4. ⚠️ **"token 的三个层级"**——一套用来判断 AI 支出是否真在产生回报的框架，落点是"**不只是采用率的问题**"（[00:26:26]–[00:27:26]）。这是本库 [token 经济学](../topics/ai-business-and-value-capture.md) 条线里第一个**由买方自己提出的分级度量**。
5. **对"为什么大公司做不到"的历史论证**：电力技术在 1879–1881 年就齐了，福特的流水线**本可以早 40 年建成**；当时的人只是把煤机换成电机、保留四层楼加传动轴与皮带的老厂房，"**是的，那能带来收益，但只有 6% 的效率提升**"——要拿到 3 倍，必须把工厂拆掉、在平地上重建（[00:32:28]–[00:34:28]）。

## 核心观点

### 一、架构：一个客户一个 agent，一个 agent 一台虚拟机

- **他们问自己的问题**（[00:03:06]）：**"如果用 2035 年 Fable 10 或 GPT 10 级别的智能，我们会怎么建 Kavak？"** 答案与他们已经建成的公司"非常不一样"，所以就照着那个答案重建。
- **客户进来时发生什么**（[00:03:06]–[00:04:07]）：为这个客户**生成一个专属 agent，带自己的虚拟机**；它记得这个客户多年来的交互——访问过网页的哪些地方、两年前打过什么电话——然后**自己想出策略、设定一个最大化这个客户终身价值的长期目标**。
- ⚠️ **他明确把这条与业界主流做法对立起来**："**人们还在用专家式的多 agent 系统在建**，而我们醒悟得太晚才发现，**有硬目标（hard goals）的长期运行 agent、而不是工作流**，才能最大化客户满意度。"（[00:04:07]）
- **规模**（[00:08:12]）：**96% 的交互、95% 的交易完全由 agent 处理**，"没有人类在里面"；只有取车时会见到一个人递钥匙。
- ⚠️ **一处自报数字的内部不一致，照录不裁决**：片头字幕说"每天有 **10 万到 20 万** 个 agent 被实例化"（[00:00:00]），正文 [00:08:12] 说"每天 **10 万** 个 agent 被实例化"，[00:12:16] 又提到"**其他 20 万个 agent** 会从这个错误里学到"。本库并列记录，不取其一。

**推倒重来那一段（[00:28:27]–[00:29:28]）值得完整引用**，因为它是本页最硬的一条：

> "我们去年 12 月还有几万个这样的 agent 在规模化地运行业务。**然后 Opus 4.5 出来了。**我意识到这已经不是对的范式了——智能已经不需要那个图、那套多 agent 的格架和 harness 了，**因为它会约束这个级别的智能**。所以我们决定**把我们建了两年、正在工作、带我们走到盈利、带来惊人增长的东西全部摧毁**，从头开始建一个我们认为足够健壮、可扩展、并且能利用递归自我改进的 harness。"

新形态是：**一台虚拟机 + 一个 agent + 记忆 + evals + 一个能访问公司里每个工具和每个 API 的 CLI + 一个长期目标**（[00:29:28]）。

- ⚠️ **他对 RSI 的重定向，是本库这条线里的一个新落点**（[00:30:28]）："人们现在都痴迷于 RSI，这会改进模型。但**过去四千年里，人类的经济价值是由组织交付的，不是由个人交付的**。所以你想要自我改进、想放进那个循环里的，是**能交付更多经济价值的那个组织**。"——他称之为 **the self-improving organization**。

### 二、三个必须同时发生的决策

（[00:05:07]–[00:07:09]）他把"为什么大部分公司卡住"归结为只做了第一步：

1. ⚠️ **不能保留原有结构**："第一反应是'好，我们采用 AI'，然后你**原封不动地保留你的结构**，只是把 ChatGPT 或 Claude 发给团队——**于是没有任何效率提升，你的客户还是那些问题，什么都没发生**。"必须围绕 agent 和**未来的能力**重新设计整个公司，这意味着**重建大部分 API、重建你的系统**让 agent 能用它们来干活。
2. **超人 agent 这个赌注**：目标是"**在每一个重要维度上——转化率、终身价值、客户体验——我们的 agent 都要胜过我们雇过的最好的人**"，并且**把它们放到最难的问题前面**。教它们的唯一方法是"把它们放出去、放到客户面前、拿到那些数据、拿到那些 eval，然后训练你的 agent"。
3. **换掉衡量公司成功的方式**：从**交易型公司**（买了几台车、卖了几台车、要买多少刹车片）换成**关系型公司**——"我数据库里有 **1000 万客户**，其中大部分都分配了一个以最大化其终身价值为任务的 agent"。他给的量级：**只要激活这个客户基数的 1%，就是几亿美元**（[00:06:08]–[00:07:09]）。

### 三、Evals 是刹车，不是事后补的东西

这一节是本期对 [评估与 Benchmark](../topics/evaluation-and-benchmarks.md) 最有用的部分（[00:08:12]–[00:10:13]）。

- **他的比喻**："我喜欢跑得极快，**但要跑得快你得有刹车**。想象一辆车——**只有刹车对，你才会去踩油门**。我见过很多公司在这件事上搞反了：他们**因为没有对的刹车所以试图慢慢来**。我反过来想：**我们能跑多快？取决于我们 evals 的质量。**"
- ⚠️ **一条可直接引用的经验法则**：**"我们花在建 eval 上的工程师时间、token 和钱，和花在建 agent 上的大致一样多。"**（[00:09:12]）
- **测什么**：**第一位是业务本身的结果**——客户高不高兴、会不会买车、贷款批没批下来、**转化了没有**。"**大多数东西就是在这里崩掉的。**"
- ⚠️ **他点名批评的反面做法**："我看到公司在测**通话次数、通话分钟数**这类**表面 KPI**——它们给你一些信息，但**并不真的有用**。重要的是这个客户转化了吗？给客户带来价值了吗？过一段时间客户还愿意再来吗？"
- **反馈回路**：agent 犯了错，"**它学到了，而第二天不只是它、另外 20 万个 agent 都会从那个错误里学到**"（[00:12:16]）。

### 四、agent 真的在卖东西，而且是在做受监管的金融业务

这是本期与本库既有材料差别最大的一条——**本库此前所有 agent 落地案例的最高杠杆动作都是客服，不是销售**。

- ⚠️ **"我们从来没建过客服或客户支持 agent，我们建的是销售 agent。"**（[00:10:13]）
- **为什么难**：在拉美卖一台车，客户要在约 **20000 个 SKU** 里挑，然后走融资流程、保险、保障，还大概率要置换旧车所以得给旧车报价。2020/2021 年 Kavak 的做法是**你得在 15 件不同的事上都极其擅长、要有 15 个团队里的 15 个专家**，客户依次跟融资专家、购车顾问、收购专家、保险专家谈，拼出一个方案（[00:11:15]）。
- **他们做的事**：先让 agent 在**每一项上都强过那一项的专家**，然后合成一个"**mega expert**"放到客户面前（[00:11:15]–[00:12:16]）。
- ⚠️ **结果数字（自报）**：**NPS 与客户满意度翻了三倍**；转化率一开始比人类团队**高 50%**，现在是 **2.1 倍**（[00:12:16]）。
- **主持人给出的框架**（[00:13:16]）很值得记：世界已经接受"AI 能做客服"；下一层的怀疑是"客户不会从 AI 手里买贵东西"——**你们在证伪它**；再下一层是"端到端的受监管金融服务不可能交给 AI"——但你们在**给薄档案或无档案客户做核保、定价、以及后续服务**。
- **金融侧的数字**（[00:13:16]–[00:15:17]）：第一个金融产品是车贷。墨西哥等新兴市场通常**要两个月甚至更久**才批下来，**他们通常三分钟内批**。另外一条设计上的说明：如果客户还不起了，**可以把车退回来换一台更便宜的**，月供降下来——他把这个能力归因于**业务的垂直整合**。
- **他对"为什么关系比交易重要"的解释**：买车+贷款这种决定，客户**通常要三到四个月才拿定主意**；如果你在这个过程里认识了这个客户、并把流程做简单，"**转化率和留存率就开始爆表**"，而且能对利率、风险、贷款上限做**很深的个性化**（[00:14:17]–[00:15:17]）。

### 五、AI CEO：在一个城市里跑了六周

（[00:15:17]–[00:17:19]）这段是被问"哪个 eval 最难设计"时给出来的，回答方式很典型：他没答难点，直接给了最激进的实施。

- **提问的起点**：重新设计公司时要问"**AI 能不能做这份工作——甚至 CEO 的工作、领导层的工作？**"他的答案是"**说实话大概率能，以这个改进速度，到 2035 年它会做得到。我们说，那就现在试试。**"
- **做法**：**圈出墨西哥的一座城市 Cuernavaca**，把一个 agent 放进他们的 harness 里当 CEO，让它开始学习、开始做决策、并对这些决策做评估。
- ⚠️ **结果（自报）**：**只跑了六周**；第一个月的目标是**让 Cuernavaca 的利润翻倍**，**没达到，但做到了 1.5 倍**。他的评论："**人们本来说 CEO 是 AI 最后才会碰的岗位——不，真不是。**"
- **它是怎么做到的**（[00:17:19]）：像"一个**菲尔兹奖级别聪明**的人，钻进每一个数字、每一个客户，做出完美的预测，然后**去微观管理每天需要被执行的每一件事**"——它**直接给 Cuernavaca 的所有一线工人发消息**，给出当天的计划，并**要求他们发语音条回来汇报进度**。
- 报出的改善项：客户满意度上升、库存更好、周转更快、融资渗透率更高，"每一个 KPI 都开始改善"。

⚠️ **本库必须标注的三点**：① 全部为**自报**，无外部验证；② **六周、单城市**，样本极小且时间极短；③ "利润 1.5 倍"是**未达标**的结果，被讲述为成功，本库照录并保留这个落差。

### 六、还在招人的岗位在物理世界，而那里的形态是"耳边的助手"

- **Kavak 在墨西哥有约 800 名技师**（mechanics）。他说这里"**有大量的灵巧性和感官，极难替代**"，所以**这一侧仍在训练和雇人**（[00:17:19]–[00:18:20]）。
- **给技师配的东西用的是同一套 harness**：他用 **Ratatouille（《料理鼠王》）**打比方——"那只其实是厨师的老鼠，和一个人类协作"，他们管这个助手叫 **El Mike**（⚠️ 转录稿写作 `psychic`，疑为 sidekick，拼写未核实）。它**告诉技师怎么检查一台车、给出提示、示范做法**。
- ⚠️ **结果数字（自报）**：检查质量"再次爆表"，检查更快、维修更快、更便宜，"但最重要的是我们交付的车质量更高"——**保修（warranties）自上线以来下降了约 20–26%**（[00:18:20]–[00:19:20]）。⚠️ 原话为 "around like 20 26%"，是一个含糊的区间，本库照录不收窄。

### 七、组织：Jedi Academy、扁平化、以及"人给 agent 打工"

这是本期对 [AI 与就业](../topics/ai-and-jobs.md) 的主要贡献（[00:19:20]–[00:24:25]）。

- **他们三年前就把这个问题当真了**，结论是"**每个人的工作都会变**"。
- ⚠️ **Jedi Academy**：一个**公司内部的培训项目，从 CEO 到 AI 工程师到技师，所有人都进**。由他本人设计，并且**必须不断更新**，"因为一切变得太快"。**你没法把这些人送去斯坦福学，因为这是新东西。**
  - **产出标准很具体**：**六周之后他们把最先进的 AI agent 发布到生产环境**。"是技师、是财务的人、是工程师——**每个人都能做到**。"
  - **它的真实目的不是转岗**："也许这个人不会变成 AI 工程师——**有些人变成了**——但他们知道**怎么和这项新技术协作**。"
- ⚠️ **他给员工的话，本库照录，因为它是本页伦理上最需要被完整呈现的一段**（[00:21:22]）：
  > "各位，**没有回头路**。这就是 Kavak 要走的路，公司会变成这样。工程团队、财务团队、产品团队的变化分别是这些。**你可以选择去训练、去获得在这个新现实里胜任的技能，也可以选择离开 Kavak，如果这不适合你——但我们就是要往这走。**"
- **组织形态**（[00:22:24]）：**非常扁平的团队、非常资深的团队、高度授权**；一个团队里工程、AI、运营"什么都有"，他们**要么在建 agent、要么在为 agent 工作、要么在物理世界里面对客户**。
- ⚠️ **"为 agent 工作"是什么意思——这段是本页最反直觉的一条**（[00:23:25]–[00:24:25]）：
  - **他先否定了主流的 human-in-the-loop**：现在大规模 agent 系统的通常做法是 agent 撞墙了就把这个 case 丢给**二线支持然后忘掉它**。"**这不管用，因为你没有闭合回路，所以你没有产生能训练 agent 把这件事做得更好的数据。**"
  - **他们的做法**：agent 撞墙或要取消什么的时候，**它调用一个 API 说"我需要帮助"**——"**而另一边不是 agent 也不是软件，是一个人在帮它。**"
  - **落点**：**"如果你把这个画成组织架构图，那就是一支支人类团队，头上有一个 agent。"**（原话 "it's really human teams that have an agent"）他自己的评价是"**我拿到了更好的结果，这非常清楚，这说得通**"。
  - 他在 [00:21:22] 也直说过：**"有时 agent 是人的老板，有时人在设计 agent。"**

### 八、给其他公司领导者的两条建议

（[00:24:25]–[00:27:26]）主持人的引子是："理性上很多公司领导者直觉上理解这件事。**但在组织里部署 AI 依然很难——模型已经够好了，你知道的，这是组织问题、是心理学问题。**"

**第一条：必须自上而下。**

- "如果你只是去搞采用率，它哪儿也去不了，因为**很难产生这种品味或战略、让人们自下而上地决定该建什么不该建什么**、并且拼出对公司有用的东西。"
- ⚠️ **他点名了一种失败模式**："我见过太多公司就是'哦我们搞个 hackathon，大家提用例，我们赞助其中一些'——**那不管用。**"应该做的是"**非常清楚地说明公司三到五年后是什么样，然后开始建那个东西，并且非常垂直地引导你的部队走向它**"。
- **他的军队类比**："如果每个人都自己想战略和战术，然后跑到战场上各干各的，一支军队是不成立的。"

**第二条：⚠️ token 的三个层级（本页对 token 经济学的主要贡献）。**

他的起点是一个观察："我看到很多公司现在花巨额的钱，然后说'好，我拿到采用率了，我现在每年在 token 上花几亿美元'。那又怎样？**token 是有质量之分的。**"（[00:26:26]）

| 层级 | 定义 | 他的评价 |
|---|---|---|
| **Tier 3（最有价值）** | 你能**算出每一个具体 token 的 ROI** 的那些 agent | "**我现在能做到这件事，这对我是好消息**——因为我在增长，而且我知道每个 token 的 ROI，因为它们流向的是**在执行组织本职工作**的 agent" |
| **Tier 2** | 只能**间接衡量**的 | "我看到开发者在代码库里，我至少能间接评估这些 token 的价值，然后把那些推到生产" |
| **Tier 1（大多数公司在这）** | 人们只是在用 ChatGPT / 各种 coding 工具 | "**那些 token 后来怎么样了？我完全不知道。**" |

落点：**"所以这不只是采用率的问题。是要有非常清晰的愿景，然后衡量你花的每一个 token 都带来了那些收益，然后迭代、迭代、再迭代。"**

### 九、为什么机会在新公司：创造性破坏与"电力用了 40 年"

（[00:30:28]–[00:34:28]）本节是他对"现有公司为什么改不动"给出的历史论证，也是他对创业者的呼吁。

- **熊彼特（Joseph Schumpeter）的创造性破坏**：创新冲击经济的方式**不是**在位公司采用新技术，而是**在位公司维持原样、被带着新技术的新公司摧毁**。短期毁灭价值，长期对所有人更好。
- **为什么这次尤其如此**："**深度采用 AI 真的很难。**对今天一家大公司、尤其是上市公司的 CEO 来说，说'我要全押 AI，公司得变成这样，我要**摧毁并重建我过去 40 年建的一切**来变成 AI 原生公司'——**在规模化的公司里，有几个 CEO 会这么做？**"
- ⚠️ **电力/福特的那段完整论证（[00:32:28]–[00:34:28]），本库记为本页最好用的历史类比**：
  - **福特流水线所需的技术在 1879 和 1881 年就被开发出来了**；爱迪生在纽约、然后伦敦开始商业化电力，并发明了一台极高效的**发电机（dynamo）**。**所以福特的工厂本可以早 40 年建成，技术全都在那儿。**
  - **但人们采用电力的方式是**："我把我的工厂保持原样——**四层楼、传动轴、皮带**——我只是**把煤机换成电机**。这会带来收益吗？会，**但只有 6% 的效率。**"
  - **本该做的是**：**把那个工厂拆掉，在平地上重建**，不建在纽约市中心而是建在康涅狄格或新泽西，**围绕小型发电机和电力重新设计**——然后你才拿到那个**支撑了美国整个 20 世纪的 3 倍生产率提升**。
  - **他的落点**："**计算机时又发生了一次。今天又在发生。人们想采用它，但不愿意重新设计整个公司**，于是只是表面地采用。最后给你的是 6% 或 10% 的改进，**不是 10 倍**。这是**产业规模上的创新者窘境**又来了一次。"

### 十、给创业者的话

（[00:34:28]–[00:35:29]）"这是人类历史上最激动人心的时刻……也是**做创始人**最激动人心的时刻，因为**这是历史上第一次任何人都能用上世界上最强大的工具和智能——几乎免费，或者每月 20 美元**。"

他的建议里有一条方法论值得记：**"想象围绕 AI 的未来是什么样。它甚至不需要是指数——就画一条线性的趋势线。如果 AI 以线性速度持续变好，就为那个未来建。"**

## 与本库其它观点的关系

- ⚠️ **与 [Decagon 的"FDE 是陷阱"](20260731-a16z-decagon-enterprise-ai-apps.md) 和 [Retell AI 的"签约后要花将近一年"](20260809-uncle-moon-todd-li-retell-ai.md) 构成三点对照**：三家都在讲同一件事的不同侧面——**企业把 agent 真正跑起来到底难在哪**。Decagon 和 Retell 是**卖方**，把难度定位在集成与落地服务；**Kavak 是买方兼自建方，把难度定位在"你不肯拆掉自己的组织"**。⚠️ 这条差异很重要：**卖方的诊断天然指向"我们来帮你做"，买方的诊断指向"没人能替你做"。** 本库并列不裁决。
- ⚠️ **与 [Retell AI 的"应用层怎么对抗巨头"](20260809-uncle-moon-todd-li-retell-ai.md) 是完全不同的问题**：Retell 关心的是应用层公司在前沿实验室面前的护城河；Kavak 根本不在那条赛道上——**它是自己的用户**，价值捕获问题不存在。这是本库 [AI 商业化与价值捕获](../topics/ai-business-and-value-capture.md) 里第一个**内部化整条价值链**的样本。
- ⚠️ **"Opus 4.5 让我们推倒重来"与 [swyx 的"能力过剩"框架](20260710-latent-space-swyx-agent-labs.md) 是同一现象的两种态度**：swyx 说"每一代模型会吞掉一批自建脚手架——我们时不时做次大扫除，这很正常，**不该对代码有任何感情**"；Kavak 是这条判断在**已盈利的生产系统上**的极端执行。⚠️ 差别在代价量级：swyx 说的是脚手架，Kavak 扔掉的是**两年的、带来盈利的核心系统**。本库把它记为 swyx 那条判断迄今**成本最高的一个实例**。
- ⚠️ **"evals 是刹车"与 [Decagon 的"自建 eval 是应用层的真实门槛"](20260731-a16z-decagon-enterprise-ai-apps.md)、[Retell AI 的"评估权在买方"](20260809-uncle-moon-todd-li-retell-ai.md) 组成三段完整链条**：Decagon 说应用层必须自建 eval；Retell 说最终裁决权在客户的采购尽调；**Kavak 是那个客户，而它自己建了 eval，并且把预算配比说清楚了（eval ≈ agent，1:1）**。这是本库这条线上第一个把**投入比例**说出来的样本。
- ⚠️ **"人类团队头上有一个 agent"与 [Machina 四家机器人公司的"第四、第五象限"](20260729-all-in-machina-robotics-four-ceos.md) 方向相反但结构互补**：后者讲的是被自动化的是"本来就没人做的任务"，人的岗位没被动；Kavak 讲的是**人还在做同样的物理工作，但汇报关系反转了**——agent 调用 API 求助，人来响应。本库把它记为 [AI 与就业](../topics/ai-and-jobs.md) 的一个**新象限：岗位没变，指挥链变了**。
- **"self-improving organization"给 [AI for AI / Auto Research](../topics/ai-for-ai-and-auto-research.md) 加了一条位置**：本库此前的 RSI 材料要么是实验室宣言，要么是生产系统的单点自改进（[Decagon 的 Duet](20260731-a16z-decagon-enterprise-ai-apps.md)、[Baseten 的 GLM 自写 kernel](20260803-latent-space-baseten-inference-engineering.md)、[Simon Mo 的 RL 环境观察](20260806-a16z-simon-mo-open-source-inference.md)）。**Kavak 的版本是把自改进的对象从模型换成组织**——⚠️ 但注意这是一句**主张**，不是一个被验证的机制，证据强度低于前三条。
- **"token 三层级"与 [Elad Gil 的"投出去的 token 的回报率"](20260806-no-priors-trillion-dollar-token-budgets.md) 是同一诉求的两侧**：Elad Gil 从投资人侧提出这个指标缺失；**Kavak 从买方侧给出了一个可操作的分级**。两条应当并读。
