# DHH（David Heinemeier Hansson）

丹麦裔开发者，**Ruby on Rails** 作者（2004 年发布）、37signals CTO（Basecamp / Hey）、《Rework》《It Doesn't Have to Be Crazy at Work》等书作者、勒芒级赛车手。2024 年起"离开云"（cloud exit）并转向 Linux 桌面，2025 年夏做出 Omakub（基于 Ubuntu），同年起做 **Omarchy**（基于 Arch + Hyprland 的发行版，2026-08 发布 Quattro 版）。

**本库收录他的理由**：他是第二个"二十年手工代码手艺人在 2026 年初急转向 agentic engineering"的一手样本（第一个是 [Peter Steinberger](peter-steinberger.md)），而且他的转向有**可查的产出物**（Omarchy Quattro 三个月、100% agent 写码）与**可查的时间线**（他把分界点定在 Opus 4.5 发布那几天）。

## 立场的时间线（重要）

- **2025 夏**（Lex 第一次访谈，本库未收录）：对 AI 在编程中的角色持怀疑态度；他的自述是"我并不讨厌 AI，我讨厌当时提供给我们的那种 AI 模式"——autocomplete 与 chatbot（[Lex #501](../videos/20260826-lex-dhh-agentic-programming-omarchy.md) [00:06:10]）。
- **2025-11-24 前后**：Opus 4.5 是他的分界线，11-26 试用后"向后一靠：刚刚发生了什么？"（[00:07:13]）。
- **2026-02 底之前**：以为**所有想法都源于人类**，agent 只负责实现（[00:36:11]）。
- **2026-08**（本库收录的这期）：自称 delirious；"**我在'产出代码、选路线'这部分已经变成可选的了**"（[00:11:15]）。

## 核心观点（2026-08）

来源：[Lex #501：从手工雕琢 Ruby 到 100% agent 写码](../videos/20260826-lex-dhh-agentic-programming-omarchy.md)

- **代码之美的经济回报在快速衰减**，但带一个会过期的限定：⚠️ **token 还稀缺，所以为 agent 写可演进的架构仍有回报**（[01:00:48]–[01:02:51]）。
- **瓶颈不在实现，在人类带宽**：10x–100x 只在人直接对 agent 时出现，任何一层人类中介都会把它吃掉；多数组织真正的瓶颈是想法、视野与品味（[00:19:30]–[00:20:32]）。
- **不要过度指定**：这正是 agile 在 1990s 末的结论——"没人在拿到东西之前知道自己想要什么"，所以"尽可能含糊地先把东西变出来，然后去用它"（[00:57:46]）。他引 Boris 的说法：⚠️ Opus 5 的 system prompt 比上一代缩小约 80%（[00:55:39]）。
- **vibe coding 的定义**：让 agent 造软件而你不看实现；不该复用 "programming" 这个词，因为后者意味着对原语的理解（[00:50:31]）。他也讨厌 "agentic"（"已成营销黑话"）（[00:48:26]）。
- ⚠️ **有些问题上程序员比非程序员更差**，因为"软件就是产品管理"，而这类能力在程序员中分布极不均匀（[00:52:35]）。
- **要在已有的大型代码库上 vibe code，你得是程序员**——Basecamp 5 的教训：设计师的 PR 单看都行，合起来摧毁了架构（[00:16:29]–[00:17:29]）。
- **Linux 的历史性翻转**：配置文件、CLI、晦涩报错这些"五分钟前的缺点"恰好是 agent 需要的；因此他认为 Linux 接管桌面是**最可能的结局**，理由是可塑性而非自由或免费（[01:40:42]、[03:38:37]）。
- **开源维护此刻是史上最好的时候**：agent 的 PR 已超过中位程序员（会写 why、补注释、复查、写单测），而且**拒绝 agent 的 PR 心理成本低**（[00:31:00]–[00:33:05]）。
- **就业**：爱"造东西"的人不受威胁，爱"拼逻辑构件"的人受威胁；援引 Jevons 悖论与 ATM/柜员史，但明说"生产率提升的意思就是用更少的人做同样的事"（[01:10:59]–[01:14:02]）。⚠️ 他把当前裁员潮主要归因于**疫情期过度招聘的回吐**，AI 是方便的借口（[03:03:24]）。
- **"没有积累"**：背包旅行一年完全没碰电脑的人，回来**两周就能追上前沿**——同时在跑的实验太多、淘汰太快（[01:23:14]）。
- **AGI**：按通用定义不是，但"在这些 glimmer 里绝对看到了"（[02:57:14]）；**非确定性是特性**——"不能同时既怪它不确定、又怪它没创造力"（[04:04:24]）。
- **"现在的编程语言是英语"**："如果有一门语言比 Ruby 更美，那就是英语。"（[04:01:18]）

## 工作方式（一手记录）

- 终端优先（不用 app 版 harness）：tmux → **Herdr**（tmux + agent 完成通知）；Neovim 退化为项目浏览器与 diff 入口（[01:34:34]–[01:40:42]）。
- **4–5 台机器 × 约 3 agent ≈ 16 线程**，用 KVM 盒子 + Tailscale 把闲置 mini PC 全接上（[01:36:35]–[01:37:38]）。
- **全程打字，明确不喜欢对电脑说话**（[02:16:39]）——与 Steinberger 以语音为主恰好相反。
- **标准作业流程**：Opus 或 Fable 做活 → **一律用 Codex xHigh 复审** → 推 GitHub 后 Copilot 再查（[02:38:35]）。
- 下一步是去掉自己：Omarchy bot 定时自主处理 PR/issue，每天给他发一封邮件做最终裁决；"**human in the loop 现在就是上限**"（[02:43:46]）。

## 对模型与实验室的判断（2026-08）

- 排名：⚠️ **Fable 第一，Opus 5 第二，GPT Sol 很好**；一次 Python→Rust 整库移植的六模型横评给出了时间与美元成本（见[视频页](../videos/20260826-lex-dhh-agentic-programming-omarchy.md)的表，数字均未核实）（[02:29:06]–[02:36:30]）。
- **主力用 Claude，理由是 harness 最好**；开放权重模型走 OpenCode + Fireworks 推理（[02:39:35]–[02:40:40]）。
- 对 Anthropic 有明确保留但继续用：⚠️ 订阅不能用于第三方 harness、Claude 不读 agents.md（他的 CLAUDE.md 只放一个指针）、⚠️ 拒绝把他一篇移民文章翻成意大利语（[03:25:12]–[03:26:17]）。
- ⚠️ 他举的反讽对照：同期 Kimi K2.5（经 Fireworks）直白回答了"1989 年中国发生了什么"（[03:29:24]）。
- **Claude 系模型开箱即是好写手**（PR/commit 文案），GPT 开箱写得很糟；他现在让 agent 一律署名 "Claude on behalf of DHH"（[03:23:10]）。
- 安全：⚠️ 他认为 Fable 的发布争议源于"找攻击链能力太强"；一手代价是 37signals 技术团队面对看不到尽头的漏洞修复队列，并给出判据——**现在没在忙打补丁的团队只是瞎了**（[00:14:19]、[03:32:28]–[03:34:31]）。

## 与他人观点的交叉

- 与 [Peter Steinberger](peter-steinberger.md) 的七条逐项对照（输入方式、并行度、MCP、代码之美、商业化去向、对 Anthropic、术语）见[视频页](../videos/20260826-lex-dhh-agentic-programming-omarchy.md)。两人在"MCP 不够用"上从不同理由走到相近结论；在"是否接受大厂收购"上完全相反。
- 与[游凯超（vLLM）](you-kaichao.md)关于 **AI slop 打破开源基本假设**的判断直接相对：DHH 认为 agent 的 PR 质量已超过中位人类贡献者，是开源史上最好的时候。本库不作裁决，差异见 [开源基础设施与治理](../topics/open-source-infrastructure.md)。
- "各自造自己的 5%"与 Steinberger 的"80% 的 app 将消失"同向；但 DHH 的论证落在**个人重写**而非 agent 绕过 app。
- ⚠️ 他转述的 Shopify 内部统计（agent 审过的 PR 引发更少生产事故）是本库少见的"**agent 做 code review 的量化证据**"，但为口述、未核实（[02:28:06]）。
- Tobi Lütke（Shopify CEO）在本期被反复引用：早期布道者、brains-and-hands 架构模式、F1 就业类比、"hyperdrive"一词（[00:45:24]、[02:58:15]、[03:05:26]）。
