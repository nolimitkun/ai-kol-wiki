# Dane Knecht（Cloudflare CTO）

来源：[No Priors / Cloudflare 的 Dane Knecht](../videos/20261023-no-priors-cloudflare-knecht-weekly-log4j-agent-kitties.md)（本页全部时间戳均出自该期；它也是本库目前收录他的唯一一期）

- **现任**：**Cloudflare 首席技术官**（⚠️ 稿中 "CTR" 为自动字幕错写）。✅ **他自述 Cloudflare 的使命是"帮助建设一个更好的互联网"，"过去 15 年没有变过"**（[00:01:01]）。
- **公司规模（他自述）**：⚠️ **约 5,000 人**（[00:25:20] 主持人核对、他确认）；**开发者平台"一百多个工具"**（[00:22:18]）。
- ⚠️⚠️ **收录本页时必须前置的利益相关**：**本期在 Cloudflare 自家用户大会现场录制，他谈到的全部产品与内部做法均为发布口径的自述，本期没有一个客户数字、采用率或第三方验证。** ⚠️ **他对"买不起红队的人怎么办"的回答直接是"把站点放到 Cloudflare 后面"，本库记为推销。**

## 一、他给的频率量级与攻击者画像（本库此前缺席的两条）

- ⚠️⚠️ **频率**：**Log4j / Shellshock 这类"全员上甲板"的事件以前约一年一次，现在"一周一次"，而且"不是所有都被公开报告"**（[00:02:04]）。⚠️ **他说过去 3 到 6 个月 CVE 数量"指数级"上涨，但未给绝对数字与口径，本库记为定性描述。**
- ⚠️⚠️ **攻击者画像下移**：**"我其实觉得最近出来的一些较大的漏洞并不是国家级行为体。是……甚至是高中生。"**（[00:05:08]）✅ **机制两条**：过去打 CTF 的那批人把 agent 指向某个方向；bug bounty 的现金激励。✅ **主持人当场造词 "agent kitties"。**
- ⚠️⚠️ **他的结构性概括**：**这等于把国家级行为体早就有的那套工具"交到了大众手里"。**
- ⚠️ **本库标注：无样本、未点名任何具体事件，记为一条来自观测位（看得见全网流量）的印象，不作为归因结论。**

## 二、他对"安全吃掉工程"给的时间定界

- ⚠️ **他引自家 keynote 的比例**：**"超过 50% 的工程时间将开始花在安全上"**（[00:02:04]–[00:03:04]）。
- ✅ **而他两次主动给了同一条限定，本库认为这是他本期最可检验的判断**：**这是一段短的过渡期，"到某个时候 AI 就已经把大部分代码巡过一遍、把大部分 bug 找出来了"**；**"你会把未来 18 个月的全部安全支出都提前花掉"**，而**18 个月后"新软件的生产率大幅上升，因为所有这些资源又回到那上面去了"**（[00:07:08]–[00:08:08]）。
- ⚠️⚠️ **本库标注它与 [Greg Brockman 那条"安全支出应该大幅超过软件支出"](greg-brockman.md) 的差别**：Brockman 讲的是稳态结构（软件趋近免费 → 价值转移到可靠性），Knecht 讲的是一次性的存量清理脉冲。**两者可同时成立，但对预算的含义相反（一个说会一直高，一个说会回落）。本库并列，不判定。**
- **存量的量级**：**"我们现在是在给外面 70 年的软件打补丁。"**（[00:09:09]）

## 三、⚠️⚠️ 他对 AI 与软件安全关系的一处 against-interest 让步

> ⚠️⚠️ **"至少早期的 AI 非常啰嗦，它喜欢制造复杂度。所以就我们打的这些交道而言，AI 其实没在帮忙造更安全的东西。"**（[00:10:09]）

- ✅ **这与他自己给的第一原则（减少攻击面——"让漏洞可以存在的地方变少"）直接相撞，而他没有回避。**
- ⚠️ **他明确拒绝"模型层会解掉"这个选项**：**"它需要在所有层面上被解决"**——训练工程师、安全团队做第二双眼睛、把它建进流程（[00:11:11]）。
- ✅ **内部做法**：一份叫 **codex** 的 RFC 集合（怎么造安全的、高可用的软件），⚠️⚠️ **被"煮成某种十诫，是 agent 知道怎么遵守、并在 review 流程每一步都会用到的"**（[00:11:11]–[00:12:12]）。✅ **分工画面**：**"你有一批 agent 在外面写大量的 slop，然后在工厂更深处，你有人在做性能跑测和安全跑测。"**

## 四、agentic web：他的"messy middle"与卖方侧定价锚

- ⚠️⚠️ **诊断**：**"人和 agent 在互联网上骑着同一套轨道，而 agent 在试图解析一个给人用的 web"**（[00:13:12]）。✅ **方向是分开**：**"在 agent 和人各自所在的地方接住它们，而不是试图把两边拉到同一个地方"**；⚠️ **他对现有翻译层的评价是否定的——"这些都只是额外的 token 燃烧"**。
- ⚠️⚠️ **定价锚是 CPM**：内容站知道自己的 CPM，**"有一个世界是 agent 可以决定要不要读这个内容，然后决定要不要付那个 CPM 价"**（[00:14:12]–[00:15:13]）；需要**每秒数百万笔**的支付轨道。✅ **他对微支付的自嘲**：**"总是两年后、两年后"**，而他认为 agent 会推成。
- ✅ **x402 的来历**（[00:18:16]）：他说 Stripe 推出时他很喜欢，因为**回到了 Tim Berners-Lee 二三十年前留下的 HTTP 402**。
- ⚠️ **在位者封锁的解读是谈判，不是安全**：Amazon **"不许个人购物 agent 进来"**——**"他们在试图保住自己的一些谈判筹码"**（[00:16:15]）。✅ **预测带降温**：个人 agent 会做到无缝，**"但我不知道技术是不是已经追上了，商业模式也还没"**。

## 五、内部 agent 化：他给的几条具体数字

⚠️⚠️ **全部为自述，无效果验证**：

- **Cloudflare OS**（本期发布的内部 AI 平台）：起源是**防客户与内部数据泄漏**；⚠️⚠️ **"为什么叫 OS"的理由是组织知识传递——"需要能教 agent 什么让 Cloudflare 特别"，对人是靠 onboarding 和同事，"但对 agent 需要把那些写下来"**（[00:20:18]）。⚠️⚠️ **采用事实与通常预期相反**：**"它其实被我们的 go-to-market 团队和 G&A 团队用得比工程团队还多。"**（[00:22:18]）✅ **机制是"空白画布"问题**：**"把他们指向一个聊天界面，那对他们来说就是太多的一张白纸。"**
- **2026-05 重组**（⚠️ **Cloudflare 第一次裁员**）：✅ **他给的那个流程对照是本期最可核对的一处**——一封客户邮件从**牵动三个团队（BI 取 cohort、市场团队设计、市场运营发送）**，变成**一个工具**（PM 描述 cohort、写邮件、工具改写成 Cloudflare 语气、经理点批准）。⚠️⚠️ **他的概括**：**"我们不是从三个团队变成做这件事更快。我们变成了一个工具，让一位 PM 现在拥有他此前没有的一种超能力。"**（[00:24:18]–[00:25:20]）
- **token 治理**：⚠️⚠️ **没有排行榜，只有三级提醒——一天 300 美元给本人发邮件、500 美元给经理、1,000 美元给一位 VP**（[00:28:22]）。✅ **"我们不鼓励 token 排行榜，鼓励大家关注产出。"** ⚠️⚠️ **他对当下做法的否定**：**"我觉得我们居然还在让人类来决定每个任务用哪个模型，这件事挺蠢的"**——应被智能路由；✅ **现在的手工分工是：前沿模型规划 → 开源模型执行 → 前沿模型 review 与红队**（[00:27:21]）。
- ⚠️⚠️ **实习生**：**两年前约 200 个**（**"第一批完全 AI 原生的人——如果你把 AI 从他们手上拿走，我不认为他们还能工作"**）；⚠️⚠️ **二阶效应是"那个夏天带了实习生的那些经理，自己采用 AI 的速度更快"**；✅ **于是今年决定招 1,000 个实习生（公司 5,000 人、一年内）**（[00:29:23]–[00:30:24]）。
- **一条蛮力做法**：今年一月开的 `agents@cloudflare` 邮件别名，回复给人一个 skill file；⚠️⚠️ **"有一阵子人们真以为这全是 AI、是自动化的。其实是一群实习生在帮人写 skill file。"**（[00:32:24]）
- ⚠️⚠️ **招聘判据**：**"如果人们不在家里、在个人生活里用 AI，那是一个相当大的红旗。"**（[00:33:24]）⚠️ **主持人给的替代解释（"恐惧和怀疑"）本期未被回答，本库记为一处未处理的反驳。**

## 六、立场：红队要加到四五支，开放权重"最终必须全开放"

- ⚠️⚠️ **红队从 1 支 → "明年年底大概四到五支"**（[00:35:27]）。⚠️⚠️ **而他拒绝"先把补丁流程修好"这个替代路线，理由是危机驱动**：**"我发现这类事情变好的最好方式，是从危机里出来的"**——**"工程师天生是懒的，是好的那种懒"**，量大到做不完时他们会自动化掉。✅ **结论：重点放在发现侧。** ⚠️ **本库标注这条可被检验：若成立，平均修补时间应随红队数量上升而下降；本期无任何修补时间数字。**
- ✅ **不冻结功能**：**"如果你不出货，你就在死"**；可能牺牲的是成本优化（[00:37:29]）。
- ⚠️⚠️ **开放 vs 闭源（网安）：他站开放，理由是扩散既成事实而非权衡**——**"坏人总会找到办法拿到它，顶级公司也会有办法拿到。所以你做的只是排除掉一大群根本没有这种渠道、而大概最需要它的人。"**（[00:38:30]）⚠️ **本库标注："反正所有人都会拿到"无证据、无时间尺度，而这恰是 [Kevin Mandia](kevin-mandia.md) 一侧会否认的前提；且这条与 Cloudflare 自身的分发位置一致。**
- ⚠️ **他对"物理隔离一切"那种末日预期的回应只有三层，其中仅一层带机制**（零信任架构位移），✅ **自我定位是"我没那么末日"**；⚠️⚠️ **但"关键基础设施会倒"这个具体命题本期从头到尾没有被正面回答**（[00:06:08]）。
- ⚠️ **普惠论证**：他把"安全能不能普惠"归约到 CDN 的历史（**"Cloudflare 开始之前全世界大概 3,000 个站点有大规模 CDN，现在有数以亿计"**，自述无来源），✅ **做法是重大漏洞的防护"不只给付费客户，我们给所有人"**（[00:39:30]–[00:40:30]）。⚠️ **本库标注未被处理的不对称：缓存可以在中间层一次性提供，漏洞发现需要进到各家代码里。**

## 七、本期的标题句

> ⚠️⚠️ **"虽然 AI 成了造成这种安全末日的那个工具，它同时也是能帮我们更快解掉它的工具。所以它在这件事的两边都在。"**（[00:37:29]）
