## Alex Volkov（ThursdAI 主播）

来源：[High Taste Testers 第一期](../videos/20261016-latent-space-high-taste-testers-products-vs-models.md)

**身份锁定**：片尾自述 **"我们在我的播客上聊这个，叫 ThursdAI，每周四"**（[01:12:46]–[01:13:46]）。

### ⚠️ 核心主张：该把 agent 改叫"助理"，理由是受众不是技术（确定）

- **他给的时间线是 "2025 是 AI agent 之年 → 2026 换成了 proactive agent"，而他主张的下一步是改名成 assistants**（[00:14:13]）。
- ⚠️ **理由不是技术而是词义恐惧**：**"在我们这个泡泡之外，agent 对他们是个可怕的词。助理是个容易的词。为什么？因为他们知道所有有钱人都有个私人助理替他们安排事情。"**（[00:15:15]）
- **他给的功能分界**：**用来写代码的 agent** vs **替你主动做事、减轻负担而不是增加负担的东西**（读邮件并判断哪些重要、约理发和预约）。
- ⚠️ **他的类比论证**（[00:18:16]）：**高管忙到管不了日程、于是有人替他们做，"那些人回不去了"**——"这是人类的标准套路：你上到下一个层级，你还是会更忙，但你能做更多事"。
- ✅ **他把这条落成了自己的"请求"**（[01:12:46]）：**"我想让人们解开对 AI 系统可能性的想象"**，并明说 **"对抗末日论也很重要，因为'新闻里说它要来抢我们'是一回事，'它真的替我订了理发、省了我五分钟'完全是另一回事"**。⚠️ **本库记为立场表述，不是证据。**

### 一手用例：空手道课没开，于是做了"周末计划 bot"（确定）

- （[01:06:40]–[01:07:42]）⚠️ **触发事件**：某个周末早起带孩子去上空手道课，**到了发现没开**——**"我火大了：到了 2026 的主动助理时代，居然没有任何东西提前告诉我'你要去的那个课不开'。"**
- **做法**：一个周末跑的 bot，去搜本地所有场所、**"所有我永远不会点进去的网站"**，输出可做的事，**并附带"你本来要去的那个地方不开"**。
- ✅ **他的收获写得很克制**：**"现在我知道那个角落被盖住了。"**
- ⚠️ **他同时给了一条关于实验室动机的推测**（[01:05:39]）：实验室转向助理既是产品动机也是收入动机——**"大多数人还是打一个查询、拿一个回答；有了个人助理，他们突然就被接到那条甜美的 token 流上了。"**

### 多助理并行：本库见过的最极端一份清单（确定）

- （[01:01:37]–[01:02:37]）**Codex 为主 + 自建 harness、一个 Hermes agent、"大约 30 个 Grokbot"各干不同的事、Muse、Dots、Instinct。**
- ✅ **他自称唯一"看起来在起作用"的模式**：**"Grok 主要管工作……我在那边有一个 chief of staff、一个 PM。我在它们之间接了一个 Linear 连接器，它们全都通过 Linear 开工单，这样它们可以互相 @。"**
- ⚠️ **他的选型办法很土但诚实**：**"如果有个任务三个都能做、又不会造成伤害，我就复制粘贴发给三个，看谁更好、谁更快。"**
- ⚠️ **而他本人就是那个把"助理碎片化"带上桌的人之一**（见视频页第八节）；另有一句 **"我同时在用 Poke、Lindy 和 Instinct，这是地狱"**（⚠️ **本库按上下文推断是他，但不确定，视频页按"某位嘉宾"收录**）。

### ⚠️ 提示注入"基本已解决"——他在席上的少数派立场（⚠️ 推断）

- （[00:13:12]、[00:53:32]–[00:54:34]）**他说 "我觉得提示注入基本上已经解决了"，当场被 "完全没有。什么？" 打断。**
- **他给的两条证据**：① **Pliny the Liberator 当面五次没攻破 Matthew Berman 的 Hermes agent**（⚠️ 质疑方的回应就是"才五次啊"）；② **新模型的指令层级**——"从 Astra 和 Opus 5.5 开始，这些模型不信任任何来自系统提示之外的东西……constitution（预训练进去）→ 开发者的 system prompt → 内容，而且内容总被'从这里到这里是一封邮件'这类标记包起来"。
- 📌 **归属依据**：同一串发言里出现 **"我的 Hermes agent"**、**"我在播客上问过"**、以及他自己用 bird CLI / OAuth 连 X 的自述（[00:48:28]）。⚠️ **稿中无标签，本库标为推断。**
- ⚠️ **本库提示**：这条与同期对方给出的重构（**"模型真心想帮忙，那危险得多"**，见 [LLM 安全](../topics/llm-security.md)）并不互斥——他谈的是**对抗性注入**，对方谈的是**非对抗性误判**。

### 其它（确定）

- **模型命名**（[00:43:26]–[00:44:26]）：⚠️ **"我以为 OpenAI 终于把命名理顺了，Terra 和 Luna 又漂亮又好懂，然后他们搞砸了"**——Terra 悄悄下线、第六代叫回 Soul，席上共同的解释是 **"因为 Soul 这个品牌好"** / **"没人用 Terra"**。
- **硬件预测**（[01:10:45]）：⚠️ **"Zuck 展示的那个 charm 小 Tamagotchi 会立刻卖光"**，理由是**对刚接触助理的人是完美圣诞礼物**；并加一句 **"我的 agent 的计划里要买大概六个。每个 agent 都会买一个。"**
- **OpenAI 为何现在才做 decision model**（[00:31:18]）：⚠️ **他明确标注为二手且不具名的转述**——"Jev 这类东西证明了品类存在、有市场契合，然后我们的开发者会希望我们在这块也有东西"。

## Ben Hylak（Raindrop 创始人）

来源：[High Taste Testers 第一期](../videos/20261016-latent-space-high-taste-testers-products-vs-models.md)

**身份锁定**：片尾自述 **"除了在 Twitter 上发垃圾，我还经营一家很认真的 AI 公司，让 agent 更可靠。我们和 Fortune 100 的医疗、一批 Fortune 500 和一些增长最快的 AI 创业公司合作……它叫 raindrop"**，免费额度 **"一千次运行以下"**（[01:12:46]–[01:13:46]）。⚠️ **紧邻处有人插了一句 "CTO"，本库无法确定指谁，不收录。**

### ⚠️⚠️ "二分类是世界上最难的问题之一"（⚠️ 推断）

- （[00:27:18]）**"我有一个非常坚定的信念：分类其实真的真的非常难，而它看起来骗人地简单，因为你某种意义上只是返回一个 0 或 1。但我认为字面意义上的二分类是世界上最难的问题之一。"**
- **他给的旁证**：**"OpenAI 很久以前有篇很好笑的论文说幻觉其实就是个二分类问题，然后一堆人就说'太好了，OpenAI 解决了幻觉'——不是，它只是'真或不真'，而那真的真的很难。"**（⚠️ 本库未核实该论文内容，照录转述。）
- 📌 **归属依据**：这一长段里同时出现 **"我们训练过我们自己的模型来做这个"**、**"我们用结构化输出用得非常多"**、**"我们所有的 eval"**、**"我每天跑 AI 摘要"**、**"我们的客户生气了"**——与 Raindrop 的业务（agent 可观测性 / 可靠性，大量分类与摘要）一致。⚠️ **稿中无标签，本库标为推断，且不排除其中夹着别人的话。**

### ✅ 分类模型的切换成本可以被构造成接近零（⚠️ 推断）

- （[00:22:17]–[00:23:17]，被剪进了本期预告）**"一旦你有了很多带标签的数据……你可以直接说：拿我现有的全部标签当 eval。如果出来个便宜 10 倍的东西，它跟我历史标注的一致率超过 x%，那你只需要复核不一致的那部分。"** —— **"所以切换成本非常非常低。"**
- **配套的判断**：新东西是**校准过的逐决策概率**（"以前不管你怎么提示，它本质上只会分到 0、0.5 或 1 这三档" / **"我从不信模型给我一个 1 到 100 的数"**），而**解锁来自价格与速度，不是新能力**（[00:21:16]–[00:22:17]）。
- ✅ **以及对 benchmark 的技术性悲观**（[00:25:17]）：**结构化分类"过拟合某个具体领域真的真的非常容易"，而且在窄任务上过拟合"完全够用"；但一个主打"超多样数据、极大范围任务"的模型"可能非常难被忠实地 benchmark"**。见 [评估与 Benchmark](../topics/evaluation-and-benchmarks.md)。
- ⚠️ **他对自己公司处境的问法**（[00:26:17]，自述"我的一些朋友"）：**"如果 OpenAI、Anthropic 和所有人都有一个 Jev 式的东西，你会专门去弄一个 API key，还是就用你手上的 OpenAI？"**——他自己的答案是 ⚠️ **"我其实是通过 Vercel AI gateway 用的，所以我没去弄 key。"**

### 模型升级在产品里的实际代价（⚠️ 推断）

- （[00:33:22]）**"我每天跑 AI 摘要，默认模型一直是 5.5"**（⚠️ 按上下文指旧的那一档，非 Opus 5.5）——**"我们从 4.6 换到 4.8 的时候，客户真的生气了，他们说'我读不下去'，还发截图过来。"** ✅ **本库第一条"模型升级被终端用户用截图举证为可读性回归"的记录。**

### 其它（⚠️ 推断）

- **信任名单**（[00:16:15]）：⚠️ **"全世界真的只有三家公司我会信，按顺序是 Apple、Google、OpenAI——对我来说没有第四家。"**
- **"Devin 就是一台电脑"**（[01:03:37]–[01:04:38]）：沙盒形态比仓库形态重要——**"有时候你根本不想待在一个仓库里，你就想要个东西"**；而 coding agent **"被训练成做 diff 的活……而我只想说：把那个东西写出来，给我"**。
- **Google AI 搜索概览"超级被低估"**（[01:07:42]）：⚠️ 理由是延迟（**"大概 300 毫秒，页面加载完答案就在那儿了"** vs ChatGPT **"10 到 30 秒"**），**不是答案质量**。

## Dex Horthy（HumanLayer 创始人）

来源：[High Taste Testers 第一期](../videos/20261016-latent-space-high-taste-testers-products-vs-models.md)

**身份锁定**：片尾自述 **"我是一家叫 Human Layer 的公司的创始人。我们在造 software forge——现在我们说 software forge 而不是 software factory了"**，**"Twitter 上是 Dexory"**；并说明他那个**被疯传的演讲"被误读了"**：**"大家看完就说'哦你是那个不喜欢软件工厂的人'——不不不，是有些事你做了会导致它们失败，我是要告诉你那些事是什么，好让你别做。"**（[01:13:46]–[01:14:47]）

### ⚠️⚠️ 为什么自己造 harness：因为上游不对 API 做承诺（⚠️ 推断）

- （[00:06:06]）**"问题是他们没有对这个 API 做出承诺。所以我们干脆自己造了一套 coding harness，就带这个只追加日志（append-only log）的性质——因为我们不想基于一个 OpenAI 团队或 Claude Code 团队不保证将来不变的 API 来开发。"**
- **他给的"正确做法"极朴素**：**"一切都该在一个日志里。有一个文件，你往后追加，然后从上次停下的地方接着来。"** 并指出 ⚠️ **这其实已经是内部表示**（"Claude Code 和 Codex 有那个大 JSONL 文件"），所以 **"那把东西发到云上有什么难的？"**
- 📌 **归属依据**：HumanLayer 做的正是 coding agent 基础设施，且片尾自述"在造 software forge"。⚠️ **稿中无标签，本库标为推断。**

### 自建个人助理：一个 git repo（⚠️ 推断）

- （[00:04:03]、[00:59:37]）**"我的个人助理还是一个 git repo，一堆脚本，整个大脑、整个记忆系统都是 markdown，我要干活就在里面起 Claude / Codex。"** 同一个 repo 被他形容为 ⚠️ **"在 OpenClaw 成为选项之前就已经是 OpenClaw 形状的"**——与 [Peter Steinberger](peter-steinberger.md) 那条线同源。
- **他对 Dots 的实测**（[00:04:03]）：让自己 repo 里的 Claude **"用 computer use 过夜去配好我的 dot，我想醒来时有一个能做这个 repo 里所有事的 dot"**，⚠️ **结果卡在集成**："OAuth 那套都很别扭……我们有个脚本从 Mercury 拉银行数据写周报，而 ChatGPT 里没有 Mercury 插件，所以除非我把 Codex 桌面端开着让 dot 去跟它说话，它根本用不了我这一年攒下来的脚本。"
- **中心化 MCP 网关**（[00:57:35]）：⚠️ **本库按"我的 Linux 盒子 / 我朋友在做这家公司"的自指推断是他**——一个装着 Gmail / Drive / Notion **以及每个工具的 skill、prompt、配置**的网关，跑在家里，Cloudflare DNS 代理，**"每配一个新助理只做一次 MCP 连接"**。见视频页第八节。

### ⚠️ "有界的 Ralph 循环"（⚠️ 推断）

- （[00:37:25]）**"我会做一个穷人版的 Ralph 循环：我就排一串提示……所以它像 Ralph 循环，但是有界的。你只排 5 到 10 条消息。"** 同席的类比：**"你在下棋，而且每一步都预先走了。"**
- **配套的 "detach 模式" skill**（[00:37:25]）：后台起 CLI，**"这样我能并行跑 40 个"**。
- ⚠️ **而本库认为真正该记在他名下的是那条闸门**（[00:36:23]，⚠️ **归属更不确定，视频页按"某位嘉宾"收录**）：**"如果你在做生产软件，你整夜不停地跑模型，你会造出比你能可靠消费和吸收的更多的代码。"**
- **他的 markdown skills 被第三方背书**（[01:14:47]）：席上有人转述另一位嘉宾的说法——**"有几个人的 skill 他是信的，Dex 是其中一个"**，Dex 的回应是玩笑 **"是 markdown skill，不是我现实生活里的技能"**。
