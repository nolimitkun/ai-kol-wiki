# Ari Weinstein

OpenAI **computer use agents 的产品与工程负责人**。自述整个职业生涯都在做计算机自动化：**Apple（Shortcuts）→ 创办 Sky → 加入 OpenAI**。他自己给的那条主线是"**一直对自动化感到兴奋，因为那样你能把时间省下来、去关心比精细操作一台电脑更重要的事**"。

**本库收录他的理由**：⚠️ **他是本库第一个 computer use 方向的一手当事人**。此前本库关于 computer use 的材料全部是旁观口径——[Greg Brockman 在 a16z 把它列为方向之一](../videos/20260914-a16z-greg-brockman-agi-era.md)、[Diogo Almeida 说"软件并不真的接受自然语言"](diogo-almeida.md)、[Danielle Perszyk 的认知科学侧](danielle-perszyk.md)——**这一期第一次有人把技术路线、度量方式与当前瓶颈讲到机制层**。

## 核心观点（2026-09-30）

来源：[Latent Space / OpenAI Dev Day 现场](../videos/20260930-latent-space-openai-devday-computer-use-decisions-api.md)

### ⚠️ 他最该被引用的一句，以及它的时间坐标

- **"现在 computer use 在完成任务上大概在多数情况下已经比普通人快了"**；而"**下一个前沿是让它真正超人——像我们这种专家级电脑用户一样快或者更快**"（[00:00:00]、[00:13:13]）。他预期那一刻的后果是产品形态变化：**"我们会突然能造出实时性强得多的产品"**，而且**门槛（activation energy）降低会让人"开始默认把某些事交给 agent，而那些事我们本来习惯手动做"**（[00:13:13]–[00:14:14]）。
- ⚠️ **本库标注这条表述缺的东西**：**他没有给任务集、也没有给测量方法**。而他同一期里承认度量跑在**harness 的不同排列与配置**上、且**生产产品有按任务分别配置的额外安全检查**（[00:09:10]）——所以"比普通人快"**不是一个可复现的声明**。

### ⚠️ 技术路线：三条变化，本库认为这是他最有长期价值的贡献

（[00:08:08]、[00:10:11]–[00:12:12]）

1. ⚠️ **computer use 已经不是"一次一个动作"**："**如果你在 Codex 里手动展开它的工具调用，你会看到它实际上在写 JavaScript，交给电脑执行，有时一次执行很多个动作。**"
2. ⚠️ **多模态界面按任务切换**：**截图 / accessibility（无障碍树）/ Playwright / 直接访问 DOM** 并存。
3. **模型本身的加速。**

- ⚠️ **他指认的最大 aha moment 是"scrolling 地狱"的消失**：过去要截图—尝试—往下滚—再截图—再尝试，而现在"**语言模型可以一次看到整页或整个应用，并写出一次做多步的代码**"。
- ⚠️ **本库认为他这一期最漂亮的一条观察**（[00:12:12]）：**"当年为有无障碍需求、要用读屏软件的人发明的那套技术，对 LLM 用电脑也非常有帮助。"** 工程难点是**同时要 token 高效**——"**把所有东西 dump 出来，但也要高效地 dump，这里头有点手艺。**"
- **他指认的模型侧最大变化不是能力而是调试**（[00:07:08]）：**"以前它们能可靠地开始任务，然后就会撞上问题；现在它们非常擅长调试、重试、反思什么有用什么没用。"**
- **app shot 的机制**（[00:11:12]–[00:13:13]）：不是截图，而是**完整的 accessibility 表示 + 元数据**——"**你截一张有链接的网页图，截图里不包含链接指向哪里；你截日历的图，事件标题是被截断的。**"

### ⚠️ 瓶颈已经从模型转到网页，这条本库认为最有预测力

（[00:14:14]–[00:15:14]）

- **"我们发现随着 computer use 变快，我们越来越被单纯的操作速度卡住。比如你在 doordash.com 上自动化一个任务，很多时间其实是在等 doordash.com 自己加载。"**
- ⚠️ **而这推出了一个新的工程问题**：**"你希望在它终于加载完、和你去触发 LLM 做下一个动作之间，延迟越小越好——而这件事本身是一门统计科学。"** 事件驱动只解决一部分（JS 与浏览器导航有 load 事件），"**但还有一些类型的事件实在没法事件驱动**"。
- ⚠️ **本库的推论**：这解释了他为什么把"**超人速度**"而不是"更强能力"当下一个前沿——**在他这条路线上，下一阶段的收益会越来越多落在"等待的统计学"而不是模型能力上。**

### ⚠️ 闭合 SDLC：agent 测试自己写的软件

（[00:18:18]–[00:19:18]）**"computer use 让 agent 真的能测试它自己造出来的软件，而这件事比听起来重要得多——因为传统上你在 Codex 里造一个东西，Codex 造好了，然后你得去测它，于是你现在就是 agent 的 QA。"**

- ⚠️ **本库记这条为对 [10 行 PR](diogo-almeida.md) 那条质疑的一个结构性回应**：Almeida 说 coding agent"优化的是一个其实相当微小的东西"、而且"**不管你用多少 coding agent，软件本身并没有变好，甚至在变差，因为监督变少了**"；**Ari 这条正好是在补那个被抽走的监督环**。⚠️ **两人没有交流，本库并列不裁决**——但要注意**Ari 补的是"能跑"这一层的监督，不是 Almeida 担心的"设计质量"那一层**。

### 平台与安全

- ⚠️ **他给开发者的建议里包含一条锁定论证**（[00:17:17]）：**"如果你想自己造 computer use harness，有很多好活可以干，但它很难；而且我们是在我们自己的 computer use harness 上训模型的。所以用模型分布内（in distribution）的那一套是有优势的——速度、成本、准确率上都可能有优势。"** ⚠️ **本库标注这既是技术事实也是平台论证**，与 [Thariq 的"harness 苦涩教训"](thariq-shihipar.md) 是同一件事的两侧，详见 [LLM 操作系统](../topics/llm-os.md)。
- **安全三条**（[00:17:17]–[00:18:18]）：**可靠、在有后果的动作（如付款）前征求同意、按任务最小化可访问的网站与应用**；落点是"**我们也许走在很多人前面，所以建立信任这件事落在我们身上**"。
- ⚠️ **而他自己的用法与上面这条形成张力，本库照录**（[00:16:16]）：**"三四年前我们还害怕把 LLM 接到网上、接到我们的设备上；而现在我在让它替我配 DNS、替我付账单，真的是几万美元的东西我就直接丢给 computer use 梭哈了——还能出什么最坏的事呢。"**（原话带笑声。）**他说这句的同一段里就在讲"要先征求用户同意"，而主持人没有追这处落差。**

## 与他人观点的交叉

- **对"computer use 两年没进步"的正面反驳**（[00:06:06]）：主持人引述"一家头部 AI 播客"的这句话（⚠️ **转录稿未点名，本库不猜**），Ari 答"**他们是几个月前说的，我希望他们现在的看法不一样了，因为 computer use 已经是 180 度不同了**"。⚠️ **本库指出真正的分歧点在口径**：他给的证据几乎全在 harness 与工程层，而他自己也说"**收益有时在 harness、有时在模型**"。
- 与 [Nikunj Handa](nikunj-handa.md) 同期出场，分别对应**harness / 产品侧**与**API / 平台侧**。
- **云上 Linux 虚拟机作为 agent 的身体**（[00:04:03]）——与 [Akshat Bubna（Modal）的 agent sandbox](akshat-bubna.md)、[Thariq 讲的沙箱表面积](thariq-shihipar.md) 是同一层问题的三个位置。
