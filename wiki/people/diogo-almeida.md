# Diogo Almeida

TypeSafe 联合创始人兼 CEO（2026-09 发布首个模型 **Jev**）。此前在 OpenAI 做**指令跟随 / InstructGPT 方向**——他自述极力推动了 instruct 的部署，早期版本甚至用过他自己写、未发表的算法。约两年前离职创业（他说"更像四年的旅程"），联合创始人为 Eric 与 Sasha。

**本库收录他的理由**：这是本库第一份主张"**根本不该把模型做成给人用的东西**"的一手材料。所有其它模型侧材料都在同一条主线上（更聪明的通才、更长的推理、更好的 harness）；他主张**模型的消费者应该是代码**，并由此连带拒绝 reasoning、拒绝 API 层的 safety alignment、拒绝公开基准、拒绝身份塑造——而他对 **pacing the frontier 的反驳也建立在同一个前提上**。

## 核心观点（2026-09）

来源：[Latent Space：让代码而不是人来消费模型](../videos/20260921-latent-space-typesafe-jev-system-one-models.md)

- **一类新模型**（[00:04:04]–[00:06:05]）：预训练 LLM 的目标是"自动补全互联网"，RLHF 模型是聊天/指令跟随，而他们这类的产出**直接被代码消费**——"所以公司叫 TypeSafe"。他的叫法是 **system one 模型 / large programmable model / machine native**，⚠️ 并明确**不叫 decision model**（"system one 比那更广"）。卖点是 **intelligence per dollar**（Jev 取自 Jevons 悖论）。
- ⚠️ **RLHF 的被忽视代价是 mode dropping**（[00:07:05]–[00:10:07]）：他认为 LeCun 那张"错误随序列累积、LLM 必然失败"的图"**数学上显而易见，经验上明显不成立**"；断点在于**mode covering / 校准良好的分布不会因离群值被重罚**，而 RLHF 式模型为了长串不出错必须**极度保守**（错误易被发现，"看起来对的微妙东西"难被发现）——"**这种校准是对字符串概率分布的彻底毒害**"，所以 string 模型做决策很糟。
- **capability alignment vs safety alignment**（[00:14:09]–[00:16:09]）：前者是"做用户想要的"（对开发者极好：越可预测越不用反复测），后者是"遵循别人的指令"。后者**对第一方产品完全合理，在 API 层荒谬**——⚠️ "**refusal 是一个 type error**；如果它是后台运行的一个依赖，它拒绝了会怎样？"
- ⚠️ **"fracturing intelligence" 是他最反对的事**（[00:16:09]–[00:17:09]、[01:55:26]）：**每次让模型为某种奇怪情形过拟合，就把它的智能撕碎一点**。所以他**不在技术层放手指**（"**智能会更像数据库，而不是同事**"），连**模型身份也不训**（"要它就代表互联网认为的那样，那才能得到平滑可预测的智能"）。
- ⚠️ **反公开基准但不反测量**（[00:19:10]–[00:21:11]、[00:54:33]）："**我极端反对公开基准**"，因为智能有说不清的质感、而基准极易被刷（"当年每个实验室都有团队专门收集长得像 MMLU 的数据"）。替代方案是"**vibes 与信任，直到你把它放进自己的工作流去测**"；他们有内部 eval，但强调**不自欺的纪律**。代价是去年融资时"没人信我们，他们只想要基准分"。
- ⚠️ **robustness > determinism**（[00:42:27]–[00:44:28]）：determinism（同输入同输出）"对单元测试有点意思但是错的北极星"；要的是**相似输入给出相似输出**，测法是**在 prompt 里塞 UUID/nonce 看输出是否稳定**。
- **版本承诺**（[00:48:31]–[00:50:32]）：⚠️ **"我们部署之后不会改模型"**（第一方产品可以随便改，API 不行），但**不承诺 LTS**——会比惯例快得多地发新模型；可能临时把 Jev 1.13.0 做成 LTS，因为"切碎自己的 fleet 对所有人都是坏氛围"。
- **"bitterest lesson"**（[00:21:11]–[00:22:12]）：⚠️ **数据比算力重要得多，而"选对任务 / 有北极星"是最难也最重要的**。LLM 史上的任务级转向只有约 **2.2 次**：RLHF（指令跟随）→ RLVR（"0.2 次，这还算宽容"）→ 他称的 **RLCD**（任务是"程序在循环里"）。
- **三个北极星的对照**（[01:22:56]）：**RHLF = 取悦人类**；**RLVR = 优化基准**（⚠️ "凡落进 RLVR 这一类的，按定义就是基准"）；**RLCD = 让它在程序化使用中可靠**。
- ⚠️ **"给我十亿美元我也不预训练"**（[01:50:22]）——太贵；他宁愿"切片、拼接"，"**Frankensteining 不优雅，但解决问题**"。他说私下对投资人说的话都会公开说。
- **经济北极星是 TFP，不是 AGI**（[01:18:54]–[01:20:54]）：⚠️ **五年内 TFP 增速 +3%**（主持人："我从没见过一个实验室关心 TFP 增速"）。他的质问是"**怎么可能做得了数学千禧难题，却做了世界经济价值工作的零**"；预期"**不会造成大规模失业**"，并认为 **SaaS 会被增强（"反向 SaaS 末日"）**，因为"他们最清楚什么值得自动化"。

## 对 pacing the frontier 的前提级反驳

来源同上（[01:43:16]–[02:06:34]）。本库目前**唯一一份从"你们的前提有替代项"这个角度反驳 pacing 的材料**。

- 技术澄清（[01:44:18]）：⚠️ "**RLVR 并不真的是关于'可验证的奖励'**"，重点是整套形状，其中推理是潜变量——**做事时让模型在中间想干什么就干什么**，以便尽可能强大。
- 反驳（[01:45:19]–[01:47:20]）：pacing 的讨论"**预设了所有人都需要做更多 RLVR**"——⚠️ "**对我们这个形状，零才是最优的 RLVR 量**"。他称这里有 **sleight of hand**："他们其实是在说我们想继续做那件看起来危险的事"；关于沙箱逃逸，⚠️ "**显然沙箱是问题，他们本可以轻松解决，但选择不解决，因为越让模型'什么都能做'它就越强**"。
- 归责（[01:47:20]）：⚠️ "**唯一有过错的是研究者**——公众只是假设 OpenAI、Anthropic 在尽力，而他们并不是清楚真实可选项的专家。"
- 自设边界（[01:47:20]）："**我的目标不是说服实验室还有别的方向**，而是让软件工程师重新有希望去自动化他们一直想自动化的东西。"
- ⚠️ 同一处**主持人**引入了一条政治解释（pacing 的推动"更多是政治定位"、指向 2028 年大选），Almeida 的反应是明显失望。**那条是主持人对私下对话的转述，本库未核实。**

## 对 neolab 的判断

（[02:03:32]–[02:05:34]）⚠️ **"大多数 neolab 是垃圾"**：他**不看重纯研究血统**（"那通常不创造价值"），看重**有多在乎选对任务**；他说多数 neolab "像在从零重做工作，推动前沿的概率很低"，而他谈过的多数**没有方向、只想要钱去玩实验**——"**如果他们有方向，我极其支持**"。给想出来创业的实验室研究者的建议是分情况：**只想玩研究，实验室就是最好的地方**；**想做对的任务，那就去打破这种单一心智**。他对自己也用同一把尺："我在乎的是成为一个可靠的开发者平台。"

## ⚠️ 2026-09-28 新增：对风投讲的那一版（a16z）

来源：[a16z：自动化到底在哪儿](../videos/20260928-a16z-diogo-almeida-smart-software-prod-not-god.md)

⚠️ **同一周内的第二份一手材料，立场一致但对象不同**：09-21 是**对工程师讲模型设计**，这一期是**对 [Ben Horowitz](a16z.md) 与 [Martin Casado](a16z.md) 讲软件为什么停滞**。本节只记新增的部分。

- ⚠️ **他自认最好的电梯演讲**（[a16z 09-28](../videos/20260928-a16z-diogo-almeida-smart-software-prod-not-god.md) 00:01:02）：**"自动化到底他妈在哪儿？"**——"**这么多智能，而 AI 聪明到离谱，却在所有其它事情上这么没用。**"他特意声明不是在黑 chatbot 和 coding agent（"我自己就爱用"）。
- ⚠️ **smart software ≠ just-in-time software（本库认为这是他最锋利的一条区分）**（[a16z 09-28](../videos/20260928-a16z-diogo-almeida-smart-software-prod-not-god.md) 00:03:05）：他**称赞** Garry Tan 等人对 Claude Code / Codex 的描述 "**just-in-time software**"——"了不起的描述"，**但"它和软件有着同样的表达力"**。他要的是**扩大软件本身能做的事，而不是自动化软件工程**。
- ⚠️ **"We build prod, not god"**（[a16z 09-28](../videos/20260928-a16z-diogo-almeida-smart-software-prod-not-god.md) 00:12:12）：Horowitz 说这是他最喜欢的一句，并指出反差——"换成任何别的大实验室领导，就算心里有喜悦也会把它盖住"。Almeida 把负面图景归因于 ⚠️ **"大家都在喝的那杯 mono model Kool-Aid"**（[00:13:12]）。
- ⚠️ **他把 RSI 与"OpenAI 定义的 AGI"明确拆开**（[a16z 09-28](../videos/20260928-a16z-diogo-almeida-smart-software-prod-not-god.md) 00:19:15–00:20:15）：**"我不认为我们走在 RSI 的路上——现在不认为，当时也不认为"**；**"但 OpenAI 定义的那个 AGI 极其做得到：自动化世界上大多数有经济价值的工作。"** 理由落在**工作的构成**而非能力增长（"大量工作非常机械简单，而做这件事所需的智能在模型里已经有相当一段时间了"）。详见 [AI for AI 与自动研究](../topics/ai-for-ai-and-auto-research.md)。
- ⚠️ **他的 canary**（[a16z 09-28](../videos/20260928-a16z-diogo-almeida-smart-software-prod-not-god.md) 00:21:15）：**"数学被解决了、两年前 GPQA 就被解决了，而我们还搞不定一个汽车餐厅点单窗口？"** 配套的机制解释是 ⚠️ **"因为人就是裁判，所以我们一直在优化那个裁判，而不是优化自动化那一侧"**（[00:20:15]）；时间尺度证据是 **"OpenAI 从 2020 年就在试图自动化客服了"**（[00:23:17]）。
- ⚠️ **他正面拒绝了"这是数据问题"**（[a16z 09-28](../videos/20260928-a16z-diogo-almeida-smart-software-prod-not-god.md) 00:21:15–00:23:17）：Casado 提出**真实世界是重尾的、我们没有那个分布的数据**，他的回答是 **"我不完全买数据这个论证"**——长尾当然存在，**但"在我这个 canary 的情形里，我们不需要自动化那条长尾"**，该不该自动化是个 **ROI 决策**。
- ⚠️ **他把"分类器"这顶帽子直接戴上**（[a16z 09-28](../videos/20260928-a16z-diogo-almeida-smart-software-prod-not-god.md) 00:06:08）：**"Jev 绝对是个分类器。分类器很赞啊——分类器当初就是为了有用而设计的。"** 推论：**"我猜 Jev 大概比请一支 2019 年的 MLE 团队还好，而且你可以现写现用。"**
- ⚠️ **coding agent：语法强、"架构上烂得离谱"，但也许够用**（[a16z 09-28](../videos/20260928-a16z-diogo-almeida-smart-software-prod-not-god.md) 00:28:18–00:29:18）：**"架构是软件里最具人类创造性的部分"**；但他立刻自我反驳——**"也许它们是第 50 百分位的架构。而如果你对架构一无所知，那就完全够用了。"**
- **可靠性拆成四层**（[a16z 09-28](../videos/20260928-a16z-diogo-almeida-smart-software-prod-not-god.md) 00:26:18–00:27:18）：uptime/SLA → determinism（"对单元测试有用，对真实系统没用"）→ robustness → ⚠️ **一层他说还没名字的："它不必每次都是相似的函数，但它必须每次都是聪明的。"** 终点是 ⚠️ **"让人们不写示例查询就直接对着 Jev 编程"**。
- ⚠️ **"反向 SaaS 末日"在这一期被讲完整了**（[a16z 09-28](../videos/20260928-a16z-diogo-almeida-smart-software-prod-not-god.md) 00:29:18–00:32:19）：**"SaaS 会是整个 AI 游戏里最大的赢家之一"**，因为**他们最清楚该自动化什么**；Horowitz 补上资本结构那一层（**分发已经付过钱**）。他的形态预测是 ⚠️ **"多选题表单会直接消失"**。详见 [AI 商业化与价值捕获](../topics/ai-business-and-value-capture.md)。
- **概率式编程**（[a16z 09-28](../videos/20260928-a16z-diogo-almeida-smart-software-prod-not-god.md) 00:35:20）：⚠️ **"会有一整个概率式编程的时代被打开"**，配一句施工顺序——**"先自动化容易的活，再自动化难的活，这永远是我的哲学。"** ⚠️ 这与 [Sinofsky 两天前（2026-09-26）的同一判断](a16z.md) 是本库里这条线的两次独立出现。
- ⚠️ **反生物启发**（[a16z 09-28](../videos/20260928-a16z-diogo-almeida-smart-software-prod-not-god.md) 00:36:20）：**"我的品牌是实用主义，极致的实用主义。我完全不喜欢受生物学启发的那套东西。"** 但他给了让步：**"它有用，它能驱动一群疯子在某件事上干几十年，直到它真的成了，然后他们把它提炼成工程版本。"**

### 更早的一段：从数学竞赛到 OpenAI

来源：[a16z：自动化到底在哪儿](../videos/20260928-a16z-diogo-almeida-smart-software-prod-not-god.md)

- ⚠️ **进入 AI 的方式本身就是他现在主张的预演**（[a16z 09-28](../videos/20260928-a16z-diogo-almeida-smart-software-prod-not-god.md) 00:09:10–00:12:12）：数学竞赛出身、得过奖，但**"我其实从没真喜欢过数学……数学一直是别人给我铺好的路，而我讨厌它，因为它永远只关乎赢比赛"**；转向 CS 是因为"**它基本就是数学，但更酷、更有用、更好玩**"，⚠️ 他自述 **"我认为自己首先是计算机科学家，其次才是 AI 研究者，尽管我的履历相反"**。真正把他带进 AI 的是 ⚠️ **赢了一个 Kaggle 比赛——"不是靠高深数学，而是靠把它自动化到死。更多的嵌套循环……它解决的是一个系统问题。"** 那场比赛的主办者是 ⚠️ **Isabelle Guyon（SVM 的共同发明人）**，她看出他**完全不属于研究圈**，于是收留他、带他见了所有 AI 的人。之后的链路是 **Jeremy Howard 的创业公司 → Google Brain → "退休了一阵" → OpenAI**（"我只是厌倦了什么都不做。我想，其实 AI 挺他妈好玩的"）。⚠️ 他也确认了一个更早的时间戳：**2017 年的演讲主题已经是《AI：理论上模块化，实践中灵活》**（[00:16:12]）。
- ⚠️ **他讲过的最直白的一次幻灭**（[a16z 09-28](../videos/20260928-a16z-diogo-almeida-smart-software-prod-not-god.md) 00:17:13–00:18:14）：**RLHF 的泛化让他"非常非常意外地惊喜"**（他把时间定在 **2021 年第四季度**），而团队确认"不是作弊"的方式是**构造一个确认过互联网上不存在的查询**（⚠️ "为什么冥想前吃袜子很重要"）。**"我真的以为那个模型有不小的机会就是 AGI。而当它不是的时候，我整个世界崩塌了，我就问：为什么？"**
### OpenAI 时期与离职

来源：[Latent Space：让代码而不是人来消费模型](../videos/20260921-latent-space-typesafe-jev-system-one-models.md)

- **InstructGPT**（[01:57:27]–[02:00:27]）：他极力推动部署，⚠️ 上线后"**基本立刻拿到当时 LLM 市场份额的一半**"；他当时真的在想"这是 AGI 吗，它在'指令进指令出'上超越人类"——⚠️ "显然不是，但**每个人都该能回答为什么那不是 AGI**"。他的答案来自结果：**它主要被用来写营销文案**（即现在说的 slop），"我们担心自己把互联网变得更糟了"。
- **北极星怎么来的**（[02:00:27]）：⚠️ "**从'AI 带来的经济革命'往回倒推——那件事发生时，如果 AI 是个 API，调用它的会是人还是代码？**"他判断"**代码会占好多个 9**"，而"所有优化都投在人那一侧"。他写了文档，**Sam 说"这太好了，你该去做这个"**；他当时以为"这么显然，Anthropic 肯定在做了"。
- **离职动因**（[02:01:27]）：⚠️ "**如果 AI 冬天发生、而我没尽一切努力阻止，我会认为自己负有个人责任**——既为 RHLF 这个方向（我认为它大大拉开了过度承诺与交付不足的差距），也为没有全力押上这个方向。"
- ⚠️ **自述"零创业者属性"**（[02:15:48]）："我不喜欢创业公司，从没想当 CEO，想不出谁会干两次。"他说在 OpenAI 感到被剥夺能动性——"像在一个所有人都只会说 ChatGPT 的疯人院里"。

## 与他人观点的交叉

- ⚠️ **与本库的 RLVR 主线正面冲突**：[Noam Brown](noam-brown.md)、[John Schulman](john-schulman.md)、[Charlie O'Neill](charlie-oneill.md) 等材料都在讨论**如何把 RLVR / 环境做得更好**；Almeida 认为"**凡落进 RLVR 这一类的按定义就是基准**"，并说对他这个形状零 RLVR 才最优。两条路线的分歧不在结论而在**任务定义**。
- **与 [Eiso Kant（Poolside）](eiso-kant.md) 的对照**：两人都是 neolab 处境、都强调"行为/可靠性胜过纸面智能"，但 Kant 的论证落在**模型工厂与开源商品化**，Almeida 落在**接口与被代码消费**；⚠️ 而 Almeida 明确不想被算作 neolab 同行。
- **与 [DHH](dhh.md) 的一处互补**（同次摄取）：DHH 说"**不要过度指定，尽可能含糊地先把东西变出来**"（对象是**人在驾驶的 coding agent**）；Almeida 说"**拆到最小语义单元、问很多很多小问题、每个都带阈值**"（对象是**跑在生产依赖里的决策**）。两条看似相反的建议其实对应不同的使用位置，本库在 [using-llms-in-practice](../topics/using-llms-in-practice.md) 里并列记录。
- **与 [Simon Mo](simon-mo.md) / [Baseten](baseten-team.md) 的接口**：他们从**推理引擎侧**讨论 KV cache 与调度；Almeida 从**产品形态侧**说"**KV cache 的暴政把 coding agent 锁进单模型世界、并毁掉状态管理与分解**"，并点名这解释了**路由为什么难、sub-agent 为什么看起来不 work、compaction 为什么是难题**（[02:10:38]）。
- **与 [OpenRouter](openrouter-atallah-midha.md) 的接口**：他观察到 ⚠️ **Claude Code 与 Codex 是围绕"单模型世界"建的，而开源 coding agent 因为能混搭而兴奋**（[01:40:15]）——这与路由层记录的"3 个月一轮的替代摆动"是同一现象的两侧。
- **与 [Brian Armstrong](brian-armstrong.md) 的接口**（同次摄取）：Armstrong 说 agent 之间的微支付主要买"**向另一个专才 agent 取源数据**"；Almeida 的"dark data"与"verify everything"用例族正是这种**被代码调用的廉价智能**的供给侧。
