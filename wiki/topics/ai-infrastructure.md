# AI 算力与基础设施

> 算力、电力、供应链、数据中心——AI 革命的物理层。

## Jensen Huang（美/NVIDIA，2026-03）

来源：[Lex #494](../videos/20260323-lex-jensen-huang-nvidia.md)

- **Extreme co-design**：问题装不进单机后，必须跨全栈（芯片→网络→供电冷却→系统软件→算法）协同设计，否则 Amdahl's Law 卡死；十年 100 万倍 vs 摩尔定律 100 倍。
- **电力是首要瓶颈**，但优先解法是制度性的：电网为最坏情况设计、99% 时间闲置约 40% 容量——数据中心签"可降级"合约吃存量电力；阻碍是客户的六个九合约文化。太空数据中心在做工程储备但属远期。
- **供应链即信念网络**：提前数年向上下游 CEO 灌输需求（HBM、LPDDR 进数据中心的例子）；NVLink-72 把超算组装搬进供应链（周产 ~200 pod，1 rack = 130 万零件、200 家供应商）。
- **Token 工厂**：计算机从仓库变工厂，token 分层定价；每年 token 成本降一个数量级（tokens/sec/watt 是核心指标）。

## Karpathy 的互补视角（美，2024-06）

工程底层的呼应：深度学习负载多数是 **memory-bound**，"flops 不重要，内存访问模式才重要"（FlashAttention 多算 flops 反而快 7.6 倍）；GPU 优化阶梯（精度/编译/kernel fusion/nice numbers）合计 11 倍。（[Let's reproduce GPT-2](../videos/20240609-karpathy-lets-reproduce-gpt2.md)）

## 芯片微观层：从逻辑门到 systolic array（Reiner Pope，美/MatX，2026-05）

来源：[Dwarkesh 芯片设计课](../videos/20260522-dwarkesh-reiner-pope-chip-design.md)

- 为本页提供最底层的电路视角：**"最大化计算相对通信"贯穿全栈**——ALU 位宽（乘法器门数随位宽**平方**增长，是低精度算术有效的唯一根本原因）、Tensor Core/systolic array（把矩阵乘外层循环烧进硬件、权重驻留，否则 7/8 面积耗在寄存器堆搬运）、直到跨芯片推理的 batch 权衡（00:14–00:37）。与 Karpathy "flops 不重要、内存访问模式才重要" 是同一原理的上下两层。
- **"GPU 是一大堆微型 TPU 平铺"**：TPU 粗粒度（超大 MXU）摊销搬运成本但 vector↔matrix 带宽受限，GPU 细粒度灵活但单元固定开销大；MatX 押注 splittable systolic array 兼得两者（01:15–01:20）——为本页姚顺宇的 TPU/GPU 使用方对照补上设计方视角。
- TPU 用 **scratchpad（软件显式管理）替代 cache（硬件自动）**换确定性延迟（01:04–01:07）；大脑低时钟类比在硅上不成立——降频只线性省开关能耗，不带来能效跃升（01:12–01:15）。

## TPU vs GPU（姚顺宇，Google DeepMind，2026-05）

来源：[张小珺访谈](../videos/20260511-zhang-xiaojun-yao-shunyu.md)

- 大规模商用下**无绝对优劣**。设计理念差异：GPU（Hopper/H 系列）一个 pod 内约 8 卡两两 NVLink 高速互联；**TPU 抛弃两两互联、采 3D Torus 拓扑**，尽量多卡放一个架子，编译器/sharding 写得好则等效更大存储 + 减少通信 bound。
- TPU 劣势：小 scale 更固定、通用性弱、无开源生态——但"大规模自用时生态不是问题，跑几十万张卡的集群，搭基础设施不是多大的事"（03:20–03:23）。
- 这与 Jensen 从 NVIDIA 侧强调的 NVLink-72/install-base 生态形成对照：姚从使用方视角认为在超大规模下 TPU 的封闭生态不构成实质劣势。

## test-time compute 的经济性（Noam Brown，OpenAI，2026-06）

- 模型能力成为"投入金钱的函数"，把**推理时算力**变成基础设施的一等成本项；评估长任务"可能要跑一年"，与算力/时间预算直接冲突（[No Priors 访谈](../videos/20260626-no-priors-noam-brown.md) 00:12–00:16）。呼应 Jensen"token 工厂 / tokens-per-sec-per-watt"的世界观。

## 算力需求的经济学：Moore 定律"价值减半"与机会成本反转（Imas & Trammell，2026-06）

来源：[Dwarkesh 访谈](../videos/20260604-dwarkesh-imas-trammell.md)

- Moore 定律的悲观解读："每 18 个月**计算的价值**减半——我们消耗算力用途的速度快到刚好维持摩尔定律"；Chad Jones 的结论是经济中付给算力（晶体管）的份额一直在下降（00:13–00:15）。
- 但可能出现拐点：**H100 租金比三年前更高**——模型越聪明，算力的机会成本越高，即"资本用途的新品类（increasing variety）不断出现"让需求不饱和；若持续，付给算力的经济份额会持续上升（00:14–00:16）。这为 Jensen"token 工厂 / 每年 token 成本降一个数量级"提供了一个需求侧的经济学镜像：**供给侧成本在降，但用途在爆炸**。

## capex 的物理上限与"模型只相关 3–9 个月"（Benedict Evans，前 a16z，2026-06）

来源：[a16z 访谈](../videos/20260608-a16z-benedict-evans-ai-economics.md)

- 微软/Meta/Google 今年 capex 均超营收 **50%**（电信才 15–20%），四大指引约 **7000 亿美元/年**——与油气（7000 亿–1 万亿）同量级，"很多钱但非天量"（00:48–00:49）。
- 但存在硬顶："**不可能一年花 10 万亿美元在 AI 基础设施上，因为世界上没有 10 万亿可花**"；1.5 万亿只能借、不可持续 → 增长终将放缓（00:49）。
- 贯穿其分析的一条线：**模型只在 3–9 个月内相关，却要花数十亿造，还得永远追下一个**——这放大了基础设施投资相对回报窗口的不匹配（00:50）。与 Jensen"token 工厂/每年成本降一个数量级"是供给侧乐观，与本节 Imas·Trammell 的需求侧"用途爆炸让算力份额上升"共同构成 capex 是否可持续的两面。价值捕获视角详见 [AI 商业化与价值捕获](ai-business-and-value-capture.md)。

## 端侧AI芯片：从冯诺依曼到存算一体（阳萌，中/安克，2026-06）

来源：[张小珺访谈](../videos/20260608-zhang-xiaojun-yangmeng-anker.md)

- **三个底层变革叠加**（[01:03:43]）：解题方法（分治法→端到端）、软件形态（程序+数据→神经网络）、硬件架构（冯诺依曼存算分离→存算一体），"构成了一个特别稳定的三角，端到端时代这个三角应该被打破"。
- **类比大脑**（[01:09:45]）：人脑不存在"把左脑知识搬到右脑计算"的问题——存算一体。冯诺依曼架构下每帧都要把所有参数从内存搬到NPU，"搬运本身就是最大功耗"。
- **2026年5月量产**：4M参数总量、单个模型~2M参数的存算芯片，用于耳机通话降噪。"一颗市面上不存在的、这个领域第一颗应用到产品上的芯片"（[01:16:52]）。
- **分层芯片路线**（[01:21:53]）：百万参数（感知/控制器官）→ 数十亿参数（大脑）→ 未来可能承载具身大脑。"不是做芯片公司，是芯片+模型+产品的闭环"——类比苹果A/M系、华为麒麟（[01:22:53]）。路线与NVIDIA差异化：NVIDIA在训练侧+万忆级推理，存算在推理侧百万到百亿参数。

## 太空数据中心：绕过地球电网瓶颈（Lewis Hong，前SpaceX，2026-06）

来源：[张小珺访谈](../videos/20260613-zhang-xiaojun-spacex-lewis.md)

## 推理引擎与 RL 训练 Infra（朱邦华，中/SGLang 母公司，2026-05）

来源：[月球大叔访谈](../videos/20260518-uncle-moon-banghua-zhu-sglang.md)

- **需求排序 pre-training < RL < 推理**：推理是最大需求（所有用 AI 处都要 inference），故 SGLang 母公司从推理引擎切入，逐步做 RL、乃至 pre-training 的 inference（00:05:02）。这与 [江鋆晨](../videos/20260609-uncle-moon-junchen-jiang-kvcache.md)"training infra 太一次性、模型绝大多数生命周期在推理"是同一判断。
- **RL environments 是被忽视的新瓶颈**：agent 环境越复杂，bottleneck 常在 function calling 的 latency/concurrency——这是"为什么大家突然发现 CPU 很重要"（code execution / multi-docker 的 CPU 调度）；reward 设计是"艺术问题"（00:24:25–00:25:26）。硅谷已有一批 RL 环境公司（如 E2B），国内偏少。
- **新架构逼出 infra 优化**：DeepSeek V4 的架构创新（sparse attention 等）逼 SGLang 做 **shadow radix**（prefix cache）与 sparse attention 优化，"划走公司一半人精力"，把 V4 性能优化了很多倍；SGLang"day one 支持新模型"（00:19:16–00:21:21）。
- **"卡养人"**：千卡/万卡训练对 fault tolerance、MFU、accuracy 的 infra 要求与小规模完全不同——这是 frontier lab 人才稀缺的根源；"本科生摸够卡会比 PhD 干得好"（00:43:47–00:45:47）。呼应 [姚顺宇](../videos/20260511-zhang-xiaojun-yao-shunyu.md)。

## DeepSeek V4 混合注意力的推理/训练适配（SGLang·Miles 团队，中，2026-05）

来源：[月球大叔 SGLang 直播](../videos/20260501-uncle-moon-sglang-deepseek-v4.md)

一线框架工程的具体案例，把 [朱邦华](../videos/20260518-uncle-moon-banghua-zhu-sglang.md)"新架构逼出 infra 优化"落到 DeepSeek V4：

- **V4 混合稀疏注意力**：SWA（sliding window）+ Compress-4（每 4 token 压 1，hierarchical top-k 选最有影响力的）+ Compress-128（每 128 压 1，全注意力），框架要维护五类 KV cache 状态——用 **shadow radix cache**（虚拟地址映射物理状态）管理（00:04–00:09）。KV cache 大幅压缩（100 万 token < 10GB），打开 offload 到 CPU 的空间（验证 3× 上下文性能，00:20）。与本页 [罗福莉](../videos/20260424-zhang-xiaojun-luo-fuli-agent-paradigm.md) 的 hybrid attention 独立同频："系统约束使混合稀疏是大势所趋"。
- **kernel 级优化**：把 KV 压缩的 5 次内存读取里的 3 个计算融成一个算子；**lightning topk** 把长上下文 topk 从 100μs 优化到 15μs（V4 有 60 层，累计影响巨大）（00:09–00:12）。但"算子融合并非总有效"——两算子须能沿同一维度切分（00:47）。
- **并行**：长上下文用 CP（单机内快）、跨机用 PP；V4 注意力不天然支持 TP（kernel 要求头数是 64 倍数，用 padding）；已支持 PD 分离（00:12–00:19）。
- **RL 训练（Miles）比推理难 day-0 支持**：无标准 baseline、要 backward、debug 成本大；精度是最耗时环节（CP 下 KV gradient 因 compress attention 稀疏、reduction 复杂使 BF16 不够，需换 FP32）；借鉴 DeepSeek deterministic ops 消除 KL loss spike（00:22–00:35）。详见 [LLM 训练管线](llm-training-pipeline.md)。
- 月球大叔总结的方法论："做 MLSys 别只补代码小窟窿，要抽象出框架——system research 需要美感"；**数据管理是被低估的新方向**（agent 持续记忆、Dreams vs Memory），与 [江鋆晨"KV Cache 是下一个数据层"](../videos/20260609-uncle-moon-junchen-jiang-kvcache.md) 同频（01:00–01:04）。

## KV Cache 作为独立数据层（江鋆晨，中/TensorMesh·LMCache，2026-06）

来源：[月球大叔访谈](../videos/20260609-uncle-moon-junchen-jiang-kvcache.md)

- **KV Cache = 大模型的记忆 = "给大模型看的视频"**（都是 3D tensor）；押注它是继模型权重、prompt 之后**下一个最大的数据层**、"未来的石油"（00:40:55–00:43:56）。数据层普适规律：web→CDN、大数据→Spark/HDFS、AI→KV Cache（00:37:50–00:39:52）。
- **LMCache**：把 KV Cache 层与推理引擎/存储/GPU/运行环境**解耦**（不与模型解耦），做成工业界事实标准；当前可见价值 = 存下 KV Cache 避免重复计算（读长程序时 90%+ input 是那段程序，存下即跳过 90% 重算）（01:24:23–01:29:28）。类比 Spark"踩着工业界实体出来"。
- **prefill vs decode 的算力误区（反直觉）**：硬件（Cerebras/Groq/LPU）多优化 decode（用户可见"一个字一个字蹦"），但 **~90% 算力其实花在 prefill/处理 input**——agent 的 input（几十万~几百万 token）远长于 output，且"任何 output 都会变成以后的 input"（01:31:30–01:34:32）。这是对"算力大头在生成"这一直觉的直接纠偏。
- **OpenAI API 兼容格式 = AI 时代的 IPv4**：网络的"细腰"是 IP layer，其上创新极难（IPv6 更好却输给 IPv4 的既成事实）；AI 生态里 OpenAI API Compatible 的 query format 已是所有应用/模型/推理商承认的稳定接口，**KV Cache 有望成为下一个这样的标准层**（02:04:50–02:08:54）。
- **硬件"IBM 化" vs disaggregation**：厂商把处理器/网络/存储 bundle 成大型机（走 IBM 老路）以最大化 margin；但历史上大型机没成数据中心主流，真正胜出的是"把便宜部件用聪明方法连起来"；**disaggregation 做到极致**（每块特殊化、可替换）可能带来颠覆性新 infra（02:08:54–02:12:56）。这与本页 [阳萌](../videos/20260608-zhang-xiaojun-yangmeng-anker.md) 的存算一体、[Jensen](../videos/20260323-lex-jensen-huang-nvidia.md) 的 extreme co-design 构成"硬件组织形态"的三种下注方向。

## Agent Cloud 与统一存储层（Matei Zaharia & Reynold Xin，美/Databricks，2026-06）

来源：[Latent Space 访谈](../videos/20260624-latent-space-databricks-agent-cloud.md)

- **Omnigent = 跨 harness 的公共 API + agent cloud**：把 Claude Code/Codex/Cursor 等所有 harness 映射到一套 session API（收 message/file、吐 streaming/tool-call 流），上层做协作/安全/成本控制；开源以吃"众人写 integration"的网络效应（发布首周末 ~400 merge）。Zaharia 明确类比**网络协议（IP layer）而非 OS/数据库**——与 [江鋆晨"OpenAI API = IPv4 细腰"](../videos/20260609-uncle-moon-junchen-jiang-kvcache.md) 是同一"稳定接口层"直觉的两个落点（00:04–00:16）。
- **agent cloud / 不关机 sandbox**：从 lakebase 架构去掉数据库即得；需本地持久化（库不每次重装）——解决"开车还得盯 Codex session"的荒诞（00:07–00:17）。
- **"把数据放到对的地方，糊一层 AGI"**：**L-TAP** 只统一存储层（Postgres 页用空闲 CPU 转码成列式 parquet，无 CDC 管道），让 agent 实时 reason 业务数据、强 10 倍；**Dream Engine** 用 **ML 模型（非 LLM）+ 十年 trace** 从零重建数据库引擎、运行时 dispatch 最优数据结构（00:32–00:50）。这是"数据层 vs 计算层"权衡的又一形态，与本页 [江鋆晨](../videos/20260609-uncle-moon-junchen-jiang-kvcache.md) 的 KV Cache 数据层、[Reiner Pope](../videos/20260522-dwarkesh-reiner-pope-chip-design.md) 的芯片级搬运税同属"计算 vs 通信/数据"主线。

## 面向 Agent 的架构与 RL Infra（罗福莉，小米 MemoVR，2026-04）

来源：[罗福莉访谈](../videos/20260424-zhang-xiaojun-luo-fuli-agent-paradigm.md)

- **hybrid attention 取代 MLA 以适配 agent**：MLA 为 Chat 时代精妙地压 KV Cache 而生，但"没有可发挥空间"——上 MTP 会卡在 compute bound；MemoVR 用 **sliding window + full attention 混合**（Flash 5:1、Pro 拉到 **7:1**），更省 KV Cache、支持更长上下文，"更大模型可以更稀疏"（01:26:48–02:06:02）。与江鋆晨"KV Cache 是核心数据层"从模型架构侧呼应：省 KV Cache 是 agent 长上下文的关键。
- **MTP（Multi-Token Prediction）只有她们在推理时用**：因 hybrid 架构天然留大量计算富裕，用投机解码把富裕算力吃满；**MTP 被 verify、无幻觉**；Flash 做到 100–150 TPS（01:31:50–01:38:52）。MLA 模型上不了 MTP 正因为它已卡在算力/访存的完美临界点。
- **RL infra ≠ 预训练 infra**：**RL infra 必须容错**（agent 交互会莫名中断、训推不一致要容忍、要在异构集群里综合调度 GPU+CPU+存储），而预训练 infra"绝不容忍 loss spike"，两者不交融（03:30:03–03:33:04）。**"真正把 agent RL scale 起来的团队非常少，海外基本只有 Anthropic"**（03:33:04）——与朱邦华"RL environments 是新瓶颈、CPU 因 function-calling 并发变重要"精确对接。
- **卡是瓶颈**：研究:预训练:后训练 = 3:1:1，研究用卡是训练的 3–5 倍；"idea 到代码太快，卡在卡上"（01:45:55–01:48:55）。推理卡需求远高于训练卡。
- **全模态离散化**：音频用多层 RVQ 离散成 token（"另类"架构），图像离散化进行中——追求"一套 infra 服用所有模态"，但"有了 Qi-code 后重写一套 infra 也就两三周，没必要为架构统一牺牲模型结构"（02:12:05–02:14:09）。

## 模型即操作系统/基础设施（广密，2026-04）

来源：[广密·全球大模型季报第 9 集](../videos/20260415-zhang-xiaojun-guangmi-llm-quarterly-9.md)

- **最领先的三五家模型 = 世界最重要的技术基础设施 = global GDP 的操作系统**，重要性将超过今天的 Google（01:04:51–01:06:53）。详见 [LLM OS](llm-os.md)。

## 能源作为 AI 的真实上限（2026-07 三方汇合）

来源：[Pat Gelsinger](../videos/20260715-all-in-gelsinger-lovable.md) · [All-In / SRO 与数据中心](../videos/20260718-all-in-sro-regulation-datacenters.md) · [a16z / 挑选 AI 赢家](../videos/20260529-a16z-picking-ai-winners.md)

2026 年 7 月这批素材里，三个立场迥异的来源**独立收敛到同一结论：约束不在芯片、不在算法，在电子**。

- **[Gelsinger](../people/pat-gelsinger.md)：能源容量是天然的防泡沫上限**——"没人会在没有能源的情况下买 GPU、建数据中心，所以你能有多泡沫**有个上界**。我从中得到不少安慰。"（世界能源容量以 4–5% 扩张；美国曾有十年只有 1%。）他的对冲目标是**把每 token 成本与能耗降五个数量级（10000x）**以真正触发 Jevons 效应。
- **[a16z 成长期](../people/a16z.md)：供给受限而非需求受限，所以不是泡沫**——"我相当有信心说我们现在不在泡沫里，没那么有信心说三年后不在。"**规模化数据中心容量要等到 2028 年底/2029 年初**；美国建设进度**落后约一年**；供应链几乎每环受限（部分因 TSMC 有意克制）。唯一可能翻转的变量是**大幅变小的模型**（来自算法突破）。
- **[Chamath](../people/all-in-hosts.md)：缺口的量级**——美国到 2050 年将短缺约 **2.5 个加州**的用电量。一次 PJM 容量拍卖需 7–8 GW，**仅约 156 MW 应标**。

### behind-the-meter 与清洁空气许可（本库最具体的一段电力工程/监管解释）
- 并网（grid power）排队排不上 → 只能 **behind-the-meter**（自有地块自建发电）。
- 卡点是**清洁空气许可**：太阳能占地太大；电池仍需先发电；所以实际多用燃气。
- Elon 的规避路径：买下大量 18 轮卡车级发动机（并买下制造商），**逐台落地按"自用"处理**以绕开集中式许可；新方案如 **Bloom Energy** 可在大规模安装下仍适用自用清洁空气许可。
- **资产定价的证据**：Chamath 持有的一组电力/数据中心资产在向超大规模厂商询价时发现"**曲线前端的价格极端之高**"——**今天就能验证、能通电的电力值大钱**，因为往后看约 **40% 的项目会被搁置或停掉**。

### 政治阻力已成为基础设施变量
- 纽约州签署**全美首个州级超大规模数据中心暂停令**。Sacks 逐条反驳（behind-the-meter 可解电价问题；数据中心是土地利用效率典范、纽约州本身 70–80% 未开发；现代数据中心闭环循环用水；天然气是较清洁燃烧源），并指出 **moratorium 实际不是数月而是至少五年**——即使解禁，项目重启也要数年。
- Sacks 补一层结构性观察：同一批政治力量既阻止美国建、**也在推动对盟友的芯片出口管制**——"这里不建，盟友那里也不建，那这些东西放哪儿？"
- 地理转移的实况（Chamath）：中东增长**没有如预期发生**（位置本极佳，200 毫秒内服务 40 亿人），反而是**亚洲、特别是澳大利亚**爆发；最新变化是 **UAE 已可进口最先进芯片**，他认为中东周期会重启。
- Jason 的"**奢侈品监管**"框架："纽约州或加州付得起说'我们不需要这个'。如果你是澳大利亚，你可能真的需要这笔钱。**虚拟信号只能撑到你的债务/GDP 高到某个程度为止。**"
- ⚠️ 关于反数据中心运动可能有外国影响的论证（Friedberg 的反 GMO 类比、OpenAI 关于 PRC 关联影响力行动的博文），见[视频页](../videos/20260718-all-in-sro-regulation-datacenters.md)的标注——**除该博文外未给出可核验证据，相关性≠因果**。

## 推理专用芯片与代工格局（2026-07 补充）

## 反向读数：能效突破会不会让已建产能作废（2026-07）

本库此前积累的主流论证是"**能源是天然的防泡沫上限**"——[Gelsinger](../people/pat-gelsinger.md)（"没人会在没有能源的情况下买 GPU、建数据中心，所以你对能有多泡沫有个上界，我从中得到不少安慰"）与 [a16z 成长期](../videos/20260529-a16z-picking-ai-winners.md)（"供给受限而非需求受限，所以不是泡沫"）是同一论证的两个版本。

[Mark Cuban](../people/mark-cuban.md) 用**同一个能源事实**得出了**相反方向的风险读数**（[视频页](../videos/20260721-all-in-mark-cuban-ai-bubble.md) 00:02–00:03）：

> **"如果 AI 上出现一条能大幅降低电力需求的性价比曲线，会有很多数据中心被改造成匹克球场。"**

- 论证走的是**光纤先例**：当年所有人都在铺光纤，然后 1G → 10G → 100G，"**突然就不再有光纤问题了、不再有带宽问题了**"——反而剩下大量暗光纤，后来以几分钱被人捡走。"AI 侧和数据中心侧凭什么就不会得到同样的性价比改善？"
- 关键在于**承诺周期与技术周期错配**：他承认利用率会按大家预期的那样 scale，但坚持技术突破会同时发生，而"**为 10 年、20 年后的事承诺几百亿美元，没人预测得了**"。
- 叠加的金融结构风险：巨头把现金流全砸进 capex **再在其上借债发债**，"**这是在按完美情况定价**"；且"本来就已经有一个私募信贷问题了"。
- 值得注意的是，**这条与 Gelsinger 自己的另一个目标恰好互为镜像**：Gelsinger 给自己定的目标是"把 AI 做好 10000 倍——每 token 的成本与能耗降五个数量级"。若这个目标达成，正是 Cuban 描述的那条曲线。**两人的分歧不在事实，而在于"效率提升被 Jevons 效应吃掉"还是"效率提升先于需求到来"。**
- Cuban 自陈的证伪条件（这一条使他的判断可跟踪）：**"如果我在数据中心这件事上会判断错，那会是因为视频"**——视频、世界模型、机器人相关，要多一个数量级的 token。
- 一个次级观察：他认为**围绕数据中心的民意反弹反而可能"保护"了它们**（限制了过度建设）——与本页"政治阻力已成为基础设施变量"一节的悲观读法相反。

## 实时性约束：物理 AI 的算力形状不同（Applied Intuition，2026-07）

来源：[为什么物理 AI 是下一个前沿](../videos/20260721-a16z-applied-intuition-physical-ai.md)

本页此前的算力论述基本都是**数据中心侧**的（token 工厂、电力、供应链）。Applied Intuition 补上了**端侧/实时侧**的一条根本约束：

> "那些实验室日子好过——他们可以做万亿参数的模型，模型可以超级慢，那没关系。**物理 AI 没有这个奢侈品。我们面对的是真实的时钟，我们只有那么多毫秒。**"

- 结构后果：**offboard 用很大的模型，onboard 必须是小模型 + 安全约束 + 确定性约束**。"这是物理 AI 难的地方，**也正是护城河**。"
- [沈宇军（蚂蚁灵波）](../people/shen-yujun.md) 从模型架构侧给出了同一约束的中方版本：因为机器人不能像文生视频那样让用户等 10–30 秒，所以**必须单向（causal）建模**、必须用 **MoE** 稀疏激活（"14B dense 模型推理激活就是 14B，你后面加速做得再好，能加速的比例是固定的"），而**可以舍弃的是画质**（"有点马赛克没关系——因为我们还有摄像头"）。
- 这条与 [阳萌的端侧分层模型](../people/yangmeng-steven.md)（百万参数感知器官 → 十亿参数大脑 → 万亿参数云端）、[Reiner Pope 的自底向上芯片设计](../videos/20260522-dwarkesh-reiner-pope-chip-design.md) 共同构成"**约束定义架构**"这一族——与数据中心侧"scale 定义架构"恰成对照。
- 另一条被 Applied Intuition 点出的基础设施事实：物理 AI 的数据**不在互联网上，必须自采**（他们自称数百 PB、"地球上最大的采集车队之一"），而**采集权限的门槛是地缘政治而非技术**（韩国不许可测绘公司；他们摸清了在中东、拉美与政府打交道的路径）。

## RL 的墙钟瓶颈：把 PD 解耦引入训练、低精度、算力政治（Eiso Kant / Poolside，2026-07）

来源：[Poolside 访谈](../videos/20260722-latent-space-poolside-eiso-kant.md)

本页此前的 prefill/decode 解耦（PD disaggregation）讨论都在**推理侧**（江鋆晨、Modal、Cerebras）。Poolside 把它接到了**训练侧**：

- **RL 是 batch-size 受限的**：任务数有限（不像整个 web 可无限放大 batch），所以**不能像预训练那样堆 GPU 扩算力**；**RL 时间是当前最大的墙钟瓶颈**。而"竞赛是按日历时间算的，不是按 GPU 数"——所以给行业提速最大的杠杆之一就是提高 RL 的 wall-clock 效率。
- **解法：把推理侧已成熟的 PD 解耦、异构硬件混搭引入 RL 训练**（GPU 做一段、Groq/LPU 类专用芯片做另一段）——这是把[江鋆晨"prefill vs decode 算力误区"](../videos/20260609-uncle-moon-junchen-jiang-kvcache.md)、[Modal 的 inference inflection](../videos/20260708-latent-space-modal-agent-infra.md)从推理迁移到训练的一个明确方向。
- **低精度训练**：Laguna S 用 FP8（新 run 里唯一非 FP8 的是 all-to-all）；最兴奋 ternary、**NVFP4（点名 Nematron 的 NVFP4 训练被低估）**；现在还在 10k H200（Hopper）集群、相对小，转 Blackwell 后上 NVFP4/低精度 RL。核心 bottleneck 归结为"MAC 瓶颈 + 网络瓶颈"，呼应 [Reiner Pope"最大化计算相对通信"](../videos/20260522-dwarkesh-reiner-pope-chip-design.md)。
- **算力政治**："Nvidia 比美国政府更有权力（算力分配 → TSMC → 下面）"；但 Eiso 认为 Nvidia 促进竞争、受监管，与"政府用监管禁止别人做基础模型"性质不同。模型能力与硬件世代强绑定——"Hopper 上能训的和 GB300 上能训的，差的是 1T 参数和 5–6T 参数的距离"。

## 碎片化对基础设施层最有利，以及"五个九"的成本阶梯（All-In，2026-07）

### "五个九"的成本阶梯：本页少见的进入壁垒量化

Chamath 在回答"Apple 该不该做云"时给出（01:14–01:15）：

| 可用性 | 大致成本量级 |
|---|---|
| 99%（两个九） | 相对便宜（给药企/国防托管也能做到） |
| 99.9%（第三个九） | **数十亿美元** |
| 99.99%（第四个九） | **数百亿美元** |
| 99.999%（第五个九） | **数千亿美元** |

- 结论："这需要真金白银和真本事，**场上只有三家**"；AWS 花了约 **17 年**打磨，Google 花了 **12–13 年**才基本追上。
- 对照：Apple 过去十年 **7550 亿回购 + 1400 亿分红 ≈ 9000 亿美元**返还股东（Sacks 的反问："谁说拿到这笔钱的投资人就没找到好用途？"）。

## 推理引擎层：模型与 Infra 的 co-design（游凯超，中/vLLM，2026-07）

来源：[张小珺访谈 #148](../videos/20260728-zhang-xiaojun-you-kaichao-vllm.md)。本页此前的视角覆盖芯片（Pope）、系统（Jensen）、KV Cache 数据层（江鋆晨），**独缺把模型跑起来的那一层**——推理引擎。这是本库首份来自 vLLM 核心维护者的一手材料。

### 推理引擎 = 电力系统

游凯超反复使用的框架（[00:54:24]–[00:56:29]、[01:52:36]）：**硬件 = 自然资源（风/水/光）、模型 = 发电机、推理引擎 = 电力系统**。
- **推理引擎的职责是屏蔽复杂性**："用户只是从下拉菜单里点了一个模型，或者只是改了一个参数说我今天请求的是 DeepSeek、明天是通义千问，**但从背后的推理引擎来看，不同模型的支持效率、适配硬件其实是千差万别的**。"
- vLLM 的 V0→V1 重构"好比发电系统从火电过渡到新能源"——**用户侧无感，底层原理巨变**；因此"**vLLM 其实一直是在重构的过程中**"，最难的是在模型/硬件不断变动下保持前端体验统一。

### ⚠️ 对本页"token 工厂"框架的一条重要限定

游凯超接受"token 即电力"的类比，但给了它一条边界（[00:01]–[00:02]，⚠️ 仅存于片头预告，完整论证不在上传版正文中）：

> "大家把 token 和电做类比的时候，可能会觉得电它是比较通用的、可以调制的，**但是 token 它是没有办法去做调制的**——你没有办法把一个 DeepSeek 模型的 token 转化为一个 Kimi 的 token，**这个 token 它是带着模型的烙印的**。"

这是对 [Jensen Huang 的 "token 工厂 / token 分层定价"](#jensen-huangnvidia2026-03) 世界观来自推理引擎一线的修正：**token 不是同质商品，不可跨供给源互换**，因此"token 价格"不像电价那样可以套利，也意味着 [AI 商业化与价值捕获](ai-business-and-value-capture.md) 中"模型商品化"的论证需要在**供给可替代性**这一点上更小心。

### 硬件彩票（Hardware Lottery）：模型结构决定推理效率的上界

[01:54:40]–[01:56:42]。这是本页 [Reiner Pope 芯片微观视角](#芯片微观层从逻辑门到-systolic-array-reiner-pope美matx2026-05)的**软件侧后果**：

- 摩尔定律黄金时代软硬件各自为战——"你写软件的人不需要考虑那么多硬件特性，因为硬件的**通用**性能每隔两年翻一倍"。
- 如今进入**专用时代**："英伟达经常说黄氏定律，算力每隔两年又会翻几倍，**但这个算力它其实都是专用的算力**。如果你的算法没有利用到这些专用算力，**你就没有抽中硬件的那个彩票，就吃不到这个时代的红利**。"
- **核心断言**：**"模型的结构决定了推理效率的一个上界。如果上界太低了，那系统工程师就无力回天了。"**
- 反例 **Hinton 的 Capsule Network**（概念上 make sense 但 GPU 不友好，至今未广泛应用）；正例 **Transformer 抽中了 GPU 的彩票**（大量矩阵乘法、适合并行）。
- **谁迁就谁**：理想是协作，现实是**硬件更强势**（"因为硬件它已经造出来了"），代价则是硬件公司"**一旦走错了，就是几年的时间走错了**"。公司内部同理：**"很多公司里面是算法的话语权更高一些，infra 很多时候是一个被动接收的状态。"**

### co-design 的一正一反两个案例

**正例：RoPE 为什么赢了**（[01:56:42]–[01:58:44]）——本页最能说明 co-design 机制的一段：
1. Transformer 之后位置编码"少说可以找到上百种实现"，但**多数实现需要改注意力 kernel**。
2. 训练长度提升使 **FlashAttention 成为训练必需品**，而"大部分用户没有能力去修改 FlashAttention"——于是**所有需要改 attention 内部实现的位置编码都被淘汰**（例：ALiBi 是 absolute position bias，因此未能广泛应用）。
3. RoPE **兼具绝对与相对位置编码的性质，且可独立注入 query/key、独立于 attention kernel 之外**——"所以它跟 attention kernel 是互补的，就变成了一个最佳搭档"。

**反例：expert choice**（[02:01:47]）——"MoE 里面曾经出现过一些 **infra 同学为了 MoE 的均衡而选择了 expert choice**，这个事情**在算法上其实是不能被接受的，但是在 infra 上你可以让它跑得很快**"。他明确定性为"**过度倾斜到 infra 的一个例子**"：co-design 失衡在两个方向上都会出问题。

**落地机制**：招既懂算法又懂 infra 的人最好；组织上**一起办公**产生"耳濡目染"的潜移默化。

### DeepSeek 的 infra：一手观察与机制解释

[01:59:45]–[02:05:53]。此前本库对 DeepSeek infra 的记载多为转述与推测，这是来自其**上游推理引擎维护者**的直接评价：

- **"DeepSeek 的 infra 团队可以说是全球顶级的团队"**，机制是**双向的**：infra 强 → 可高效实现的模型结构更多 → 算法研究员探索空间更大；同时**算法同学也懂 infra**——DeepSeekMoE 早期那版较粗粒度 MoE 的高效实现**出自一位算法同学之手**，细粒度 MoE 也是他们在推理系统里第一个做出来的。
- **合作史比外界以为的早**：DeepSeek 内部从 2023/24 年起就用 vLLM（加了自有优化变种），"**24 年的时候 DeepSeek 还属于社区里面的一员，只是一个泯然众人的模型厂商**"。R1 之后关系反转——"**他们在推理引擎方面虽然基于 vLLM 做，但比我们做得往前面走了很多，我们当时是在不断跟他们学习的过程中**"。
- **投机解码的现状**（⚠️ 方法名 "DSpark" / 路线名 "DFlash" 均为转录音，官方名待核）：EAGLE / MTP 系猜得短（3–5 个 token）但接收率高；DFlash 系一次猜 16 个但错得也多、验证阶段浪费算力；DSpark 的改进是**先用置信度估计哪几个猜测大概率准，只验证前若干个**。vLLM 与 NVIDIA 刚发布的 DFlash 支持"**可以对某些模型达到每秒上千 token**"。
- 他对创新性的判断很克制（"在算法上并不能算很 novel"，腾讯混元、上海交大已有同思路工作），但随即给出本节的收束——也是整个 co-design 论的落点：
  > "**创新性是一回事，能不能把这个创新的想法扎实地做出来又是另一回事。**……**有没有一个好的推理引擎上的实现，是决定一个投机解码算法能不能大规模使用的关键。**"
- ⚠️ 他把 DeepSeek 的 infra 功底归因于**幻方量化时期对性能的极致压榨**，但该判断仅存于片头预告（[00:01]），完整论证不在上传版正文中。

## ⚠️ 数据中心之外这一层：用 Wi-Fi 替代 PCIe（孟子立 / WiCi，中，2026-07）

来源：[月球大叔访谈](../videos/20260728-uncle-moon-zili-meng-wici.md)。本页此前所有的中方 infra 视角（[游凯超/vLLM](#推理引擎层模型与-infra-的-co-design游凯超中vllm2026-07)、[朱邦华/SGLang](#推理引擎与-rl-训练-infra朱邦华中sglang-母公司2026-05)、[江鋆晨/KV Cache](#kv-cache-作为独立数据层江鋆晨中tensormeshlmcache2026-06)、[vLLM Omni](#多模态全模态-serving-stage-抽象与-dit-加速vllm-omni-团队中2026-05)）都在**数据中心内部**做推理效率。[孟子立](../people/zili-meng.md)（港科大助理教授、网络系统出身）补的是**数据中心之外**：把 GPU 从终端设备里搬到附近的"算力路由器"。

### 定位：无线 GPU

- "**任何终端——手机、笔记本、甚至眼镜——只要支持 Wi-Fi，就能连上这个无线 GPU，并认为自己本地就有一块 GPU。**"（[00:59:27]）名字取自把 Wi-**Fi** 的 Fi 换成 **Ci** = **W**ireless **C**omputing **I**nfrastructure。
- **不需要改应用**：拦截**驱动层/API 层的函数调用**发到远端执行，应用看到的就是一块本地 RTX 5090（[00:59:27]–[01:00:29]）。实现是 **Wi-Fi 驱动 + GPU 驱动**两层。
- **与云游戏的区别是本节的关键论证**（[00:58:27]）：他在腾讯做过云游戏，复盘其增长受限的原因——**云游戏/云电脑/云手机前后端都在云上、把视频传回来，对互联网可靠性要求极高，而互联网是 best-effort 网络，无法保证**。所以换了个问法：**前端留本地，只把计算卸载出去**。并且**一旦流量跨公网性能就急剧劣化**，所以最终形态更像一台路由器——附近物理区域内、可能只有一跳（[01:00:29]–[01:01:29]）。

### ⚠️ 最硬的一条：这是在重造一种计算机体系结构

（[01:12:35]–[01:13:35]）本页 [Reiner Pope 从逻辑门讲芯片](#芯片微观层从逻辑门到-systolic-array-reiner-pope美matx2026-05) 是**芯片内部**的架构问题，这一条是**芯片之间**的：

- **正常情况下 GPU 通过 PCIe 连设备**——**数百 Gbps 带宽、微秒级延迟**。"**我们实际上是在用 Wi-Fi 替代 PCIe，带宽和延迟都差好几个数量级。**"
- 因而"**事实上定义了一种新的计算机体系结构：CPU 与 GPU 通过弱链路而非强链路通信**"。
- **这个问题历史上被解决过**——**二十多年前、PCIe 出现之前**就存在；PCIe 之后消费级主板上不再是问题，研究者逐渐离开（数据中心里仍是问题）。"**我们等于把这个问题重新提了出来**，这也提示了解法：把计算机体系结构几十年的知识拿到新场景下重新优化——**缓存、预测、调度**。"
- **从游戏切入的原因**是游戏最吃 PCIe 带宽与低延迟，是最苛刻的验证场。

### 需求侧的第二条论证：非文本本地数据

（[01:01:29]–[01:02:30]）这一条对本页"算力需求从哪来"是新的：

- **coding 之所以先成功，是因为每个文件都是纯文本，本地 grep 就够。**
- **非 coding 领域的区别就在这里**：PPT、Word、视频、图像怎么办？**难道给每个文件都做 embedding？开销会极其巨大——谁本地没有 100 GB 文件？**
- 结论：**未来会有大量必须在本地跑的工作负载，就像机器人一样。**

### 物理约束与既有路线的张力

- **RTX 5090 近 600 瓦、3 公斤**，笔记本装不下、手机更不可能；而不移动的设备功耗可以一路上涨（**3090→5090 从 300 瓦到 600 瓦**），"**算力增长的空间远大于移动端或端侧芯片**"（[01:03:30]）。

## 推理服务商这一层：优化的"报价单"、量化的反直觉与 Rubin 世代（Baseten，2026-08）

来源：[Latent Space 访谈](../videos/20260803-latent-space-baseten-inference-engineering.md)（[Philip Kiely & Ali Taha](../people/baseten-team.md)）

本页此前的 infra 视角覆盖芯片（[Reiner Pope](#芯片微观层从逻辑门到-systolic-array-reiner-pope美matx2026-05)）、系统（[Jensen](#jensen-huangnvidia2026-03)）、推理引擎（[游凯超](#推理引擎层模型与-infra-的-co-design游凯超中vllm2026-07)、[朱邦华](#推理引擎与-rl-训练-infra朱邦华中sglang-母公司2026-05)）、KV Cache 数据层（[江鋆晨](#kv-cache-作为独立数据层江鋆晨中tensormeshlmcache2026-06)）与 agent 云（[Modal](#agent-云--sandbox--弹性推理akshat-bubna美modal2026-07)）。**独缺把这些拼起来卖 token 的那一层**——本节是本库第一份来自推理服务商的一手材料，因此第一次拿到**每项优化的增益倍数与工时**这种粒度。

### 加速倍数的"报价单"（本页最可操作的一段）

[00:36:19]–[00:40:24]。基线：**万亿参数模型、合理流量、开箱即用推理引擎不做优化 = 30–50 TPS**；全套优化 = **300–400 TPS**。

| 优化项 | 增益 | 上手成本 |
|---|---|---|
| BF16 → FP8 | 约 30–40% | 懂行的人**数小时到数天**；今天多半可直接取用他人发布的 NVFP4 权重 |
| FP8 → NVFP4 | 再约 30–40%（合计不到 2 倍） | 同上 |
| 投机解码 | 约 **2 倍** | 数小时到数天；今天多半可直接取用他人训好的 speculator |
| **PD 分离** | 约 **2 倍** | ⚠️ 首次跑通很难，边际部署不难；且**需足够硬件与足够流量才吃得到** |
| 更好的运行时 / 最新 kernel | 两位数百分比 | — |

- **"投机解码 + 量化大概就是 95%。"**
- ⚠️ **重要的降温**：**"10 倍很激进，通常更像 4–6 倍"**；**归一化到同样硬件、同样 GPU 数则只有 2–4 倍**，其余来自换更好的硬件——"**一部分是车，一部分是司机**"。这为本页 [Cerebras 的 15–20 倍](#晶圆级芯片与快推理andrew-feldman美cerebras2026-05)、[Modal 的投机解码 2–4 倍](#agent-云--sandbox--弹性推理akshat-bubna美modal2026-07) 等零散数字提供了一个**同口径的分解基线**。
- **术语纠正**（[00:35:18]）：TPS 同时指**吞吐**与**延迟**，"是我们这行取错的名字"——后者应叫 **ITL（inter-token latency）**，而大多数人关心的正是后者。
- **行业成熟度的一把标尺**（[00:34:17]）：金融业优化到极致后按**基点**算改进，推理现在还在按 20%、100%、200% 算——"**等到研究者开始发论文说自己快了 1%，推理才算基本解决了**"。

### ⚠️ 量化：误差可以互相抵消，所以"量化更多反而更准"

[00:26:14]–[00:33:17]。这是本页关于**有损优化**最反直觉的一条。

- **前置框架**：**绝大多数推理优化是无损的**（KV 缓存只避免重算、投机解码猜错就拒收），**唯一的有损项是量化**；质量取决于**数据格式 / 量化哪些层 / 校准力度**。图像模型里**不量化 modulation 层与 out projection**（"out projection 是用户看到的，modulation 是模型理解的"）。
- **核心发现**：量化层 1、5、10 **可能优于**只量化层 1、2，因为**各层的量化误差会互相抵消**（"一层偏右、一层偏左"），最终 logit 分布反而更贴近原模型；且**可以预测哪些层会抵消**。结果是比 NVIDIA 方案**多量化约 20%**（多约 20% 吞吐）**同时保真度更好**。
- ⚠️ **方法论比结论更值得记**：验证不用 benchmark 分数（"高两个基点通常只是噪声"），而是**比较量化模型与全精度模型 logit 分布的 KL 散度**。这为 [评估与 Benchmark](evaluation-and-benchmarks.md) 补了一条**推理侧的替代度量**。
- **"质量"的定义**：不是模型多聪明，而是**在多大程度上忠实服务了原模型**——"你不应该分辨得出我们的 API 和官方 API"。**Kimi 的 vendor verifier** 是这条的市场机制：用户在某家云上体验差，"**他不会说这家把模型量化坏了，他会说 Kimi 烂**"。

### ⚠️ 生产实况：模式坍塌是软件问题，不是权重问题

[00:22:12]–[00:26:14]。本页此前的讨论多在设计与经济层，这段是少见的**运维层归因**：

- 兜底做法：**同一 token 连出 4 次以上直接掐掉生成并重试**（对画表格的连续横线等特殊字符做排除）。⚠️ 最常坍塌的 token 是 **"S"**，问为什么——"没什么特别的，就是那一个 token"。
- **同一份权重换推理引擎（SGLang → vLLM）问题就不出现**，所以不是权重问题、也不是 PTQ 做错了。
- ⚠️ **更深一层是 kernel 竞态**："**同一个模型放 A 集群永远不出问题，放 B 集群就出**"——因为 B 集群**节点间 KV cache 传输走更慢的互联，把竞态暴露了**。处理办法就是**换集群托管**。
- 关联点名：**CUDA 没有 Rust borrow checker 那样的东西**，kernel 正确性测试极难；PDL 这类"上个 kernel 没结束就启动下一个"的重叠优化会放大问题。

这条与本页 [游凯超"硬件彩票"](#推理引擎层模型与-infra-的-co-design游凯超中vllm2026-07) 构成一个完整的悲观图景：**模型结构定推理效率的上界，而上界之内的最优点也推理不出来**——TP/EP 组合与 kernel 参数只能用**影子流量扫参数空间按实测选**（[00:55:34]–[00:56:35]，Ali 明确表示不喜欢这一点："你没法推理出哪个配置最好，也不存在一个永远最好的配置"）。

### Rubin 世代：推理工程正在变成基础设施工程

[01:00:38]–[01:07:41]。本页此前对 Rubin 的记载几乎为零，这是第一份来自使用侧的读法。

- **Philip 的版本**：他经历过 Ampere / Hopper / Blackwell 三个周期，并指出"硬件上架"与"硬件真能用于推理"之间有很长时间差（最初的 vLLM 是奔 Ampere 写的，每代都要改，"**每次更快更急，也实质上更复杂**"）。他从 **Dynamo 的设计**反推 Rubin：NVFP4 张量核算力巨大、带宽更快，**但最大的变化是系统**——CPU↔GPU、GPU↔GPU 互联；而 Dynamo 整个就是围绕"**怎么把 KV cache 在需要时送到需要的地方**"设计的。
  > 结论：**KV cache offload、KV-aware 路由、PD 分离在 Rubin 时代会显著更重要**，推理工程因此不只是 CUDA kernel 问题，也是**非常传统的硬件基础设施问题**。
- **Ali 推得更远**：**"我认为它正在趋向于变成一个纯粹的基础设施问题"**——GPU 越来越像 ASIC，"你只是在编排 GPU 上发生什么，而不再逐线程控制它"。
- ⚠️ **本页 [推理专用芯片与代工格局](#推理专用芯片与代工格局2026-07-补充) 一节的第一次正面压力测试**：[swyx 此前的立场](../people/latent-space-hosts.md)是"推理这件事大到理所当然会有专用 ASIC，且押注架构不变是好赌注"。本期同一人现场被 Ali 从**供给侧**反驳：

  | 立场 | 论证 |
  |---|---|
  | **Ali（怀疑独立 ASIC 公司）** | Rubin 相比 Ampere/T4"**基本上就是个 ASIC**"（systolic array、tensor core、TMA、tensor memory，指令形状几乎按当今模型 head 维度定制）——**专用性正在被 GPU 自己吸收**；把东西刻进芯片，**下一代架构一出就废**；若前沿实验室每年换架构，**等于每年花 500 亿造新 ASIC 再扔掉去年的** |
  | **Ali（同时反对"权重烧进芯片"）** | 要微调、要量化、要发新 checkpoint——**烧进去的芯片一两个月就没用了** |
  | **Philip（回应一）** | **硬件周期极长**，今天的芯片几年前就开始设计，而 NVIDIA 很擅长预判——"**Rubin 老实说是第一颗完全在 MoE 世界里设计出来的芯片**" |
  | **Philip（回应二）** | **模型寿命比想象的长**："还有人在用 4o、我还看到 Llama 3 的工作负载"，**企业要的是可靠性与可预测性**——这恰是 swyx"**存量 workload 不会迁移**"的正面证据 |
  | **swyx（收缩后的立场）** | 区分**垂直整合的模型实验室自研 ASIC**（如 OpenAI–Broadcom，援引 [Martin Casado](../people/a16z.md)："5000 亿的训练拿 500 亿做 ASIC 很合理"）与**独立 ASIC 公司**——后者的价值在**互联与布局分配**而非算子，"**10 倍到 1000 倍更快的推理，真正的阻碍不是能在现有 GPU 设计里重排的东西**"；目标量级是**每秒 30 万 token** |

  **本库标注：这是同一立场被拆细，不是翻转；四条并列不裁决。**
- ⚠️ **Ali 公开唱空 mega kernel**（本库首个明确的反 mega kernel 一手表态，[00:57:35]–[00:59:36]）：① **写一个真正优化好的 mega kernel 极其困难**；② **融合救不了张量并行的通信**——TP 下半个矩阵在一卡、下一步 softmax 这类**非线性**算子需要整行，必须通信；③ ⚠️ **据他接触的从业者，做融合 mega kernel 的公司自己在生产里往往并不跑它们**，因为 TensorRT-LLM / modular 那类逐个优化、彼此并行的 kernel 更快；④ ⚠️ 他称 **Rubin 的设计让 mega kernel 大体不再必要**、"这整个研究方向不会再继续下去了"——**该条基于一条推文的二手转述，规格与推论均未核实**。

### ⚠️ "下一个 10 倍是更快的网络"：对 KV Cache 层的第三次独立佐证

[01:38:03]–[01:41:04]。Ali 自称"很无聊的答案"，但这是本节对本页 [江鋆晨的 KV Cache 押注](#kv-cache-作为独立数据层江鋆晨中tensormeshlmcache2026-06) 最直接的支持：

> 分离式服务里 KV cache 跨节点要走**两段传输**：找到 → 传到对端 → 落对端内存 → 再进 GPU。之所以绕这一圈，是因为 **HBM 快到约 4.5 TB/s，比网络通信快若干个数量级**。
> **"如果网络能极快、跳过 HBM 直接节点到节点传 KV cache，分离式服务能有接近 100 倍的加速。"**（他明确加了免责：不了解把网络做快的技术难点）

本期在**三个独立位置**指向同一层，构成本页对"KV Cache 是下一个数据层"最集中的一次外部佐证：① Philip 把 Rubin 的核心读成"Dynamo 整个围绕 KV cache 搬运设计"；② Ali 把"下一个 10 倍"押在 KV cache 跨节点传输；③ ⚠️ Ali 认为**持续学习的解法是 KV 压缩而非改权重**——理由是**权重编辑改不动二阶推理**（可以把"最好的大学是滑铁卢"编辑进 MLP，但问"该从滑铁卢还是 MIT 招实习生"它仍会说"都不错"）。他自陈在一次推特争论中被说服转向这一派。**⚠️ 推论对本页意义重大：若持续学习走 KV 路线，则推理侧几乎不用变**（权重不变 → 推理时间、投机解码都不变），只是多一步 KV 更新。

### 硬件算术与并行策略（补本页此前缺的实操层）

- **容量**（[00:54:34]、[01:11:43]）：**H100 每卡 80 GB、B200 每卡 180 GB、GB300 每卡 288 GB**；**2.8 万亿参数模型在 NVFP4 下约 1.4 TB，八卡 GB300 可容纳**。⚠️ 但真正的约束是**还要给 KV cache 留空间**——参数量大 + 上下文长时两者抢地盘，"**这正是 KV cache offload 在巨型模型上变得更突出的原因**"。另一条常被忽略的事实：**世界上 HGX 机架远多于 NVL72**，不能假设推理跑在 NVL72 上（[01:12:43]）。
- **EP / TP / PP 的分工**（[00:52:32]–[00:54:34]）：**专家并行**把整个 expert 放进一卡、router 每卡复制一份，expert 间不争资源、**对卡间互联要求不高**；**张量并行**横切模型、每步 all-gather/all-reduce，**互联极关键、有利于延迟**；实践中两者**混用**。**流水线并行只在被迫多节点时用**（节点内仍 EP+TP）。
- ⚠️ **优化不可跨场景移植**（[00:47:29]–[00:51:32]）：本页 [阳萌的存算一体](#端侧ai芯片从冯诺依曼到存算一体阳萌中安克2026-06)、[孟子立的无线 GPU](#-数据中心之外这一层用-wi-fi-替代-pcie孟子立--wici中2026-07) 讲的是端侧硬件形态，Philip 补的是**目标函数**："**本地 AI = 怎么把模型塞进硬件然后让它别那么笨；数据中心 = 怎么装载起来然后让它别那么慢。**"具体反例：某种在 MacBook 上大火的量化 kernel（因本地内存带宽慢而极有用）**放到 B200 上就不划算**——**B200 带宽约 3.5 TB/s**，kernel 内反量化的开销比省下的带宽时间还大，**NVIDIA 明确表示这不是好优化，他们也实测证实**。同理**张量并行假设有 NVLink 级互联**，因此不适合本地；反过来"**除非做多节点推理，否则我们永远不用 PP**"。
- **另一条模态外的形状差异**（[01:13:45]）：**视频扩散不做批处理**——每请求占一卡、模型小几个数量级（开源视频模型约 200 亿参数）；瓶颈是 token 数与平方级注意力（**5 秒 480p 压到 latent 仍约 3.5 万 token**）。详见[视频页](../videos/20260803-latent-space-baseten-inference-engineering.md#十视频扩散与-llm-几乎没有共享直觉ali)。

### 支持一个新模型到底是多少工作（对 co-design 一节的施工侧补充）

[00:13:09]–[00:21:11]。本页 [游凯超那节](#推理引擎层模型与-infra-的-co-design游凯超中vllm2026-07) 从引擎维护者侧讲了"新架构逼出 infra 优化"，这里是服务商侧的账：

- **"能吐出一个 token"≠"有生产可用的 API"**。前者不难——vLLM/SGLang 常**提前拿到权重**或由模型方自己提 PR 保 day-0；难的是每家都有**专有栈**。
- 即使是纯续训的新版本，仍要：**重做量化并校准**（模型基本不以 NVFP4 发布，而他们要 NVFP4 吃满 Blackwell）+ **重训 speculator**。⚠️ 一条硬约束：**训 speculator 必须用基座模型本身**（训练数据是模型跑推理产生的 hidden states），**拿不到真权重就训不了**。
- ⚠️ **数据来源的自我限制**：模型 API 做 **ZDR（零数据保留）**，"**不知道用户发了什么，但知道什么流行**"，于是用**公开数据集**里代表编码/agent 流量的数据训通用 speculator。
- **speculator 规模**：GLM 那档约 10 亿参数，MiniMax 那档**就一层**——"通常是原模型的约 1/60"（[00:45:28]–[00:46:28]）。实践约束是**它必须与大模型跑在同一硬件上**，因此存在编排与资源竞争——"**draft token 要花算力去造，也要花软件复杂度去管**"，这也是"投机的投机解码"不划算的原因。
- **开源实验室互相借零件是可操作的**（[00:16:11]–[00:21:11]）：把 **Kimi 的视觉编码器嫁接到 GLM 5.2**（只训投影层，编码器与主干全冻结，约几百万参数）；把 **MiniMax M3 的全注意力头换成另一模型的 GQA 层**再训回同样的接收率。Philip 的总结值得直接记：**"你突然就有了 Kimi 的视觉、GLM 的权重、DeepSeek 的注意力，全在一个模型里。"** 详见 [开源基础设施与治理](open-source-infrastructure.md)。
- **Dynamo 的定位**（[00:42:26]）：**工具箱而非开箱即用系统**——"pip install Dynamo 不会让你直接快一大截"，它擅长的是在集群里协调 NIXL 搬运 KV cache。

### 训练与推理的合流

[01:28:55]–[01:31:58]。本页 [Poolside 的"RL 是墙钟瓶颈"](#rl-的墙钟瓶颈把-pd-解耦引入训练低精度算力政治eiso-kant--poolside2026-07) 从模型实验室侧讲了这件事，本节是推理服务商侧的同一判断：

- **为训练而推理**：RL rollout 慢就卡住整条流水线，"**你不想在太 off-policy 的 rollout 上训练，所以只能等**"。⚠️ 一个具体卡点：**要训的模型若在 TensorRT-LLM 里没被支持、只能退回更老的引擎，rollout 就会慢**。
- **为推理而训练**：训 speculator / EAGLE 头；以及**量化后的补救**——"有时 PTQ 就够了，有时量到 NVFP4 质量太差，必须后训练让模型理解自己现在是 NVFP4 还要输出同样的 logit"，手段含 SFT、**量化感知训练**与 **NVIDIA 的量化蒸馏**（同时保留 NVFP4 版与全精度版，按两者 logit 蒸馏）。
- **组织后果**："**我们团队的推理工程师必须非常熟悉训练技术、能自己写训练管线。**"
- ⚠️ 最具体的一环见 [AI for AI](ai-for-ai-and-auto-research.md)：**GLM 5.2 在为自己写 SGLang 的 GPU kernel**。

## ⚠️ "算力市场被 LLM 化了"：本页第一条来自非 LLM 工作负载的抱怨（Chai Discovery，2026-08）

来源：[Chai Discovery 那期](../videos/20260811-latent-space-chai-discovery-protein-design.md)（[01:01:33]–[01:04:35]、[01:11:37]–[01:12:38]）。

⚠️ **为什么这条对本页是新的**：本页此前所有材料——[Baseten](#推理服务商这一层优化的报价单量化的反直觉与-rubin-世代baseten2026-08)、[游凯超](#推理引擎层模型与-infra-的-co-design游凯超中vllm2026-07)、[Simon Mo](../videos/20260806-a16z-simon-mo-open-source-inference.md)、[孟子立](#️-数据中心之外这一层用-wi-fi-替代-pciec孟子立--wici中2026-07)——**都是在 LLM 的形状内部讨论优化**。Chai 说的是**硬件形状本身就不是为这类模型造的**。

### 供给侧：幂律

Neil（他的岗位之一就是给公司买算力，"**最糟的活，我不推荐，压力非常大**"）：

- **2025 年 9 月开始感到紧**：他们大量推理跑在 **spot 和按需市场**上，开始出现容量挤兑，于是决定自己买。
- ⚠️ **"我没意识到这是多大的一个幂律——比方说全球在出货 10000 台 B300，超大规模云和最大的那几家 AI 实验室买走 95% 以上，然后创业公司在抢剩下的渣。"**

### ⚠️ 更值得记的第二层：硬件的形状

> "这些后期的算力版本——**Vera Rubin、B300**——**很多东西是照着 LLM 造的**：巨大的 KV cache、72 张 GPU 全都要互相通信。有些性能收益当然也帮到我们，**但算力市场被 LLM 化（LLM pilled）的程度挺有意思的**……**我认为这一类模型会和 LLM 一样大、一样有影响力，但算力那边好像还没意识到**——既是容量意义上的，也是软件栈意义上的。"

**Matt 给的架构侧机制**（本页此前没有这类非 Transformer 的算力画像）：

| 项 | LLM | AlphaFold 式结构模型 |
|---|---|---|
| 注意力作用对象 | 长度 **L** 的序列表示 | ⚠️ **成对表示（pair representation）**，相当于长度 **L²**；按实际 batch 方式最后是 **L³** |
| 每 token 的 flops | — | **非常高** |
| 真瓶颈 | KV cache / 带宽 | ⚠️ **内存带宽**——"**哪怕简单如一个 layer norm 都可能占掉相当一部分算力**" |

### 一条被主动展开的工程原语：durable execution
